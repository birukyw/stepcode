# Your First Class: Objects & Methods

Dictionaries are a good way to hold related data: `{"name": "Ada", "balance": 100}`. But the data alone does nothing. Every function that works on it has to be told where it lives, and nothing stops you putting the wrong thing inside. A **class** bundles the data **and** the functions that work on it into one tidy thing called an **object**. You have been using objects all along: every string, list and dictionary is an object, and `.upper()`, `.append()` and `.items()` are their **methods**. Now you will make your own.

## The dictionary way, and its limits

```python
account = {"owner": "Ada", "balance": 100}

def deposit(acct, amount):
    acct["balance"] += amount

deposit(account, 50)
print(account)

account["balence"] = 999     # a typo silently creates a new key
print(account)
```

```text
{'owner': 'Ada', 'balance': 150}
{'owner': 'Ada', 'balance': 150, 'balence': 999}
```

The typo `balence` made a *new* key instead of failing. The functions live separately from the data, and anyone can put anything anywhere.

## A class: a blueprint

A **class** describes what a kind of thing has (its **attributes**) and can do (its **methods**). An **object** (or **instance**) is one particular thing built from the blueprint.

```python
class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.balance = balance

    def deposit(self, amount):
        self.balance += amount

    def describe(self):
        return self.owner + " has $" + str(self.balance)

acct = BankAccount("Ada", 100)
acct.deposit(50)
print(acct.describe())
print(acct.balance)

other = BankAccount("Linus")
print(other.describe())
```

```text
Ada has $150
150
Linus has $0
```

Take the pieces one at a time:

- **`class BankAccount:`** defines the blueprint. Class names use `CapitalizedWords`.
- **`__init__`** is the **constructor**. Python runs it automatically when you write `BankAccount("Ada", 100)`. It sets up the new object's data.
- **`self`** is the object itself. It is always the first parameter of a method, and **Python passes it for you**: `acct.deposit(50)` calls `deposit(acct, 50)` behind the scenes.
- **`self.balance = balance`** stores data **on** the object. Each object has its own copy: `acct` and `other` are separate.
- **Methods** are functions defined inside the class. They use `self` to read and change the object's data.

## Objects have identity and state

Each instance carries its own **state**. Changing one does not touch the others:

```python
class Counter:
    def __init__(self):
        self.value = 0

    def click(self):
        self.value += 1

a = Counter()
b = Counter()
a.click(); a.click(); b.click()
print(a.value, b.value)
print(a is b, a == b)
```

```text
2 1
False False
```

`a is b` is `False` because they are two different objects, even though they look alike. This is the same "labels and boxes" idea from lesson 1.1.2: `a` and `b` are names attached to two different objects.

## Methods that protect the data

The real power: methods can **guard** the object so it stays valid. Use what you learned about raising errors:

```python
class BankAccount:
    def __init__(self, owner, balance=0):
        if balance < 0:
            raise ValueError("opening balance cannot be negative")
        self.owner = owner
        self.balance = balance

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("deposit must be positive")
        self.balance += amount

    def withdraw(self, amount):
        if amount > self.balance:
            raise ValueError("insufficient funds")
        self.balance -= amount

acct = BankAccount("Ada", 100)
acct.withdraw(30)
print(acct.balance)

try:
    acct.withdraw(500)
except ValueError as err:
    print("Declined:", err)
print(acct.balance)
```

```text
70
Declined: insufficient funds
70
```

A failed withdrawal leaves the object unchanged. Nobody has to remember the rule, because the **class enforces it**.

## Making objects print nicely: `__str__`

Printing a plain object shows something unhelpful like `<__main__.BankAccount object at 0x...>`. Define `__str__` to control it. Methods with double underscores on both sides are called **special methods**, and Python calls them for you at the right moments:

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __str__(self):
        return "(" + str(self.x) + ", " + str(self.y) + ")"

    def __eq__(self, other):
        return self.x == other.x and self.y == other.y

    def __add__(self, other):
        return Point(self.x + other.x, self.y + other.y)

p = Point(1, 2)
q = Point(3, 4)
print(p)
print(p + q)
print(p == Point(1, 2))
print(f"The point is {q}")
```

```text
(1, 2)
(4, 6)
True
The point is (3, 4)
```

`__str__` powers `print` and f-strings, `__eq__` powers `==`, and `__add__` powers `+`. This is how `+` can mean different things for numbers, strings and lists: each class decides.

## Class attributes and a counter

Data shared by **all** instances lives on the class, outside `__init__`:

```python
class Dog:
    species = "Canis familiaris"       # shared by every Dog
    count = 0

    def __init__(self, name):
        self.name = name
        Dog.count += 1

    def speak(self):
        return self.name + " says woof"

rex = Dog("Rex")
fido = Dog("Fido")
print(rex.speak(), "|", fido.species, "|", Dog.count)
```

```text
Rex says woof | Canis familiaris | 2
```

## Objects holding objects

Objects can hold other objects. This is how real programs are modelled: a library has books, a classroom has students.

```python
class Book:
    def __init__(self, title, pages):
        self.title = title
        self.pages = pages

class Library:
    def __init__(self):
        self.books = []

    def add(self, book):
        self.books.append(book)

    def total_pages(self):
        return sum(book.pages for book in self.books)

    def find(self, word):
        return [b.title for b in self.books if word.lower() in b.title.lower()]

lib = Library()
lib.add(Book("Learning Python", 1600))
lib.add(Book("Python Tricks", 300))
lib.add(Book("Cooking Basics", 220))
print(lib.total_pages())
print(lib.find("python"))
```

```text
2120
['Learning Python', 'Python Tricks']
```

## Inheritance: a class built on another

A class can **extend** another, gaining its attributes and methods and adding or changing some. This is **inheritance**:

```python
class Animal:
    def __init__(self, name):
        self.name = name

    def speak(self):
        return "..."

    def intro(self):
        return self.name + " says " + self.speak()

class Dog(Animal):
    def speak(self):
        return "Woof"

class Cat(Animal):
    def speak(self):
        return "Meow"

for pet in [Dog("Rex"), Cat("Tom"), Animal("Thing")]:
    print(pet.intro())
```

```text
Rex says Woof
Tom says Meow
Thing says ...
```

`Dog` and `Cat` reuse `__init__` and `intro` from `Animal` and **override** `speak`. Calling `pet.intro()` does the right thing for each kind. Use inheritance sparingly: it is easy to overdo, and Track 2 shows when a different design is better.

## Class or dictionary?

| Use a... | When |
|---|---|
| plain `dict` | quick, throwaway, or data that came from JSON |
| class | the data has rules, you have operations on it, or you will make many of them |
| `dataclass` (below) | a class that mostly just holds fields |

```python
from dataclasses import dataclass

@dataclass
class Item:
    name: str
    price: float
    quantity: int = 1

    def total(self):
        return self.price * self.quantity

item = Item("pen", 1.5, 4)
print(item)
print(item.total(), item == Item("pen", 1.5, 4))
```

```text
Item(name='pen', price=1.5, quantity=4)
6.0 True
```

`@dataclass` writes `__init__`, `__repr__` and `__eq__` for you from the field list. It is the neat tool for plain data holders.

## Common mistakes

- **Forgetting `self`** as the first parameter, or forgetting `self.` before attribute names (`balance = 5` makes a local variable, not an attribute).
- **Calling the method without parentheses.** `acct.describe` is the method itself. `acct.describe()` runs it.
- **Mutable class attributes shared by accident.** A list defined on the class is shared by every instance (compare lesson 1.5.4). Create it inside `__init__`.
- **Overusing classes.** If it is just data and one function, a dictionary and a function may be simpler.
- **Using inheritance to share code** when two things are not truly "kinds of" the same thing.

```python
class Rectangle:
    def __init__(self, width, height):
        self.width = width
        self.height = height

    def area(self):
        return self.width * self.height

    def perimeter(self):
        return 2 * (self.width + self.height)

    def __str__(self):
        return str(self.width) + " x " + str(self.height) + " rectangle"

class Square(Rectangle):
    def __init__(self, side):
        super().__init__(side, side)

print(Rectangle(3, 4), Rectangle(3, 4).area(), Square(5).perimeter())   # 3 x 4 rectangle 12 20
```

```python
class TodoList:
    def __init__(self):
        self.tasks = {}

    def add(self, task):
        self.tasks[task] = False

    def done(self, task):
        if task not in self.tasks:
            raise KeyError(task)
        self.tasks[task] = True

    def pending(self):
        return [t for t, finished in self.tasks.items() if not finished]

todo = TodoList()
todo.add("write"); todo.add("test"); todo.done("write")
print(todo.pending())   # ['test']
```

## Recap

- A **class** is a blueprint that bundles data (attributes) and behaviour (methods). An **object** is one instance built from it.
- `__init__` sets up a new object. `self` is the object itself and is the first parameter of every method.
- Each object has its **own state**, and methods can **protect** it by raising errors on invalid changes.
- Special methods such as `__str__`, `__eq__` and `__add__` let your objects work with `print`, `==` and `+`.
- **Inheritance** (`class Dog(Animal)`) reuses and overrides behaviour, and `@dataclass` removes the boilerplate for simple data holders.
- Pick a class when the data has rules and operations. Pick a dictionary when it is quick and throwaway.
