# Handling Exceptions with try/except

Last lesson you learned to read errors. This one teaches the next skill: **handling** them so that your program keeps going. A program that crashes the moment a user types "abc" where a number belongs is a fragile program. Python's tool for this is `try` / `except`: *try this risky thing, and if it fails in a way I expected, do this instead*.

## The problem

```python error
age = int("twenty")
print("Next year you will be", age + 1)
```

```text
Traceback (most recent call last):
  File "main.py", line 1, in <module>
    age = int("twenty")
ValueError: invalid literal for int() with base 10: 'twenty'
```

One bad input and the whole program dies. We need to catch the failure.

## try and except

Put the risky code in a `try` block, and the response in an `except` block:

```python
text = "twenty"

try:
    age = int(text)
    print("Next year you will be", age + 1)
except ValueError:
    print("That is not a whole number.")

print("The program keeps going.")
```

```text
That is not a whole number.
The program keeps going.
```

If everything inside `try` works, `except` is skipped. If a `ValueError` is raised, Python **jumps straight** to the `except` block, abandoning the rest of the `try`. Then the program carries on after the whole statement.

Naming the error type matters. `except ValueError` only catches *that* kind of failure. Other errors still stop the program, which is what you want: a bug you did not expect should be loud.

## A reusable safe function

```python
def to_int(text, default=0):
    try:
        return int(text)
    except ValueError:
        return default

print(to_int("42"), to_int("oops"), to_int("oops", default=-1), to_int(" 7 "))
```

```text
42 0 -1 7
```

Notice that `int(" 7 ")` works because `int` ignores surrounding spaces, and an empty string `""` would fail and use the default.

## Several kinds of failure

A block can have several `except` clauses, each for a different error. The first one that matches runs:

```python
def divide(a, b):
    try:
        return a / b
    except ZeroDivisionError:
        return "cannot divide by zero"
    except TypeError:
        return "both values must be numbers"

print(divide(10, 4))
print(divide(1, 0))
print(divide("1", 2))
```

```text
2.5
cannot divide by zero
both values must be numbers
```

You can also handle two errors the same way by listing them in a tuple: `except (ValueError, TypeError):`.

## Getting the message: `as`

Bind the error to a name to read its message:

```python
try:
    value = {"a": 1}["b"]
except KeyError as err:
    print("Missing key:", err)

try:
    int("x1")
except ValueError as err:
    print("Problem:", err)
```

```text
Missing key: 'b'
Problem: invalid literal for int() with base 10: 'x1'
```

## else and finally

Two optional extras:

- **`else`** runs only if the `try` block raised **nothing**. It keeps the "success" code out of the risky block.
- **`finally`** runs **always**, whatever happened. It is for cleanup, like closing a file.

```python
def parse(text):
    try:
        number = int(text)
    except ValueError:
        print("  failed to parse", repr(text))
        return None
    else:
        print("  parsed", number)
        return number
    finally:
        print("  done with", repr(text))

parse("12")
parse("zz")
```

```text
  parsed 12
  done with '12'
  failed to parse 'zz'
  done with 'zz'
```

Note that `finally` runs even though both branches `return`.

## Raising your own errors

You are not limited to catching errors: you can **raise** them when your function receives something it cannot work with. That is the contract idea from module 1.5, enforced.

```python
def set_age(age):
    if not isinstance(age, int):
        raise TypeError("age must be a whole number")
    if age < 0:
        raise ValueError("age cannot be negative")
    return age

for candidate in [30, -4, "ten"]:
    try:
        print("ok:", set_age(candidate))
    except (TypeError, ValueError) as err:
        print(type(err).__name__ + ":", err)
```

```text
ok: 30
ValueError: age cannot be negative
TypeError: age must be a whole number
```

Use `ValueError` for a bad value, `TypeError` for a bad type. Raising early with a clear message beats a confusing crash ten lines later.

## Your own error types

For larger programs, define a custom exception with a class. It only needs a name and a base:

```python
class InsufficientFunds(Exception):
    pass

def withdraw(balance, amount):
    if amount > balance:
        raise InsufficientFunds("need " + str(amount - balance) + " more")
    return balance - amount

try:
    withdraw(50, 80)
except InsufficientFunds as err:
    print("Declined:", err)
```

```text
Declined: need 30 more
```

A named error lets the code that calls you catch exactly this case and nothing else. You will see how `class` works properly in lesson 1.7.6.

## Looking before you leap, or asking forgiveness

Two styles handle risk. **LBYL** (look before you leap) checks first. **EAFP** (easier to ask forgiveness than permission) just tries it and handles failure. Python generally prefers EAFP, since checking can be racy or repetitive:

```python
inventory = {"apples": 3}

# LBYL
if "pears" in inventory:
    count = inventory["pears"]
else:
    count = 0

# EAFP
try:
    count2 = inventory["pears"]
except KeyError:
    count2 = 0

# for dictionaries there is also the shortcut
count3 = inventory.get("pears", 0)
print(count, count2, count3)
```

```text
0 0 0
```

Use whichever is clearest. For a dictionary, `.get` is the neatest of all.

## A validation loop

A classic use: keep asking until the input is valid.

```python
def read_age(answers):
    answers = iter(answers)               # stands in for repeated input() calls
    while True:
        text = next(answers)
        try:
            age = int(text)
            if age < 0:
                raise ValueError("negative")
            return age
        except ValueError:
            print("Invalid:", repr(text), "- try again")

print(read_age(["abc", "-3", "28"]))
```

```text
Invalid: 'abc' - try again
Invalid: '-3' - try again
28
```

## What not to do

```python
try:
    result = 10 / 0
except:
    pass
```

A bare `except:` that swallows everything with `pass` is the worst habit in this lesson. It hides real bugs, including typos, and makes the program silently wrong. Always catch **specific** errors, and do something useful with them, even if it is only printing a message.

## Common mistakes

- **Catching too much.** `except Exception` or a bare `except:` hides bugs. Name the error you expect.
- **Putting too much code in `try`.** Keep the block small, so you know which line failed.
- **Silencing errors with `pass`.** At least log what happened.
- **Using exceptions for normal flow** when a simple `if` is clearer.
- **Forgetting that `return` inside `try` still runs `finally`.**

## Practice

1. Write `safe_divide(a, b)` that returns `None` when `b` is zero.
2. Write `parse_ints(items)` that converts a list of strings to ints and **skips** those that fail.
3. Write `get_item(seq, index, default)` that returns the item or the default if the index is out of range.
4. Write `validate_password(pw)` that raises `ValueError` with a helpful message if it is shorter than 8 characters or has no digit.

+++ Solutions
```python
def safe_divide(a, b):
    try:
        return a / b
    except ZeroDivisionError:
        return None

def parse_ints(items):
    out = []
    for item in items:
        try:
            out.append(int(item))
        except ValueError:
            pass            # a deliberate skip, with a comment saying why
    return out

def get_item(seq, index, default=None):
    try:
        return seq[index]
    except IndexError:
        return default

print(safe_divide(1, 0), parse_ints(["1", "x", "3"]), get_item([1, 2], 5, "none"))   # None [1, 3] none
```

```python
def validate_password(pw):
    if len(pw) < 8:
        raise ValueError("password must be at least 8 characters")
    if not any(ch.isdigit() for ch in pw):
        raise ValueError("password must contain a digit")
    return True

for pw in ["short1", "longenough", "longenough9"]:
    try:
        print(validate_password(pw))
    except ValueError as err:
        print("rejected:", err)
```

## Recap

- `try` runs risky code and `except SomeError` runs if that error happens, so the program continues instead of crashing.
- Catch **specific** errors, read the message with `as err`, and never swallow everything with a bare `except: pass`.
- `else` runs when nothing went wrong. `finally` always runs, even after a `return`.
- `raise` creates an error when a function gets input it cannot accept, and a custom `class MyError(Exception)` gives it a precise name.
- Python prefers asking forgiveness (try, then handle) over checking first, and `dict.get` covers the common dictionary case.
