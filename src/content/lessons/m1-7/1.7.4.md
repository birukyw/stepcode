# Modules & the Standard Library

When people say "Python comes with batteries included", they mean **the standard library**: hundreds of ready-made tools for dates, maths, random numbers, JSON, text and more. You use them through **modules**, files full of useful code that you `import`. Learning to find and use a module is one of the biggest steps from "I can write programs" to "I can build things".

## importing

```python
import math

print(math.sqrt(144))
print(math.pi)
print(math.ceil(4.2), math.floor(4.8))
```

```text
12.0
3.141592653589793
5 4
```

`import math` loads the module and gives you the name `math`. You reach its contents with a dot: `math.sqrt`. Three common ways to import:

```python
import math                     # use as math.sqrt(...)
from math import sqrt, pi       # use as sqrt(...) directly
import statistics as stats      # a shorter name

print(math.floor(2.7), sqrt(25), round(pi, 3), stats.mean([1, 2, 3, 4]))
```

```text
2 5.0 3.142 2.5
```

Prefer `import module` for clarity, because `math.sqrt` tells the reader where `sqrt` came from. Avoid `from module import *`: it dumps every name into your file and hides where things come from.

## Finding out what a module has

You do not need to memorise modules. Ask Python:

```python
import math

print([name for name in dir(math) if not name.startswith("_")][:8])
print(math.hypot.__doc__.splitlines()[0])
```

```text
['acos', 'acosh', 'asin', 'asinh', 'atan', 'atan2', 'atanh', 'cbrt']
Multidimensional Euclidean distance from the origin to a point.
```

`dir(module)` lists names, `help(module.name)` prints the documentation (in a terminal), and the official docs at python.org have everything. Reading documentation is a core skill.

## random: choices and chance

```python
import random

random.seed(7)
first = [random.randint(1, 6) for _ in range(5)]
random.seed(7)
second = [random.randint(1, 6) for _ in range(5)]
print(first == second)                   # the same seed gives the same "random" numbers
print(all(1 <= n <= 6 for n in first))   # randint is inclusive on both ends
print(random.choice(["rock", "paper", "scissors"]) in ["rock", "paper", "scissors"])
items = [1, 2, 3, 4, 5]
random.shuffle(items)                    # shuffles IN PLACE
print(sorted(items))
print(len(random.sample(range(100), 5)), "unique picks")
```

```text
True
True
True
[1, 2, 3, 4, 5]
5 unique picks
```

The module name is not the data: `random.seed(7)` restarts the sequence, so the same seed gives the same "random" numbers every run. That is how tests and games make random behaviour reproducible. Notice `shuffle` changes the list itself (like `sort`), while `sample` returns a new list.

## collections: better containers

`Counter` counts things (compare with the frequency counting you wrote by hand in module 1.6), and `defaultdict` removes the "key missing" step:

```python
from collections import Counter, defaultdict

words = "the cat and the hat and the bat".split()
counts = Counter(words)
print(counts)
print(counts.most_common(2))
print(counts["dog"])

groups = defaultdict(list)
for w in words:
    groups[len(w)].append(w)
print(dict(groups))
```

```text
Counter({'the': 3, 'and': 2, 'cat': 1, 'hat': 1, 'bat': 1})
[('the', 3), ('and', 2)]
0
{3: ['the', 'cat', 'and', 'the', 'hat', 'and', 'the', 'bat']}
```

## datetime: dates and times

```python
from datetime import date, datetime, timedelta

launch = date(2030, 1, 15)
print(launch, launch.year, launch.strftime("%d %B %Y"))
print(launch + timedelta(days=30))
print((date(2030, 3, 1) - launch).days, "days between")

moment = datetime(2030, 1, 15, 9, 30)
print(moment.strftime("%H:%M on %A"))
```

```text
2030-01-15 2030 15 January 2030
2030-02-14
45 days between
09:30 on Tuesday
```

Dates are **objects with arithmetic**: subtracting two dates gives a `timedelta`. Never calculate dates by hand with `30 * 24 * 60 * 60`; leap years and months will bite you.

## json: data between programs

JSON is the universal format for sending data between programs and over the web. It looks like the dictionaries and lists you already know:

```python
import json

person = {"name": "Ada", "languages": ["Python", "C"], "age": 36, "active": True, "boss": None}
text = json.dumps(person)
print(text)

back = json.loads(text)
print(back["languages"][0], back == person)
print(json.dumps(person, indent=2, sort_keys=True).splitlines()[1])
```

```text
{"name": "Ada", "languages": ["Python", "C"], "age": 36, "active": true, "boss": null}
Python True
  "active": true,
```

`dumps` turns a Python value into JSON **text** (a string), and `loads` turns it back. `True` becomes `true`, `None` becomes `null`.

## itertools and functools: tools for loops and functions

```python
from itertools import combinations, product
from functools import lru_cache

print(list(combinations("ABC", 2)))
print(len(list(product("01", repeat=3))))

@lru_cache(maxsize=None)
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)

print(fib(60))
```

```text
[('A', 'B'), ('A', 'C'), ('B', 'C')]
8
1548008755920
```

You do not need these today. The point is that **someone already wrote** the combinations generator and the memoizing cache, and tested them far more than you could.

## Writing your own module

Any Python file is a module. If you save the functions below as `geometry.py`, another file can `import geometry`:

```python
# imagine this is geometry.py
def area_circle(r):
    return 3.14159 * r * r

def area_rect(w, h):
    return w * h

if __name__ == "__main__":
    # this block runs only when the file is run directly, not when it is imported
    print(area_circle(2), area_rect(3, 4))
```

```text
12.56636 12
```

The `if __name__ == "__main__":` guard lets a file serve two purposes: a library of functions when imported, and a program when run. You will see it in almost every real Python project.

## Third-party packages

Beyond the standard library lies **PyPI**, a public collection of over 400,000 packages: `requests` for the web, `numpy` for numbers, `pandas` for tables. You install them with `pip` (covered in lesson 1.7.7) and then `import` them exactly like standard modules. In this course's editor, popular packages such as NumPy load automatically when you import them.

## Common mistakes

- **Naming your own file like a module** (`random.py`, `math.py`). Python then imports *your* file instead of the real module, and everything breaks in strange ways.
- **`from module import *`.** Hard to read and can overwrite names.
- **Forgetting the module name** (`sqrt(4)` after `import math`).
- **Assuming `random` is truly random.** It is predictable from its seed, which is perfect for games and wrong for passwords (use the `secrets` module).
- **Rewriting what exists.** Search the standard library first.

## Recap

- A **module** is a file of reusable code. `import math` gives you `math.sqrt`, and `from math import sqrt` lets you write `sqrt` directly.
- The **standard library** is huge: use `random`, `math`, `collections` (`Counter`, `defaultdict`), `datetime`, `json`, `itertools` and `functools` before writing your own.
- `dir(module)` and the docs tell you what is inside. Reading documentation is a skill worth practising.
- `random.seed(n)` makes randomness repeatable. `json.dumps` and `json.loads` convert between Python values and JSON text.
- Any `.py` file is a module, and `if __name__ == "__main__":` separates "run me" from "import me".
- Never name your own file after a standard module.
