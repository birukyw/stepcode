# Why Lists Are Slow at Searching

Lists are great when order matters. They are bad at one very common job: finding a value. This lesson shows why, and introduces the data structure that fixes it, the **dictionary**, which can find a value among millions in what is effectively one step.

## Searching a list means checking every item

To answer `"Grace" in names`, Python starts at index 0 and compares items one by one until it finds a match or runs out. That is called a **linear search**. Here is the same thing written by hand, counting how many comparisons it makes:

```python
def linear_search(items, target):
    steps = 0
    for item in items:
        steps += 1
        if item == target:
            return steps
    return steps

names = ["Ada", "Linus", "Grace", "Guido", "Margaret"]
print(linear_search(names, "Ada"))
print(linear_search(names, "Margaret"))
print(linear_search(names, "Nobody"))
```

```text
1
5
5
```

Finding the first item is quick. Finding the last item, or proving an item is missing, means checking **everything**.

## How it scales

```python
def linear_search(items, target):
    steps = 0
    for item in items:
        steps += 1
        if item == target:
            return steps
    return steps

for size in [10, 1_000, 100_000]:
    data = list(range(size))
    print(size, "items:", linear_search(data, -1), "comparisons")
```

```text
10 items: 10 comparisons
1000 items: 1000 comparisons
100000 items: 100000 comparisons
```

The work grows in proportion to the size of the list. Computer scientists write this as **O(n)**, read "order n": double the data and you double the time. If you search a 100,000-item list inside a loop that also runs 100,000 times, you have 10 billion comparisons, and your program appears to freeze.

## Dictionaries: look up by key

A **dictionary** (`dict`) stores **key-value pairs**. You look values up by their key, the way you look up a word in a real dictionary instead of reading every page.

```python
ages = {"Ada": 36, "Linus": 28, "Grace": 85}

print(ages["Grace"])
print(len(ages))
print("Linus" in ages)
print("Guido" in ages)
```

```text
85
3
True
False
```

Write a dictionary with curly braces, with `key: value` pairs separated by commas. Square brackets with a key fetch the value. `in` checks the **keys**.

## Adding, changing and removing

Dictionaries are mutable. Assigning to a key adds it if it is new, or replaces its value if it exists.

```python
stock = {"apples": 12, "pears": 4}

stock["plums"] = 9
stock["apples"] = 15
del stock["pears"]

print(stock)
```

```text
{'apples': 15, 'plums': 9}
```

Keys are unique. A dictionary cannot hold the same key twice, so assigning to an existing key always overwrites. Dictionaries also remember the order in which keys were first added, which is why the printout lists `apples` before `plums`.

## Why dictionary lookups are fast

A dictionary does not search. When you store a key, Python runs it through a **hash function**, which turns the key into a number. That number decides which slot of an internal table the value goes into. To look the key up later, Python hashes it again and jumps straight to that slot.

```python
print(hash(42))
print(hash(42) == hash(42))
```

```text
42
True
```

The same key always produces the same hash during a run, so the lookup lands in the same place every time. The cost does not depend on how many items are stored. That is written **O(1)**, "constant time". A dictionary with ten million entries finds a key about as quickly as one with ten.

> **Why it matters:** Choosing the right data structure often matters more than clever code. Replacing a list search inside a loop with a dictionary lookup can turn a program that takes an hour into one that takes a second.

## Keys must be hashable

Because the position depends on the key's hash, a key must never change once stored. So keys must be **immutable**: numbers, strings, booleans and tuples work. Lists do not.

```python error
locations = {["x", "y"]: "corner"}
```

```text
Traceback (most recent call last):
  File "main.py", line 1, in <module>
    locations = {["x", "y"]: "corner"}
TypeError: unhashable type: 'list'
```

A tuple works, because it cannot change:

```python
locations = {(0, 0): "origin", (3, 4): "corner"}
print(locations[(3, 4)])
```

```text
corner
```

Values have no such restriction. A value can be anything, including a list or another dictionary.

## Lists or dictionaries?

| Use a list when | Use a dictionary when |
|---|---|
| order matters | you look things up by a name or ID |
| you process every item | you need fast membership tests |
| items are just values | each value belongs to a key |

A phone book is a dictionary from name to number. A queue of customers is a list.

## Common mistakes

- **Searching a list repeatedly inside a loop.** Build a dictionary or set once, then look up.
- **Using a list as a key.** Use a tuple.
- **Expecting `in` to check values.** For a dictionary, `in` checks keys.
- **Assuming a missing key returns `None`.** It raises `KeyError`. The next lesson covers safe lookups.

## Recap

- Searching a list checks items one by one: O(n), slower as data grows.
- A dictionary maps keys to values: `{"key": value}`. Look up with `d[key]`.
- Hashing lets a dictionary jump straight to a key: O(1) on average.
- Keys must be immutable (hashable). Values can be anything.
- Use dictionaries for lookups by name or ID, and lists for ordered sequences.
