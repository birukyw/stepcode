# Nested Data Modeling

Real data rarely fits in a single list or a single dictionary. A user has a name, a list of orders, and an address, and each order has items. Python models this by nesting collections inside each other: lists of dictionaries, dictionaries of lists, and deeper still. This is the same shape as JSON, the format most web APIs use, so learning to navigate it pays off immediately.

## Records as dictionaries

A dictionary with fixed keys makes a good **record**: one thing, described by named fields.

```python
book = {"title": "Dune", "author": "Frank Herbert", "year": 1965, "tags": ["sci-fi", "classic"]}

print(book["title"])
print(book["tags"][0])
print(len(book["tags"]))
```

```text
Dune
sci-fi
2
```

`book["tags"][0]` reads left to right: get the `"tags"` value, which is a list, then take its first item.

## A list of records

Many records of the same shape form a list of dictionaries, the most common structure in real programs.

```python
library = [
    {"title": "Dune", "year": 1965, "rating": 4.3},
    {"title": "Neuromancer", "year": 1984, "rating": 3.9},
    {"title": "Hyperion", "year": 1989, "rating": 4.2},
]

for book in library:
    print(f"{book['title']:<12} {book['year']}  {book['rating']}")
```

```text
Dune         1965  4.3
Neuromancer  1984  3.9
Hyperion     1989  4.2
```

Each loop variable is one whole dictionary, so you reach its fields by key.

## Querying a list of records

Filtering, aggregating and sorting all follow patterns you already know.

```python
library = [
    {"title": "Dune", "year": 1965, "rating": 4.3},
    {"title": "Neuromancer", "year": 1984, "rating": 3.9},
    {"title": "Hyperion", "year": 1989, "rating": 4.2},
]

recent = []
for book in library:
    if book["year"] >= 1980:
        recent.append(book["title"])
print(recent)

total = 0
for book in library:
    total += book["rating"]
print(round(total / len(library), 2))

best = max(library, key=lambda b: b["rating"])
print(best["title"])

by_year = sorted(library, key=lambda b: b["year"], reverse=True)
print([b["title"] for b in by_year])
```

```text
['Neuromancer', 'Hyperion']
4.13
Dune
['Hyperion', 'Neuromancer', 'Dune']
```

`key=lambda b: b["rating"]` says "compare books by their rating". The final line uses a list comprehension, covered fully in Track 3, to pull out just the titles.

## A dictionary of records

When you look records up by an ID, key them by that ID instead of keeping a list.

```python
users = {
    "u1": {"name": "Ada", "email": "ada@example.com"},
    "u2": {"name": "Linus", "email": "linus@example.com"},
}

print(users["u2"]["name"])
users["u3"] = {"name": "Grace", "email": "grace@example.com"}
print(len(users))
```

```text
Linus
3
```

This gives you O(1) lookups by ID, which a list of records cannot.

## Deeper nesting

Data from an API often goes several levels deep:

```python
order = {
    "id": 1042,
    "customer": {"name": "Ada", "address": {"city": "London", "postcode": "N1"}},
    "items": [
        {"sku": "BK-1", "qty": 2, "price": 12.5},
        {"sku": "PN-7", "qty": 10, "price": 1.2},
    ],
}

print(order["customer"]["address"]["city"])

total = 0
for item in order["items"]:
    total += item["qty"] * item["price"]
print(total)
```

```text
London
37.0
```

Work out the path one level at a time: `order` is a dictionary, `"customer"` holds a dictionary, `"address"` holds another, and `"city"` holds the string.

## Navigating safely

When some records lack some fields, a chain of `[...]` lookups crashes on the first missing key. Chain `get` with empty-dictionary defaults instead:

```python
orders = [
    {"id": 1, "customer": {"address": {"city": "London"}}},
    {"id": 2, "customer": {}},
    {"id": 3},
]

for o in orders:
    city = o.get("customer", {}).get("address", {}).get("city", "unknown")
    print(o["id"], city)
```

```text
1 London
2 unknown
3 unknown
```

Each `.get(..., {})` returns an empty dictionary when a level is missing, so the next `.get` still works, and the final default fills in the answer.

## Printing nested data readably

The `json` module can print nested structures with indentation, which makes them much easier to inspect.

```python
import json

config = {"name": "app", "ports": [80, 443], "db": {"host": "localhost", "pool": 5}}
print(json.dumps(config, indent=2))
```

```text
{
  "name": "app",
  "ports": [
    80,
    443
  ],
  "db": {
    "host": "localhost",
    "pool": 5
  }
}
```

`json.dumps` turns the data into JSON text. That is also exactly how you would save it to a file or send it to a web service.

## Aliasing returns

Nested data is mutable at every level, so the aliasing rules from lesson 1.4.4 still apply. Copying the outer structure does not copy what is inside.

```python
import copy

template = {"name": "", "tags": []}
a = copy.deepcopy(template)
b = copy.deepcopy(template)

a["tags"].append("vip")
print(a["tags"], b["tags"], template["tags"])
```

```text
['vip'] [] []
```

With `template.copy()` instead of `deepcopy`, all three would share one `tags` list.

## Choosing a shape

- **One thing with named fields:** a dictionary.
- **Many things of the same kind, in order:** a list of dictionaries.
- **Many things looked up by ID:** a dictionary of dictionaries.
- **A group of values under each key:** a dictionary of lists or sets.

Pick the shape that makes your most frequent question easy to answer.

## Common mistakes

- **Losing track of the level.** Print `type(...)` at each step when unsure.
- **Chaining `[...]` through optional fields.** Use `.get(..., {})`.
- **Shallow copying nested templates.** Use `copy.deepcopy`.
- **Using a list of records for lookups by ID.** Key a dictionary by ID.

```python
team = [
    {"name": "Ada", "role": "dev", "skills": ["python", "math"]},
    {"name": "Linus", "role": "dev", "skills": ["c", "git"]},
    {"name": "Grace", "role": "lead", "skills": ["cobol", "python"]},
]

for person in team:
    if person["role"] == "dev":
        print(person["name"])

for person in team:
    if "python" in person["skills"]:
        print(person["name"])

counts = {}
for person in team:
    counts[person["name"]] = len(person["skills"])
print(counts)

by_skill = {}
for person in team:
    for skill in person["skills"]:
        by_skill.setdefault(skill, []).append(person["name"])
print(by_skill)
```

## Recap

- Dictionaries model records, and lists of dictionaries model tables of records.
- Key a dictionary by ID when you look records up by ID.
- Read nested paths one level at a time: `order["customer"]["address"]["city"]`.
- Chain `.get(key, {})` to navigate optional fields safely.
- `json.dumps(data, indent=2)` prints nested data readably. Deep-copy nested templates.
