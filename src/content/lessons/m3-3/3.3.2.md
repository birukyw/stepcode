# Context Managers & Resource Safety

Some things must be **given back**: an open file, a database connection, a lock, a network socket, a temporary directory, a stopped timer. If a program forgets (especially when an error interrupts it), resources leak, files stay half-written, and locks stay locked forever. Python's answer is the **`with` statement** and the **context manager** protocol: set something up, guarantee the cleanup, whatever happens in between. You have been using it since `with open(...)`. This lesson shows how it works and how to write your own.

## The problem with manual cleanup

```python
log = []

def read_manually(fail):
    handle = "opened"
    log.append("open")
    try:
        if fail:
            raise RuntimeError("boom")
        log.append("work")
    finally:
        log.append("close")          # must remember this every single time
    return handle

try:
    read_manually(True)
except RuntimeError:
    pass
read_manually(False)
print(log)
```

```text
['open', 'close', 'open', 'work', 'close']
```

`try`/`finally` works, but every function that touches a resource must remember the pattern, and it buries the real work. A context manager packages "setup and teardown" once.

## What `with` does

```python
class Section:
    def __enter__(self):
        print("setup")
        return "the resource"

    def __exit__(self, exc_type, exc_value, traceback):
        print("cleanup")
        return False

with Section() as thing:
    print("using", thing)
print("after")
```

```text
setup
using the resource
cleanup
after
```

The sequence is always the same:

1. Python calls `__enter__()`. Whatever it returns is bound to the name after `as`.
2. The body of the `with` block runs.
3. Python calls `__exit__(...)` **always**, even if the body raised an exception, returned, or hit `break`.

`__exit__` receives the exception details (type, value, traceback), or three `None`s if there was no error. Its return value matters:

- **`False` / `None`:** the exception, if any, continues to propagate.
- **`True`:** the exception is **swallowed** and the program continues after the `with` block.

```python
class Quiet:
    def __enter__(self):
        return self

    def __exit__(self, exc_type, exc_value, tb):
        print("saw:", exc_type.__name__ if exc_type else None)
        return exc_type is ValueError          # swallow ValueError only

with Quiet():
    raise ValueError("ignored")
print("continued")

try:
    with Quiet():
        raise KeyError("not ignored")
except KeyError:
    print("KeyError escaped")
```

```text
saw: ValueError
continued
saw: KeyError
KeyError escaped
```

Swallowing errors is powerful and dangerous. Only do it for errors you truly intend to ignore.

## A real one: a timer

```python
import time

class Timer:
    def __enter__(self):
        self.start = time.perf_counter()
        return self

    def __exit__(self, *exc):
        self.elapsed = time.perf_counter() - self.start
        return False

with Timer() as t:
    total = sum(range(200_000))

print(total, t.elapsed >= 0)
```

```text
19999900000 True
```

The timer stops even if the body fails, and the result is available afterwards on `t`.

## The easy way: `@contextmanager`

Writing a class with two dunder methods is wordy. `contextlib.contextmanager` turns a **generator** into a context manager: everything before `yield` is setup, and everything after is cleanup:

```python
from contextlib import contextmanager

@contextmanager
def announce(name):
    print("start", name)
    try:
        yield name.upper()
    finally:
        print("end", name)

with announce("job") as label:
    print("working on", label)

try:
    with announce("bad"):
        raise RuntimeError("fail")
except RuntimeError:
    print("error propagated")
```

```text
start job
working on JOB
end job
start bad
end bad
error propagated
```

The `try`/`finally` around `yield` is what guarantees the cleanup when the body fails: the exception is thrown into the generator **at the yield**. This is the form you will write most often.

### Useful examples

Change a setting temporarily and always restore it:

```python
import os
from contextlib import contextmanager

@contextmanager
def working_directory(path):
    previous = os.getcwd()
    os.chdir(path)
    try:
        yield
    finally:
        os.chdir(previous)

import tempfile
home = os.getcwd()
with tempfile.TemporaryDirectory() as folder:
    with working_directory(folder):
        inside = os.path.basename(os.getcwd()) == os.path.basename(folder)
print(inside, os.getcwd() == home)
```

```text
True True
```

```python
from contextlib import contextmanager

@contextmanager
def temporary_value(obj, name, value):
    original = getattr(obj, name)
    setattr(obj, name, value)
    try:
        yield obj
    finally:
        setattr(obj, name, original)

class Settings:
    debug = False

with temporary_value(Settings, "debug", True):
    print("inside:", Settings.debug)
print("after:", Settings.debug)
```

```text
inside: True
after: False
```

## Context managers in the standard library

Many tools you already know are context managers, and `contextlib` adds more:

```python
import io
import tempfile
from contextlib import suppress, redirect_stdout, closing

# suppress: ignore a specific error neatly
with suppress(FileNotFoundError):
    open("definitely-missing-file.txt")
print("no crash")

# redirect_stdout: capture print output
buffer = io.StringIO()
with redirect_stdout(buffer):
    print("captured text")
print(repr(buffer.getvalue()))

# TemporaryDirectory cleans up after itself
with tempfile.TemporaryDirectory() as folder:
    print(len(folder) > 0)
```

```text
no crash
'captured text\n'
True
```

`suppress(SomeError)` is the tidy form of `try: ... except SomeError: pass`, and it says clearly which error you chose to ignore. `redirect_stdout` is wonderful for testing code that prints.

## Several at once: ExitStack

How do you open a variable number of files? `ExitStack` collects context managers and unwinds them all in reverse order, even if one of them fails to open:

```python
from contextlib import ExitStack, contextmanager

events = []

@contextmanager
def resource(name):
    events.append("open " + name)
    try:
        yield name
    finally:
        events.append("close " + name)

with ExitStack() as stack:
    handles = [stack.enter_context(resource(n)) for n in ("a", "b", "c")]
    events.append("using " + ",".join(handles))

print(events)
```

```text
['open a', 'open b', 'open c', 'using a,b,c', 'close c', 'close b', 'close a']
```

They are closed in **reverse** order (`c`, `b`, `a`), like unstacking plates. `ExitStack` also supports `stack.callback(func)` for arbitrary cleanup.

## Nested and multiple with-items

You can list several managers in one `with`:

```python
from contextlib import contextmanager

order = []

@contextmanager
def ctx(name):
    order.append("enter " + name)
    try:
        yield
    finally:
        order.append("exit " + name)

with ctx("outer"), ctx("inner"):
    order.append("body")
print(order)
```

```text
['enter outer', 'enter inner', 'body', 'exit inner', 'exit outer']
```

## A realistic one: transactions

The classic use: "do several steps, and either keep all of them or undo them all". Lesson 3.3.4 does this with a database. Here is the same idea with a plain dictionary:

```python
from contextlib import contextmanager

@contextmanager
def transaction(data):
    snapshot = dict(data)                 # remember the state before
    try:
        yield data
    except Exception:
        data.clear()
        data.update(snapshot)             # roll back to the snapshot
        raise

account = {"alice": 100, "bob": 50}

with transaction(account):
    account["alice"] -= 30
    account["bob"] += 30
print(account)

try:
    with transaction(account):
        account["alice"] -= 500
        if account["alice"] < 0:
            raise ValueError("overdraft")
        account["bob"] += 500
except ValueError:
    pass
print(account)
```

```text
{'alice': 70, 'bob': 80}
{'alice': 70, 'bob': 80}
```

The failed transfer left **no trace**: the half-finished change was rolled back. That is the safety net context managers give you.

## Making your own classes work with `with`

Any class can become a context manager. A realistic example is a file that writes atomically: it writes to a temporary file and only replaces the real file if everything succeeds:

```python
import os
import tempfile

class AtomicWriter:
    def __init__(self, path):
        self.path = path

    def __enter__(self):
        folder = os.path.dirname(os.path.abspath(self.path))
        fd, self.tmp = tempfile.mkstemp(dir=folder)
        self.file = os.fdopen(fd, "w")
        return self.file

    def __exit__(self, exc_type, exc, tb):
        self.file.close()
        if exc_type is None:
            os.replace(self.tmp, self.path)      # success: swap in the new file
        else:
            os.remove(self.tmp)                  # failure: throw the draft away
        return False

with tempfile.TemporaryDirectory() as folder:
    target = os.path.join(folder, "data.txt")
    with open(target, "w") as f:
        f.write("original")

    try:
        with AtomicWriter(target) as f:
            f.write("half-written new content")
            raise RuntimeError("crash mid-write")
    except RuntimeError:
        pass
    print(open(target).read())

    with AtomicWriter(target) as f:
        f.write("complete new content")
    print(open(target).read())
```

```text
original
complete new content
```

If the program crashes midway, the original file is untouched, never left half-written. Lesson 3.3.3 builds on this idea.

## Common mistakes

- **Writing the cleanup after the `yield` without `try`/`finally`** in a `@contextmanager`, so a failure skips the cleanup.
- **Returning `True` from `__exit__` by accident,** silently swallowing every error.
- **Forgetting that `__enter__` must return the object** you want after `as`.
- **Using a resource after the `with` block,** when it has already been closed.
- **Opening files without `with`** and hoping they get closed.
- **Doing slow work in `__enter__`** that can fail without cleanup, because `__exit__` does not run if `__enter__` raised.

import tempfile, os, time

def marked(buffer):

            return True
        return False

s = Suppressing()
with s:

## Recap

- A **context manager** guarantees setup and teardown around a block. `with` calls `__enter__` (its return value goes after `as`) and always calls `__exit__`, even after an error, return or break.
- `__exit__` returns `True` to **swallow** the exception, and `False`/`None` to let it propagate. Swallow only deliberately.
- `@contextlib.contextmanager` turns a generator into one: code before `yield` is setup, and code after it (in a `finally`) is cleanup.
- The standard library helps: `open`, `tempfile.TemporaryDirectory`, `suppress`, `redirect_stdout`, and `ExitStack` for a variable number of resources (closed in reverse order).
- Context managers express **transactions** (all or nothing) and **atomic writes**: write a draft, then swap it in only on success.
- `__exit__` does not run if `__enter__` itself raises, and `async with` is the same idea for asynchronous code.
