# Topological Sort & DAG Dependency Resolution

Before you can bake the cake you need the batter, before the batter you need eggs, and before anything else you need a clean bowl. Build systems, course schedules, spreadsheet formulas and package installers all face the same puzzle: **given what depends on what, in which order should things happen?** The answer is a **topological sort**, and it only exists when there are no circular dependencies.

## DAGs: directed graphs without cycles

Draw an arrow from each prerequisite to the thing that needs it. If there is **no cycle**, the graph is a **DAG** (directed acyclic graph). A **topological order** lists every node so that **every arrow points forward**: a node always appears after everything it depends on.

```python
deps = {
    "eggs": ["batter"],
    "flour": ["batter"],
    "bowl": ["batter"],
    "batter": ["bake"],
    "oven": ["bake"],
    "bake": ["serve"],
    "serve": [],
}
print(len(deps), deps["batter"])
```

```text
7 ['bake']
```

Here `deps[x]` lists what `x` unlocks. A DAG may have **many** valid orders. If a cycle exists (A needs B, B needs A) there is **none**, which is how you detect impossible schedules.

## Kahn's algorithm: peel off the free items

The idea is natural. Anything with **no remaining prerequisites** can happen now. Do it, then remove it, which may free up others. Count each node's **in-degree** (its number of unmet prerequisites), start with the zeros, and keep peeling:

```python
from collections import deque

def topo_sort(graph):
    indegree = {n: 0 for n in graph}
    for node in graph:
        for nxt in graph[node]:
            indegree[nxt] += 1
    queue = deque(sorted(n for n in graph if indegree[n] == 0))
    order = []
    while queue:
        node = queue.popleft()
        order.append(node)
        for nxt in sorted(graph[node]):
            indegree[nxt] -= 1
            if indegree[nxt] == 0:
                queue.append(nxt)
    return order if len(order) == len(graph) else None

deps = {
    "eggs": ["batter"], "flour": ["batter"], "bowl": ["batter"],
    "batter": ["bake"], "oven": ["bake"], "bake": ["serve"], "serve": [],
}
print(topo_sort(deps))
```

```text
['bowl', 'eggs', 'flour', 'oven', 'batter', 'bake', 'serve']
```

Each edge is handled once, so the cost is **O(V + E)**.

### Cycle detection for free

If a cycle exists, the nodes on it never reach in-degree zero, so they never enter the queue and `len(order) < len(graph)`. The function above returns `None` in that case:

```python
from collections import deque

def topo_sort(graph):
    indegree = {n: 0 for n in graph}
    for node in graph:
        for nxt in graph[node]:
            indegree[nxt] += 1
    queue = deque(n for n in graph if indegree[n] == 0)
    order = []
    while queue:
        node = queue.popleft()
        order.append(node)
        for nxt in graph[node]:
            indegree[nxt] -= 1
            if indegree[nxt] == 0:
                queue.append(nxt)
    return order if len(order) == len(graph) else None

print(topo_sort({"a": ["b"], "b": ["c"], "c": []}))
print(topo_sort({"a": ["b"], "b": ["c"], "c": ["a"]}))
print(topo_sort({"a": ["b"], "b": ["c"], "c": ["b"], "d": []}))
```

```text
['a', 'b', 'c']
None
None
```

The third graph shows that a cycle can hide in one corner while the rest is fine: `d` is sorted but `b` and `c` are not, so the whole schedule is impossible.

## The DFS way

There is a second classic method. Run DFS, and add each node to a list **after all its descendants are finished** (post-order). Reversing that list gives a topological order:

```python
def topo_dfs(graph):
    order, state = [], {}
    def visit(node):
        state[node] = 1                      # in progress
        for nxt in graph[node]:
            if state.get(nxt) == 1:
                raise ValueError("cycle")
            if nxt not in state:
                visit(nxt)
        state[node] = 2
        order.append(node)                   # finished: everything it unlocks is already listed
    for n in graph:
        if n not in state:
            visit(n)
    return order[::-1]

order = topo_dfs({"shirt": ["tie", "belt"], "tie": ["jacket"], "pants": ["belt", "shoes"], "belt": ["jacket"], "socks": ["shoes"], "shoes": [], "jacket": []})
pos = {n: i for i, n in enumerate(order)}
print(all(pos[a] < pos[b] for a, bs in {"shirt": ["tie", "belt"], "tie": ["jacket"], "pants": ["belt", "shoes"], "belt": ["jacket"], "socks": ["shoes"]}.items() for b in bs))
```

```text
True
```

Kahn's version is iterative and tells you about cycles for free, which usually makes it the better default.

## Ordering with rules: course schedules

Real input arrives as pairs `(course, prerequisite)`. Build the graph, then sort:

```python
from collections import deque

def course_order(n, prerequisites):
    graph = {i: [] for i in range(n)}
    indegree = [0] * n
    for course, pre in prerequisites:
        graph[pre].append(course)
        indegree[course] += 1
    queue = deque(i for i in range(n) if indegree[i] == 0)
    order = []
    while queue:
        c = queue.popleft()
        order.append(c)
        for nxt in graph[c]:
            indegree[nxt] -= 1
            if indegree[nxt] == 0:
                queue.append(nxt)
    return order if len(order) == n else []

print(course_order(4, [(1, 0), (2, 0), (3, 1), (3, 2)]))
print(course_order(2, [(1, 0), (0, 1)]))
```

```text
[0, 1, 2, 3]
[]
```

## Using the order: longest path in a DAG

Once you have a topological order, a whole family of problems becomes a simple loop, because by the time you reach a node, **all its prerequisites are already done**. If each task takes some time, how long does the whole project take at minimum, assuming unlimited workers? That is the **longest path** through the DAG (the "critical path"):

```python
from collections import deque

def project_time(tasks, deps):
    # tasks: name -> duration, deps: name -> list of tasks it unlocks
    indegree = {t: 0 for t in tasks}
    for t, outs in deps.items():
        for o in outs:
            indegree[o] += 1
    finish = {t: tasks[t] for t in tasks}        # earliest finish time so far
    queue = deque(t for t in tasks if indegree[t] == 0)
    while queue:
        t = queue.popleft()
        for o in deps.get(t, []):
            finish[o] = max(finish[o], finish[t] + tasks[o])
            indegree[o] -= 1
            if indegree[o] == 0:
                queue.append(o)
    return max(finish.values())

tasks = {"design": 3, "build": 5, "test": 2, "docs": 1, "release": 1}
deps = {"design": ["build", "docs"], "build": ["test"], "test": ["release"], "docs": ["release"]}
print(project_time(tasks, deps))
```

```text
11
```

The critical path is design, build, test, release: 3 + 5 + 2 + 1 = 11. Docs finish long before, so speeding them up changes nothing. This is how project managers find what to shorten.

## Common mistakes

- **Edge direction.** Decide once what an arrow means ("unlocks" or "depends on") and stay consistent. Reversing it reverses the order.
- **Forgetting nodes that are only prerequisites.** Every node must appear as a key, even with an empty list.
- **Not checking for cycles.** If `len(order) < len(graph)` the order is incomplete.
- **Expecting one answer.** Many orders are valid. Sort the queue if you need a deterministic one.
- **Running it on an undirected graph.** Topological order only makes sense for directed edges.

```python
from collections import deque

def can_build(deps):
    indeg = {n: 0 for n in deps}
    for outs in deps.values():
        for o in outs:
            indeg[o] += 1
    q = deque(n for n in deps if indeg[n] == 0)
    seen = 0
    while q:
        n = q.popleft()
        seen += 1
        for o in deps[n]:
            indeg[o] -= 1
            if indeg[o] == 0:
                q.append(o)
    return seen == len(deps)

def all_levels(graph):
    indeg = {n: 0 for n in graph}
    for outs in graph.values():
        for o in outs:
            indeg[o] += 1
    level = sorted(n for n in graph if indeg[n] == 0)
    rounds = []
    while level:
        rounds.append(level)
        nxt = []
        for n in level:
            for o in graph[n]:
                indeg[o] -= 1
                if indeg[o] == 0:
                    nxt.append(o)
        level = sorted(nxt)
    return rounds

g = {"a": ["c"], "b": ["c"], "c": ["d"], "d": []}
print(can_build(g), all_levels(g))   # True [['a', 'b'], ['c'], ['d']]
```

```python
from collections import deque

def alien_order(words):
    graph = {ch: set() for w in words for ch in w}
    for a, b in zip(words, words[1:]):
        for x, y in zip(a, b):
            if x != y:
                graph[x].add(y)
                break
    indeg = {c: 0 for c in graph}
    for c in graph:
        for d in graph[c]:
            indeg[d] += 1
    q = deque(sorted(c for c in graph if indeg[c] == 0))
    out = []
    while q:
        c = q.popleft()
        out.append(c)
        for d in sorted(graph[c]):
            indeg[d] -= 1
            if indeg[d] == 0:
                q.append(d)
    return "".join(out)

print(alien_order(["wrt", "wrf", "er", "ett", "rftt"]))   # wertf
```

## Recap

- A **topological order** lists nodes so every dependency comes before what needs it. It exists only for a **DAG**.
- **Kahn's algorithm:** compute in-degrees, queue the zeros, pop one, lower its neighbours' in-degrees, queue new zeros. O(V + E).
- If fewer nodes come out than went in, there is a **cycle**: the schedule is impossible.
- The DFS alternative reverses the post-order.
- With a topological order, DP over a DAG is a single loop, as in the **critical path** (longest path) calculation.
