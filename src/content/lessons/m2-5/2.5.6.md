# Disjoint Set Union (Union-Find) & MST

Imagine you are laying cable between towns. You want every town connected, as cheaply as possible, and you must never lay a wire that connects two towns that are already connected. Every time you consider a wire you need to answer one question fast: **are these two towns already in the same network?** The structure built for exactly that question is **Union-Find**, also called **disjoint set union (DSU)**. It powers one of the most famous graph algorithms, minimum spanning trees.

## The problem

You have `n` items, each starting alone in its own group. Two operations:

- **union(a, b)**: merge the groups containing `a` and `b`.
- **find(a)**: which group is `a` in? Two items are in the same group when `find` returns the same answer.

A list of sets could do it, but merging and searching would cost O(n). We can do far better.

## Groups as trees

Represent each group as a tree where every item points to a **parent**, and the root points to itself. The root is the group's name:

```python
parent = list(range(8))        # each item is its own root

def find(x):
    while parent[x] != x:
        x = parent[x]
    return x

def union(a, b):
    ra, rb = find(a), find(b)
    if ra != rb:
        parent[ra] = rb

union(0, 1)
union(2, 3)
union(1, 3)
print(find(0) == find(2), find(0) == find(5))
print(parent)
```

```text
True False
[1, 3, 3, 3, 4, 5, 6, 7]
```

`union` hangs one root under the other. This works, but a bad sequence of unions builds a long chain, and `find` degenerates to O(n).

## Two optimizations that make it nearly O(1)

**Path compression:** while walking up to the root in `find`, point every visited node **directly at the root**. The next `find` on any of them takes one step.

**Union by size:** always hang the **smaller** tree under the larger one, so trees stay shallow.

```python
class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n
        self.groups = n

    def find(self, x):
        root = x
        while self.parent[root] != root:
            root = self.parent[root]
        while self.parent[x] != root:            # compress the path
            self.parent[x], x = root, self.parent[x]
        return root

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False                         # already connected
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]
        self.groups -= 1
        return True

d = DSU(6)
print(d.union(0, 1), d.union(1, 2), d.union(0, 2))
print(d.groups, d.size[d.find(0)])
print(d.find(0) == d.find(2), d.find(0) == d.find(4))
```

```text
True True False
4 3
True False
```

With both tricks, each operation costs **O(α(n))**, where α is the inverse Ackermann function: it never exceeds 4 for any input that could exist in the universe. In practice, treat it as **constant time**. Returning `False` when two items were already connected is the detail Kruskal's algorithm depends on.

A million unions and finds run instantly:

## Counting components and detecting cycles

Union-find answers "how many separate groups?" while edges stream in, and it detects a cycle the moment an edge connects two nodes that are **already** connected:

```python
class DSU:
    def __init__(self, n):
        self.parent = list(range(n))

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]     # path halving
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False
        self.parent[ra] = rb
        return True

def first_redundant_edge(n, edges):
    d = DSU(n)
    for a, b in edges:
        if not d.union(a, b):
            return (a, b)
    return None

print(first_redundant_edge(5, [(0, 1), (1, 2), (3, 4), (2, 0), (2, 3)]))
print(first_redundant_edge(3, [(0, 1), (1, 2)]))
```

```text
(2, 0)
None
```

Compared with DFS (lesson 2.5.2), union-find shines when edges **arrive over time** and you must answer connectivity queries in between.

## Minimum spanning trees

A **spanning tree** connects all `n` nodes with exactly `n - 1` edges and no cycles. In a weighted graph, the **minimum spanning tree (MST)** is the spanning tree with the smallest total weight: the cheapest way to wire up every town.

**Kruskal's algorithm** is greedy and short:

1. Sort all edges by weight, cheapest first.
2. Take each edge in turn. If it joins two **different** groups, keep it and union them. If both ends are already connected, skip it (it would make a cycle).
3. Stop when you have `n - 1` edges.

```python
class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]
        return True

def kruskal(n, edges):
    d = DSU(n)
    total, chosen = 0, []
    for w, a, b in sorted(edges):
        if d.union(a, b):
            total += w
            chosen.append((a, b, w))
            if len(chosen) == n - 1:
                break
    return total, chosen

towns = 5
cables = [(4, 0, 1), (8, 0, 2), (2, 1, 2), (6, 1, 3), (3, 2, 3), (9, 2, 4), (5, 3, 4)]
total, chosen = kruskal(towns, cables)
print(total)
print(chosen)
```

```text
14
[(1, 2, 2), (2, 3, 3), (0, 1, 4), (3, 4, 5)]
```

Sorting dominates: **O(E log E)**. Why is greedy correct here? At each step the cheapest edge that does not form a cycle is always safe to include: any spanning tree that omits it could swap it in for a heavier edge and get cheaper. (This "cut property" is the proof.)

If the graph is disconnected, you end with fewer than `n - 1` edges: a **minimum spanning forest**.

```python
class DSU:
    def __init__(self, n):
        self.parent = list(range(n))

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False
        self.parent[ra] = rb
        return True

def mst_cost(n, edges):
    d = DSU(n)
    total, used = 0, 0
    for w, a, b in sorted(edges):
        if d.union(a, b):
            total += w
            used += 1
    return total if used == n - 1 else None

print(mst_cost(4, [(1, 0, 1), (2, 1, 2), (3, 2, 3), (10, 0, 3)]))
print(mst_cost(4, [(1, 0, 1), (2, 2, 3)]))
```

```text
6
None
```

## Another MST route: Prim

**Prim's algorithm** grows a single tree outward from a start node, always adding the cheapest edge that leaves the tree. It uses the same min-heap as Dijkstra:

```python
import heapq

def prim(graph, start):
    seen = {start}
    heap = [(w, start, nxt) for nxt, w in graph[start]]
    heapq.heapify(heap)
    total = 0
    while heap and len(seen) < len(graph):
        w, a, b = heapq.heappop(heap)
        if b in seen:
            continue
        seen.add(b)
        total += w
        for nxt, w2 in graph[b]:
            if nxt not in seen:
                heapq.heappush(heap, (w2, b, nxt))
    return total

graph = {0: [(1, 4), (2, 8)], 1: [(0, 4), (2, 2), (3, 6)], 2: [(0, 8), (1, 2), (3, 3), (4, 9)], 3: [(1, 6), (2, 3), (4, 5)], 4: [(2, 9), (3, 5)]}
print(prim(graph, 0))
```

```text
14
```

Both reach the same total. Kruskal is nicer for a list of edges, Prim for dense graphs held as adjacency lists.

## Common mistakes

- **Using `parent[a] = b` without finding roots.** Always `find` first.
- **Skipping path compression or union by size,** leaving worst-case chains.
- **Forgetting that Kruskal needs sorted edges.** And sort by weight first in the tuple `(w, a, b)`.
- **Assuming a graph is connected.** Check you got `n - 1` edges.
- **Confusing MST with shortest paths.** An MST minimizes total cable. Dijkstra minimizes distance from one node.

```python
def merge_accounts(people):
    parent = list(range(len(people)))
    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x
    owner = {}
    for i, emails in enumerate(people):
        for e in emails:
            if e in owner:
                parent[find(i)] = find(owner[e])
            else:
                owner[e] = i
    groups = {}
    for i, emails in enumerate(people):
        groups.setdefault(find(i), set()).update(emails)
    return sorted(sorted(g) for g in groups.values())
```

## Recap

- **Union-Find** keeps disjoint groups as trees: `find` returns a group's root, `union` merges two groups.
- **Path compression** plus **union by size** make each operation almost constant time.
- `union` returning `False` means the two items were already connected, which detects cycles as edges arrive.
- A **minimum spanning tree** connects all nodes with `n - 1` edges at the least total weight.
- **Kruskal:** sort edges by weight and keep each edge that joins two different groups (O(E log E)). **Prim:** grow one tree with a heap.
