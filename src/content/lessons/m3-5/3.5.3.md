# Mocking, Stubbing & Dependency Isolation

A unit test should test **one unit**, quickly, the same way every time. But real code talks to the outside world: it sends email, charges credit cards, reads the clock, calls web services, touches databases. You cannot send a real email in every test run, a payment test must not charge a real card, and a test that depends on the current time or on random numbers will pass today and fail tomorrow. The solution is to **replace the outside world with stand-ins** you control. This lesson shows the vocabulary, the designs that make code easy to test, and Python's `unittest.mock` toolkit.

> **Tip:** Everything runs in the course editor. The helper `run_tests` runs a test class and prints a short summary, so the output is identical every time.

## The problem

```python
import time

def greeting():
    hour = time.localtime().tm_hour
    return "Good morning" if hour < 12 else "Good afternoon"

print(greeting() in ("Good morning", "Good afternoon"))
```

```text
True
```

How would you test that `greeting()` returns "Good morning" at 9 a.m.? You would have to run the test at 9 a.m. The function secretly depends on the **real clock**, and anything hidden like that makes tests slow, flaky or impossible.

## Test doubles: a vocabulary

A **test double** is a stand-in for a real dependency, like a stunt double in a film. They come in kinds:

| Kind | What it does | Example |
|---|---|---|
| **Dummy** | fills a parameter, never used | `None` or an empty object |
| **Stub** | returns **canned answers** | a clock that always says 9 a.m. |
| **Fake** | a **working but simplified** version | an in-memory database instead of a real one |
| **Mock** | **records how it was used**, so a test can verify the calls | "was `send` called once with this address?" |
| **Spy** | a real object that also records the calls | a real sender that counts uses |

Two broad styles of testing follow from this. **State-based**: run the code, then check the **result or final state** (preferred when possible). **Interaction-based**: check that the code **made the right calls** to a dependency (necessary for things like "an email was sent").

## Design for testing: dependency injection

The best fix needs no mocking library at all. Instead of the function reaching out and grabbing the clock, **pass the clock in** (lesson 3.2.6, Dependency Inversion):

```python
import io
import unittest

def greeting(clock):
    hour = clock()                                   # the dependency is a parameter
    return "Good morning" if hour < 12 else "Good afternoon"

class TestGreeting(unittest.TestCase):
    def test_morning(self):
        self.assertEqual(greeting(lambda: 9), "Good morning")      # a stub: always 9

    def test_afternoon(self):
        self.assertEqual(greeting(lambda: 15), "Good afternoon")

    def test_noon_boundary(self):
        self.assertEqual(greeting(lambda: 12), "Good afternoon")

def run_tests(case):
    suite = unittest.defaultTestLoader.loadTestsFromTestCase(case)
    result = unittest.TextTestRunner(stream=io.StringIO()).run(suite)
    return result.testsRun, len(result.failures), len(result.errors)

print(run_tests(TestGreeting))
```

```text
(3, 0, 0)
```

In production you pass the real clock (`lambda: time.localtime().tm_hour`), in tests a stub. A tiny change in design made the function **deterministic**, including the exact noon boundary. This is worth repeating: **code that is easy to test is code that receives its dependencies instead of creating them.**

## A hand-written fake

For something bigger, such as a notification service, write a **fake** that records what it was asked to do:

```python
import io
import unittest

class OrderService:
    def __init__(self, mailer, inventory):
        self.mailer = mailer
        self.inventory = inventory

    def place_order(self, email, item, qty):
        if self.inventory.get(item, 0) < qty:
            raise ValueError(f"not enough {item}")
        self.inventory[item] -= qty
        self.mailer.send(email, f"Order confirmed: {qty} x {item}")
        return "confirmed"

class FakeMailer:
    def __init__(self):
        self.sent = []

    def send(self, to, body):
        self.sent.append((to, body))

class TestOrderService(unittest.TestCase):
    def setUp(self):
        self.mailer = FakeMailer()
        self.inventory = {"pen": 5}
        self.service = OrderService(self.mailer, self.inventory)

    def test_order_reduces_stock_and_emails(self):
        self.assertEqual(self.service.place_order("ada@example.com", "pen", 2), "confirmed")
        self.assertEqual(self.inventory["pen"], 3)
        self.assertEqual(self.mailer.sent, [("ada@example.com", "Order confirmed: 2 x pen")])

    def test_insufficient_stock_sends_nothing(self):
        with self.assertRaises(ValueError):
            self.service.place_order("ada@example.com", "pen", 9)
        self.assertEqual(self.mailer.sent, [])
        self.assertEqual(self.inventory["pen"], 5)

def run_tests(case):
    suite = unittest.defaultTestLoader.loadTestsFromTestCase(case)
    result = unittest.TextTestRunner(stream=io.StringIO()).run(suite)
    return result.testsRun, len(result.failures), len(result.errors)

print(run_tests(TestOrderService))
```

```text
(2, 0, 0)
```

No real email was sent, no network used, and the test runs in microseconds. `FakeMailer` is trivial, and because we wrote it ourselves it behaves exactly as we expect. Many experienced developers prefer fakes like this because the tests read as plain code.

## unittest.mock: automatic doubles

When writing a fake by hand would be tedious, `unittest.mock.Mock` **fabricates** a stand-in that accepts any call and **remembers it**:

```python
from unittest.mock import Mock

mailer = Mock()
mailer.send("ada@example.com", "hello")
mailer.send("linus@example.com", "hi")

print(mailer.send.call_count)
print(mailer.send.call_args)                       # the most recent call
print(mailer.send.call_args_list[0])
mailer.send.assert_any_call("ada@example.com", "hello")
mailer.send.assert_called_with("linus@example.com", "hi")
print(mailer.send.call_args.args, mailer.send.call_args.kwargs)

mailer.reset_mock()
print(mailer.send.called)
```

```text
2
call('linus@example.com', 'hi')
call('ada@example.com', 'hello')
('linus@example.com', 'hi') {}
False
```

A `Mock` has **any attribute you ask for**, and every attribute is itself a mock. Calls are recorded, and the `assert_...` methods verify them (raising `AssertionError` if they are wrong). Useful checks:

- `assert_called_once()` and `assert_called_once_with(...)`
- `assert_not_called()`
- `assert_any_call(...)` and `assert_has_calls([...])`

## Controlling what a mock returns

```python
from unittest.mock import Mock

# return_value: a canned answer
gateway = Mock()
gateway.charge.return_value = {"status": "ok", "id": 17}
print(gateway.charge(25)["status"])

# side_effect with an exception: simulate failure
gateway.charge.side_effect = ConnectionError("network down")
try:
    gateway.charge(25)
except ConnectionError as err:
    print("raised:", err)

# side_effect with a list: a different result for each call
flaky = Mock(side_effect=[ConnectionError("1st fails"), ConnectionError("2nd fails"), "success"])
results = []
for _ in range(3):
    try:
        results.append(flaky())
    except ConnectionError as err:
        results.append(str(err))
print(results)

# side_effect with a function: compute the answer from the arguments
doubler = Mock(side_effect=lambda x: x * 2)
print(doubler(21))
```

```text
ok
raised: network down
['1st fails', '2nd fails', 'success']
42
```

`side_effect` raising an exception is how you test the **sad paths** that are hard to reproduce for real: network down, disk full, timeout. A list of values and exceptions plays out a scripted story, such as "fails twice, then works", which is exactly what you need to test retry logic.

## Using mocks in a test

```python
import io
import unittest
from unittest.mock import Mock

def charge_with_retry(gateway, amount, attempts=3):
    for attempt in range(1, attempts + 1):
        try:
            return gateway.charge(amount)
        except ConnectionError:
            if attempt == attempts:
                raise
    return None

class TestChargeWithRetry(unittest.TestCase):
    def test_succeeds_on_the_third_try(self):
        gateway = Mock()
        gateway.charge.side_effect = [ConnectionError(), ConnectionError(), "paid"]
        self.assertEqual(charge_with_retry(gateway, 50), "paid")
        self.assertEqual(gateway.charge.call_count, 3)
        gateway.charge.assert_called_with(50)

    def test_gives_up_after_three_failures(self):
        gateway = Mock()
        gateway.charge.side_effect = ConnectionError("down")
        with self.assertRaises(ConnectionError):
            charge_with_retry(gateway, 50)
        self.assertEqual(gateway.charge.call_count, 3)

    def test_no_retry_on_success(self):
        gateway = Mock()
        gateway.charge.return_value = "paid"
        charge_with_retry(gateway, 10)
        gateway.charge.assert_called_once_with(10)

def run_tests(case):
    suite = unittest.defaultTestLoader.loadTestsFromTestCase(case)
    result = unittest.TextTestRunner(stream=io.StringIO()).run(suite)
    return result.testsRun, len(result.failures), len(result.errors)

print(run_tests(TestChargeWithRetry))
```

```text
(3, 0, 0)
```

Without mocks, testing "retries three times then gives up" would need a real gateway that you can make fail on cue. With them, it is three lines.

## spec: stop typos from passing silently

A plain `Mock` accepts **any** attribute, so `mailer.sned(...)` (a typo) silently "works" and your test checks nothing. Give the mock the **shape of the real thing**:

```python
from unittest.mock import Mock, create_autospec

class Mailer:
    def send(self, to, body):
        ...

loose = Mock()
loose.sned("typo")                       # no error: the typo goes unnoticed
print("loose mock accepted a typo")

strict = Mock(spec=Mailer)
strict.send("ada@example.com", "hi")     # fine
try:
    strict.sned("typo")
except AttributeError:
    print("spec mock caught the typo")

auto = create_autospec(Mailer, instance=True)
auto.send("ada@example.com", "hi")
try:
    auto.send("only one argument")       # wrong number of arguments for the real signature
except TypeError:
    print("autospec caught the wrong signature")
```

```text
loose mock accepted a typo
spec mock caught the typo
autospec caught the wrong signature
```

`spec` limits the mock to the **real object's attributes**, and `create_autospec` also checks the **call signatures**. Use them by default: a mock that can never fail is worse than no test.

## patch: swap something temporarily

Sometimes you cannot inject a dependency (old code, a third-party library). `patch` **replaces an attribute for the duration of a test** and puts it back afterwards:

```python
import io
import random
import unittest
from unittest.mock import patch

def roll_dice():
    return random.randint(1, 6) + random.randint(1, 6)

def lucky():
    return roll_dice() == 7

class TestLucky(unittest.TestCase):
    def test_seven_is_lucky(self):
        with patch.object(random, "randint", side_effect=[3, 4]):      # replace random.randint
            self.assertTrue(lucky())

    def test_other_totals_are_not(self):
        with patch.object(random, "randint", return_value=6):
            self.assertFalse(lucky())

    @patch.object(random, "randint", return_value=1)
    def test_as_a_decorator(self, fake_randint):
        self.assertEqual(roll_dice(), 2)
        self.assertEqual(fake_randint.call_count, 2)

def run_tests(case):
    suite = unittest.defaultTestLoader.loadTestsFromTestCase(case)
    result = unittest.TextTestRunner(stream=io.StringIO()).run(suite)
    return result.testsRun, len(result.failures), len(result.errors)

print(run_tests(TestLucky))
print(1 <= random.randint(1, 6) <= 6)          # restored to the real function afterwards
```

```text
(3, 0, 0)
True
```

`patch.object(target, "name", ...)` replaces `target.name` and **restores it when the block (or decorated test) ends**, even if the test fails. You can use it as a `with` block or a decorator, and the replacement is a `MagicMock` unless you supply something else. There is also `patch("package.module.name")` taking a dotted string, and `patch.dict(os.environ, {...})` for temporarily changing a dictionary such as environment variables.

### The golden rule of patching: patch where it is **used**

If module `app` does `from time import time` and uses `time()`, then `app.time` is a **separate reference**. Patching `time.time` will not affect `app`. You must patch the name **in the module that looks it up**:

```python
import types
from unittest.mock import patch

source = types.ModuleType("app")
exec("from math import floor\ndef half(x):\n    return floor(x / 2)", source.__dict__)

import math
with patch.object(math, "floor", return_value=-1):
    print("patching math.floor:", source.half(10))           # app still holds the ORIGINAL floor

with patch.object(source, "floor", return_value=-1):
    print("patching app.floor:", source.half(10))            # the name app actually uses
```

```text
patching math.floor: 5
patching app.floor: -1
```

This is the single most common reason a patch "does nothing". Even better, avoid the problem with injection, so there is nothing to patch.

## MagicMock: mocks that support operators

`MagicMock` (what `patch` gives you by default) also supports dunder methods like `len()`, `[]`, `with`, and iteration:

```python
from unittest.mock import MagicMock

db = MagicMock()
db.__len__.return_value = 3
db.__getitem__.side_effect = lambda i: f"row{i}"
print(len(db), db[1])

with MagicMock() as ctx:                 # works as a context manager
    pass
print("context manager mock ok")

connection = MagicMock()
connection.cursor.return_value.fetchall.return_value = [("ada",), ("linus",)]
print(connection.cursor().fetchall())
```

```text
3 row1
context manager mock ok
[('ada',), ('linus',)]
```

The last line shows how to configure a **chain** of calls (`connection.cursor().fetchall()`) by setting `return_value` along the way.

## Time and randomness, the clean way

The patterns for the two classic flaky ingredients:

```python
import random

# Time: inject a clock
def expired(created_at, ttl, now):
    return now - created_at > ttl

print(expired(100, 60, now=150), expired(100, 60, now=200))

# Randomness: inject a random generator, or seed it
def shuffled(items, rng):
    items = list(items)
    rng.shuffle(items)
    return items

a = shuffled(range(5), random.Random(42))
b = shuffled(range(5), random.Random(42))
print(a == b)                              # the same seed gives the same "random" result
```

```text
False True
True
```

## Mock too much, learn too little

Mocking is a sharp tool. Over-use makes tests worthless:

- **Do not mock the thing you are testing.** If you mock your own function and assert the mock was called, you have tested the mock.
- **Do not mock what you do not own** (a third-party library's internals). Wrap it in a small class of your own, and fake **that**.
- **Prefer fakes and real objects for simple collaborators.** A real list, a real dictionary or a small in-memory fake is more convincing than a mock that returns whatever you tell it to.
- **Beware tests that mirror the code.** If a test is a line-for-line replay of the implementation's calls, then any refactor breaks it and it proves little. Check **outcomes**, and verify interactions only for real side effects (an email sent, a payment made).
- **Keep some tests that use real components together** (integration tests). Mocks cannot tell you that the real mail server rejects your message format.

## Common mistakes

- **Patching the wrong place** (`time.time` instead of `app.time`).
- **A mock with no `spec`,** accepting typos and wrong signatures.
- **Asserting on a mock's attribute that you set yourself,** which is circular.
- **Forgetting that mocks return mocks by default,** so `if mock.is_ok():` is always true.
- **Mocking everything,** until the test only proves the mocks agree with each other.
- **Leaving a patch active** by starting it manually and forgetting to stop it. Use `with` or the decorator.
- **Non-deterministic tests** from real time, randomness or the network.

## Practice

1. Rewrite `def is_weekend(): return datetime.today().weekday() >= 5` so that it takes the date as a parameter, then test it with a Saturday, a Wednesday and a Sunday.
2. Write a test for `notify(user, mailer)` using `Mock(spec=Mailer)` that checks `send` was called once with the user's email.
3. Test a function that retries an HTTP call twice, using `side_effect=[ConnectionError, ConnectionError, "data"]`.
4. Use `patch.object` to replace `random.choice` with a function that always returns the first item, and test a function that picks a "random" greeting.

+++ Solutions
```python
import datetime
import io
import random
import unittest
from unittest.mock import Mock, patch

def is_weekend(day):
    return day.weekday() >= 5

class Mailer:
    def send(self, to, body): ...

def notify(user, mailer):
    mailer.send(user["email"], "welcome")

def greeting():
    return random.choice(["hello", "hi", "hey"])

class T(unittest.TestCase):
    def test_weekend(self):
        self.assertTrue(is_weekend(datetime.date(2030, 1, 5)))      # a Saturday
        self.assertFalse(is_weekend(datetime.date(2030, 1, 2)))     # a Wednesday
        self.assertTrue(is_weekend(datetime.date(2030, 1, 6)))      # a Sunday

    def test_notify(self):
        mailer = Mock(spec=Mailer)
        notify({"email": "ada@example.com"}, mailer)
        mailer.send.assert_called_once_with("ada@example.com", "welcome")

    def test_greeting(self):
        with patch.object(random, "choice", side_effect=lambda items: items[0]):
            self.assertEqual(greeting(), "hello")

result = unittest.TextTestRunner(stream=io.StringIO()).run(unittest.defaultTestLoader.loadTestsFromTestCase(T))
print(result.testsRun, result.wasSuccessful())   # 3 True
```

## Recap

- Tests must be **fast and deterministic**, so real clocks, randomness, networks and mail servers are replaced by **test doubles**: dummies, **stubs** (canned answers), **fakes** (simple working versions), **mocks** (record calls) and spies.
- The best design for testing is **dependency injection**: pass in the clock, the mailer, the repository. No mocking tricks are needed, and hand-written **fakes** are often the clearest tests.
- `unittest.mock.Mock` accepts any call and records it. Check with `assert_called_once_with`, `call_count` and `call_args`. `return_value` gives canned results, and `side_effect` raises errors, plays a list of results, or runs a function, ideal for **sad paths** and **retries**.
- Use `Mock(spec=...)` or `create_autospec` so typos and wrong signatures fail. `MagicMock` also supports operators and context managers.
- `patch.object` (or `patch("module.name")`) swaps something for one test and restores it. **Patch the name where it is used**, not where it is defined.
- Do not over-mock: never mock the unit under test, do not mock what you do not own, prefer fakes and real objects, assert on outcomes, and keep some integration tests with real components.
