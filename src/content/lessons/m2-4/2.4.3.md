# Binary Search Trees (BST) & Balance

Binary search (lesson 2.3.1) is fast but needs a sorted array, and inserting into a sorted array is slow. A **binary search tree** keeps the halving idea and gives up the array: data stays ordered in a tree, so you can search, insert and delete in about O(log n). The catch, which this lesson makes you feel, is that the speed depends on the tree staying **balanced**.

## The rule

A **binary search tree** is a binary tree where, for **every** node:

- everything in its **left** subtree is smaller than it,
- everything in its **right** subtree is larger.

That one rule is what makes searching fast: at each node you compare once and discard an entire subtree.

```python
class Node:
    def __init__(self, key):
        self.key = key
        self.left = None
        self.right = None

def insert(root, key):
    if root is None:
        return Node(key)
    if key < root.key:
        root.left = insert(root.left, key)
    elif key > root.key:
        root.right = insert(root.right, key)
    return root                       # equal keys are ignored

def contains(root, key):
    while root:
        if key == root.key:
            return True
        root = root.left if key < root.key else root.right
    return False

root = None
for k in [50, 30, 70, 20, 40, 60, 80]:
    root = insert(root, k)
print(contains(root, 60), contains(root, 65))
```

```text
True False
```

Each comparison walks one level down, so search and insert cost **O(h)**, where h is the height of the tree.

## Inorder gives sorted order

Visit left, node, right (lesson 2.4.1) and a BST hands you its keys **in ascending order**. A BST is a sorted collection you can keep updating:

```python
class Node:
    def __init__(self, key):
        self.key, self.left, self.right = key, None, None

def insert(root, key):
    if root is None:
        return Node(key)
    if key < root.key:
        root.left = insert(root.left, key)
    elif key > root.key:
        root.right = insert(root.right, key)
    return root

def inorder(n):
    return [] if n is None else inorder(n.left) + [n.key] + inorder(n.right)

root = None
for k in [50, 30, 70, 20, 40, 60, 80, 35]:
    root = insert(root, k)
print(inorder(root))
```

```text
[20, 30, 35, 40, 50, 60, 70, 80]
```

The same walk also answers range questions and "k-th smallest" without sorting anything.

## Minimum, maximum and the neighbours

The smallest key is the **leftmost** node, the largest is the **rightmost**. The next larger key after `x` (its **successor**) is the leftmost node of its right subtree, or, if there is no right child, the last ancestor you passed while going **left**.

```python
class Node:
    def __init__(self, key):
        self.key, self.left, self.right = key, None, None

def insert(root, key):
    if root is None:
        return Node(key)
    if key < root.key:
        root.left = insert(root.left, key)
    elif key > root.key:
        root.right = insert(root.right, key)
    return root

def minimum(n):
    while n.left:
        n = n.left
    return n.key

def maximum(n):
    while n.right:
        n = n.right
    return n.key

def successor(root, key):
    best = None
    while root:
        if key < root.key:
            best = root.key           # a candidate: something bigger than key
            root = root.left
        else:
            root = root.right
    return best

root = None
for k in [50, 30, 70, 20, 40, 60, 80]:
    root = insert(root, k)
print(minimum(root), maximum(root), successor(root, 40), successor(root, 80))
```

```text
20 80 50 None
```

## Deleting a key

Deletion has three cases, and the third is the interesting one:

1. **A leaf**: just remove it.
2. **One child**: replace the node with that child.
3. **Two children**: the node cannot simply vanish. Replace its key with its **inorder successor** (the minimum of the right subtree), then delete that successor from the right subtree.

```python
class Node:
    def __init__(self, key):
        self.key, self.left, self.right = key, None, None

def insert(root, key):
    if root is None:
        return Node(key)
    if key < root.key:
        root.left = insert(root.left, key)
    elif key > root.key:
        root.right = insert(root.right, key)
    return root

def delete(root, key):
    if root is None:
        return None
    if key < root.key:
        root.left = delete(root.left, key)
    elif key > root.key:
        root.right = delete(root.right, key)
    else:
        if root.left is None:
            return root.right
        if root.right is None:
            return root.left
        succ = root.right
        while succ.left:
            succ = succ.left
        root.key = succ.key
        root.right = delete(root.right, succ.key)
    return root

def inorder(n):
    return [] if n is None else inorder(n.left) + [n.key] + inorder(n.right)

root = None
for k in [50, 30, 70, 20, 40, 60, 80]:
    root = insert(root, k)
root = delete(root, 20)
root = delete(root, 70)
root = delete(root, 50)
print(inorder(root))
print(root.key)
```

```text
[30, 40, 60, 80]
60
```

## Validating a BST

A frequent bug: checking only that each node is larger than its left child and smaller than its right child. That misses violations deeper down. The rule applies to the **whole subtree**, so pass down the allowed range:

```python
class Node:
    def __init__(self, key, left=None, right=None):
        self.key, self.left, self.right = key, left, right

def is_bst(n, lo=float("-inf"), hi=float("inf")):
    if n is None:
        return True
    if not lo < n.key < hi:
        return False
    return is_bst(n.left, lo, n.key) and is_bst(n.right, n.key, hi)

good = Node(10, Node(5), Node(15, Node(12), Node(20)))
bad = Node(10, Node(5), Node(15, Node(6), Node(20)))   # 6 is in the right subtree but < 10
print(is_bst(good), is_bst(bad))
```

```text
True False
```

## The balance problem

Insert the keys `1, 2, 3, ..., n` **in order** into a BST. Each new key is the largest, so it always goes right, and the tree becomes a **linked list**: height n, and every operation costs O(n). The ordering rule alone does not protect you.

```python
class Node:
    def __init__(self, key):
        self.key, self.left, self.right = key, None, None

def insert_iter(root, key):
    if root is None:
        return Node(key)
    cur = root
    while True:
        if key < cur.key:
            if cur.left is None:
                cur.left = Node(key)
                return root
            cur = cur.left
        else:
            if cur.right is None:
                cur.right = Node(key)
                return root
            cur = cur.right

def height(root):
    best, stack = 0, [(root, 1)] if root else []
    while stack:
        n, d = stack.pop()
        best = max(best, d)
        for c in (n.left, n.right):
            if c:
                stack.append((c, d + 1))
    return best

def build(keys):
    root = None
    for k in keys:
        root = insert_iter(root, k)
    return root

ordered = build(range(1, 1001))
middle_first = []
def fill(lo, hi):
    if lo > hi:
        return
    mid = (lo + hi) // 2
    middle_first.append(mid)
    fill(lo, mid - 1)
    fill(mid + 1, hi)
fill(1, 1000)
balanced = build(middle_first)
print(height(ordered), height(balanced))
```

```text
1000 10
```

Same keys, same rule: height **1000** versus **10**. A **balanced** tree keeps its height near log₂ n, which is what the fast operations rely on. Self-balancing trees (AVL, red-black) repair the shape after every insert or delete with small local **rotations**, guaranteeing O(log n). You rarely write one yourself, but databases, `std::map` in C++ and Java's `TreeMap` use them.

A rotation lifts a node over its parent while keeping the ordering rule intact:

```python
class Node:
    def __init__(self, key, left=None, right=None):
        self.key, self.left, self.right = key, left, right

def rotate_left(x):
    y = x.right
    x.right = y.left
    y.left = x
    return y                         # y is the new root of this subtree

def inorder(n):
    return [] if n is None else inorder(n.left) + [n.key] + inorder(n.right)

# a right-leaning chain 1 -> 2 -> 3
chain = Node(1, None, Node(2, None, Node(3)))
fixed = rotate_left(chain)
print(fixed.key, fixed.left.key, fixed.right.key)
print(inorder(fixed))
```

```text
2 1 3
[1, 2, 3]
```

The inorder list is unchanged, which proves the BST property survived. Only the shape got better.

## In Python

Python has no built-in tree. The usual substitutes: a **sorted list with `bisect`** for read-heavy data, a `dict` when you do not need order, and the third-party `sortedcontainers` package when you need both. Learn the tree to understand what those are doing, and because **hierarchical data** keeps appearing.

## Common mistakes

- **Validating only parent-child pairs.** Pass the range down, as in `is_bst`.
- **Duplicate keys with no policy.** Decide: ignore, count, or always send equals to one side.
- **Assuming O(log n).** It is O(h), and h can be n.
- **Forgetting to reassign the child** in a recursive insert or delete: `root.left = insert(root.left, key)`.
- **Deleting a two-child node by removing it directly.** Use the successor.

```python
class Node:
    def __init__(self, key, left=None, right=None):
        self.key, self.left, self.right = key, left, right

def kth_smallest(root, k):
    stack, cur = [], root
    while cur or stack:
        while cur:
            stack.append(cur)
            cur = cur.left
        cur = stack.pop()
        k -= 1
        if k == 0:
            return cur.key
        cur = cur.right

def range_sum(n, lo, hi):
    if n is None:
        return 0
    if n.key < lo:
        return range_sum(n.right, lo, hi)
    if n.key > hi:
        return range_sum(n.left, lo, hi)
    return n.key + range_sum(n.left, lo, hi) + range_sum(n.right, lo, hi)

def lca(root, a, b):
    while root:
        if a < root.key and b < root.key:
            root = root.left
        elif a > root.key and b > root.key:
            root = root.right
        else:
            return root.key

def from_sorted(keys):
    if not keys:
        return None
    mid = len(keys) // 2
    return Node(keys[mid], from_sorted(keys[:mid]), from_sorted(keys[mid + 1:]))

t = from_sorted([1, 2, 3, 4, 5, 6, 7])
print(kth_smallest(t, 3), range_sum(t, 3, 6), lca(t, 1, 3), t.key)   # 3 18 2 4
```

## Recap

- A **BST** keeps every left subtree smaller and every right subtree larger than its node, so each comparison discards a subtree.
- Search, insert and delete cost **O(h)**. Inorder traversal yields the keys sorted.
- Deleting a node with two children means copying in its **inorder successor** and deleting that instead.
- Validate with an allowed range passed down, not just parent-child comparisons.
- Inserting sorted data builds a chain with height n. **Balanced** trees (AVL, red-black) use rotations to stay near log₂ n.
