# Binary Heaps & Priority Queues (heapq)

A normal queue serves whoever arrived first. A **priority queue** serves whoever is **most important**, regardless of arrival: the sickest patient in a waiting room, the next event in a simulation, the shortest road in a GPS search. The structure behind it is the **binary heap**, and Python gives you one in the `heapq` module.

## What a priority queue must do

Two operations, both fast:

- **push** an item with a priority,
- **pop** the item with the smallest (or largest) priority.

A sorted list makes pop cheap but push O(n). An unsorted list makes push cheap but pop O(n). A **heap** makes both **O(log n)**, and reading the minimum **O(1)**.

## heapq: a min-heap on a list

```python
import heapq

heap = []
for n in [5, 1, 8, 3, 2]:
    heapq.heappush(heap, n)

print(heap[0])
print([heapq.heappop(heap) for _ in range(len(heap))])
```

```text
1
[1, 2, 3, 5, 8]
```

`heap[0]` is always the smallest item. Popping repeatedly returns the items in sorted order, which is **heap sort**. Note that `heapq` is a **min**-heap: the smallest comes out first.

```python
import heapq

data = [9, 4, 7, 1, 8, 2]
heapq.heapify(data)            # rearrange a list into a heap in place, O(n)
print(data[0])
print(heapq.nsmallest(3, [9, 4, 7, 1, 8, 2]))
print(heapq.nlargest(2, [9, 4, 7, 1, 8, 2]))
```

```text
1
[1, 2, 4]
[9, 8]
```

For a **max**-heap, push negated values, or negate the priority.

## How a heap works

A heap is a **complete binary tree** (every level full except possibly the last, filled left to right) with one rule: **every parent is smaller than or equal to its children**. That rule puts the minimum at the root. Because the tree is complete, it fits in a plain list with no pointers:

```python
heap = [1, 3, 2, 7, 4, 5]
#            1            index 0
#          /   \
#         3     2         indexes 1, 2
#        / \   /
#       7   4 5           indexes 3, 4, 5

def parent(i): return (i - 1) // 2
def left(i):   return 2 * i + 1
def right(i):  return 2 * i + 2

print(parent(4), left(1), right(1))
print(heap[left(1)], heap[right(1)])
```

```text
1 3 4
7 4
```

The index arithmetic is the whole structure. Now the two operations.

**Push** puts the new item at the end (the next free slot), then **sifts up**: while it is smaller than its parent, swap them. The tree is only `log₂ n` levels tall, so that is at most log n swaps.

**Pop** takes the root. To keep the tree complete, move the **last** item into the root, then **sifts down**: swap it with its **smaller** child until it is no larger than both.

```python
class MinHeap:
    def __init__(self):
        self.a = []

    def push(self, x):
        a = self.a
        a.append(x)
        i = len(a) - 1
        while i > 0 and a[i] < a[(i - 1) // 2]:
            a[i], a[(i - 1) // 2] = a[(i - 1) // 2], a[i]
            i = (i - 1) // 2

    def pop(self):
        a = self.a
        top = a[0]
        last = a.pop()
        if a:
            a[0] = last
            i, n = 0, len(a)
            while True:
                smallest = i
                for c in (2 * i + 1, 2 * i + 2):
                    if c < n and a[c] < a[smallest]:
                        smallest = c
                if smallest == i:
                    break
                a[i], a[smallest] = a[smallest], a[i]
                i = smallest
        return top

h = MinHeap()
for n in [5, 1, 8, 3, 2, 9, 4]:
    h.push(n)
print(h.a)
print([h.pop() for _ in range(7)])
```

```text
[1, 2, 4, 5, 3, 9, 8]
[1, 2, 3, 4, 5, 8, 9]
```

Both operations walk one root-to-leaf path, so they cost **O(log n)**. That is why a heap beats the two list approaches.

## Priorities with tuples

`heapq` compares items. A tuple compares element by element, so `(priority, item)` pairs give you a task queue:

```python
import heapq

tasks = []
heapq.heappush(tasks, (2, "write report"))
heapq.heappush(tasks, (1, "fix outage"))
heapq.heappush(tasks, (3, "plan lunch"))
heapq.heappush(tasks, (1, "call client"))

while tasks:
    priority, name = heapq.heappop(tasks)
    print(priority, name)
```

```text
1 call client
1 fix outage
2 write report
3 plan lunch
```

Notice the tie: with equal priorities, Python compares the next element, the text. If the second elements cannot be compared (for example, dictionaries), add a **counter** as a tiebreaker: `(priority, counter, item)`.

## Top-K with a small heap

To find the 3 largest of a million numbers, you do not need to sort them. Keep a **min-heap of size 3**. If a new number beats the smallest of the three, swap it in. That is O(n log k):

```python
import heapq

def top_k(nums, k):
    heap = []
    for n in nums:
        if len(heap) < k:
            heapq.heappush(heap, n)
        elif n > heap[0]:
            heapq.heapreplace(heap, n)     # pop the smallest, push n
    return sorted(heap, reverse=True)

print(top_k([4, 1, 9, 7, 3, 8, 2, 6], 3))
```

```text
[9, 8, 7]
```

## Merging sorted streams

`heapq.merge` combines already-sorted inputs lazily, using a heap of each stream's current head. It never loads everything into memory:

```python
import heapq

a = [1, 4, 9]
b = [2, 3, 10]
c = [5, 6, 7]
print(list(heapq.merge(a, b, c)))
```

```text
[1, 2, 3, 4, 5, 6, 7, 9, 10]
```

## The running median: two heaps

How do you keep the median of a stream of numbers? Hold the **smaller half** in a max-heap and the **larger half** in a min-heap, balanced to differ in size by at most one. The median is at the top of one heap or between the two tops:

```python
import heapq

class RunningMedian:
    def __init__(self):
        self.low = []      # max-heap (stored negated): smaller half
        self.high = []     # min-heap: larger half

    def add(self, x):
        heapq.heappush(self.low, -x)
        heapq.heappush(self.high, -heapq.heappop(self.low))    # move the biggest low item up
        if len(self.high) > len(self.low):
            heapq.heappush(self.low, -heapq.heappop(self.high))

    def median(self):
        if len(self.low) > len(self.high):
            return -self.low[0]
        return (-self.low[0] + self.high[0]) / 2

rm = RunningMedian()
for n in [5, 15, 1, 3]:
    rm.add(n)
    print(rm.median())
```

```text
5
10.0
5
4.0
```

Each add is O(log n), and the median is O(1). Two simple heaps beat repeatedly sorting.

## Scheduling and Dijkstra

The heap powers some of the most famous algorithms. A scheduler pops the next due event. **Dijkstra's shortest path** (module 2.5) always expands the closest unvisited node, which is exactly "pop the minimum". This tiny simulation processes events in time order, whatever order they were added:

```python
import heapq

events = []
for time, label in [(5, "email"), (1, "boot"), (3, "login"), (2, "load")]:
    heapq.heappush(events, (time, label))

clock = []
while events:
    t, label = heapq.heappop(events)
    clock.append(f"{t}:{label}")
print(" ".join(clock))
```

```text
1:boot 2:load 3:login 5:email
```

## Common mistakes

- **Treating `heapq` as a max-heap.** It is a min-heap. Negate values for the largest.
- **Reading `heap[1]` as the second smallest.** Only `heap[0]` is guaranteed. The rest is partially ordered.
- **Sorting a heap list directly or indexing it as sorted.** Pop to get sorted order.
- **Mutating an item already in the heap.** Its position is not fixed up. Push a new entry and ignore the stale one.
- **Comparing unorderable tiebreakers.** Add a counter in the tuple.

```python
import heapq

def k_largest(nums, k):
    heap = []
    for n in nums:
        heapq.heappush(heap, n)
        if len(heap) > k:
            heapq.heappop(heap)
    return sorted(heap, reverse=True)

def merge_k(lists):
    heap = [(l[0], i, 0) for i, l in enumerate(lists) if l]
    heapq.heapify(heap)
    out = []
    while heap:
        value, i, pos = heapq.heappop(heap)
        out.append(value)
        if pos + 1 < len(lists[i]):
            heapq.heappush(heap, (lists[i][pos + 1], i, pos + 1))
    return out

def reorganize(text):
    from collections import Counter
    heap = [(-c, ch) for ch, c in Counter(text).items()]
    heapq.heapify(heap)
    out, held = [], None
    while heap:
        c, ch = heapq.heappop(heap)
        out.append(ch)
        if held:
            heapq.heappush(heap, held)
            held = None
        if c + 1 < 0:
            held = (c + 1, ch)
    return "".join(out) if not held else ""

print(k_largest([4, 1, 9, 7, 3], 2))        # [9, 7]
print(merge_k([[1, 4], [2, 3], [0, 9]]))    # [0, 1, 2, 3, 4, 9]
print(reorganize("aab"), repr(reorganize("aaab")))   # aba ''
```

`heapify` builds bottom-up: most nodes are near the leaves and sift down only a step or two, so the total is a convergent sum of O(n). Pushing one at a time sifts each new item up a path as long as log n.

## Recap

- A **priority queue** serves the most important item first. A **binary heap** gives push and pop in O(log n) and the minimum in O(1).
- A heap is a **complete tree stored in a list**: children of `i` live at `2i + 1` and `2i + 2`, the parent at `(i - 1) // 2`.
- Push sifts up, pop moves the last item to the root and sifts down.
- `heapq` is a **min-heap**: `heappush`, `heappop`, `heapify`, `nsmallest`, `nlargest`, `merge`. Negate values for a max-heap, and use `(priority, counter, item)` tuples.
- Patterns: top-k with a size-k heap, merging sorted streams, two heaps for a running median, event schedulers and Dijkstra.
