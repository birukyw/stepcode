# Prefix Trees (Tries) & Autocomplete

Type "pyth" into a search box and a list appears: "python", "pytorch", "pythagoras". The app does not scan every word it knows. It uses a **trie** (pronounced "try"), a tree built from the **letters** of the words themselves. Lookups cost time proportional to the length of the word, not the size of the dictionary.

## The idea: share prefixes

Storing `car`, `card` and `care` as separate strings repeats `car` three times. A trie stores each letter once, and words that start the same way share a path:

```tree
(root)
  └ c
    └ a
      └ r *          * marks the end of a word
        ├ d *
        └ e *
```

Each node represents a prefix. A flag marks whether a word **ends** there, because `car` is a word and also a prefix of `card`.

## Building a trie

Each node holds a dictionary from a letter to the child node:

```python
class TrieNode:
    def __init__(self):
        self.children = {}
        self.is_word = False

class Trie:
    def __init__(self):
        self.root = TrieNode()

    def insert(self, word):
        node = self.root
        for ch in word:
            if ch not in node.children:
                node.children[ch] = TrieNode()
            node = node.children[ch]
        node.is_word = True

    def _walk(self, text):
        node = self.root
        for ch in text:
            node = node.children.get(ch)
            if node is None:
                return None
        return node

    def contains(self, word):
        node = self._walk(word)
        return node is not None and node.is_word

    def starts_with(self, prefix):
        return self._walk(prefix) is not None

t = Trie()
for w in ["car", "card", "care", "dog"]:
    t.insert(w)
print(t.contains("car"), t.contains("ca"), t.starts_with("ca"), t.starts_with("cat"))
```

```text
True False True False
```

Insert and lookup both take **O(L)**, where L is the length of the word, regardless of how many words are stored. A hash set also gives O(1) lookups for whole words, but it cannot answer **"does anything start with this?"** without scanning everything. That question is what a trie is for.

## Autocomplete

To list every word under a prefix: walk down to the prefix node, then collect the words in its subtree with a depth-first search.

```python
class TrieNode:
    def __init__(self):
        self.children = {}
        self.is_word = False

class Trie:
    def __init__(self, words=()):
        self.root = TrieNode()
        for w in words:
            self.insert(w)

    def insert(self, word):
        node = self.root
        for ch in word:
            node = node.children.setdefault(ch, TrieNode())
        node.is_word = True

    def complete(self, prefix, limit=5):
        node = self.root
        for ch in prefix:
            node = node.children.get(ch)
            if node is None:
                return []
        out = []
        def collect(n, path):
            if len(out) >= limit:
                return
            if n.is_word:
                out.append(prefix + path)
            for ch in sorted(n.children):            # alphabetical order
                collect(n.children[ch], path + ch)
        collect(node, "")
        return out

t = Trie(["python", "pytorch", "pythagoras", "pyramid", "java", "pycharm"])
print(t.complete("py"))
print(t.complete("pyth"))
print(t.complete("x"))
print(t.complete("py", limit=2))
```

```text
['pycharm', 'pyramid', 'pythagoras', 'python', 'pytorch']
['pythagoras', 'python']
[]
['pycharm', 'pyramid']
```

The cost is O(prefix length + size of the part of the subtree you read). With a limit, it stops early, which keeps typing responsive on huge dictionaries.

## Counting words per prefix

Store a **count** in each node as you pass through, and you can ask "how many words start with this?" in O(prefix length), with no traversal at all:

```python
class TrieNode:
    def __init__(self):
        self.children = {}
        self.passing = 0            # words that go through this node
        self.is_word = False

class Trie:
    def __init__(self):
        self.root = TrieNode()

    def insert(self, word):
        node = self.root
        for ch in word:
            node = node.children.setdefault(ch, TrieNode())
            node.passing += 1
        node.is_word = True

    def count_prefix(self, prefix):
        node = self.root
        for ch in prefix:
            node = node.children.get(ch)
            if node is None:
                return 0
        return node.passing

t = Trie()
for w in ["apple", "app", "apply", "ape", "bat"]:
    t.insert(w)
print(t.count_prefix("ap"), t.count_prefix("app"), t.count_prefix("b"), t.count_prefix("z"))
```

```text
4 3 1 0
```

## Longest common prefix

Walk down from the root while there is exactly one child and no word ends:

```python
class TrieNode:
    def __init__(self):
        self.children = {}
        self.is_word = False

def longest_common_prefix(words):
    root = TrieNode()
    for w in words:
        node = root
        for ch in w:
            node = node.children.setdefault(ch, TrieNode())
        node.is_word = True
    prefix, node = "", root
    while len(node.children) == 1 and not node.is_word:
        ch, node = next(iter(node.children.items()))
        prefix += ch
    return prefix

print(repr(longest_common_prefix(["flower", "flow", "flight"])))
print(repr(longest_common_prefix(["dog", "racecar", "car"])))
print(repr(longest_common_prefix(["interview", "internet", "interval"])))
```

```text
'fl'
''
'inter'
```

## Wildcard search

Because the structure is a tree, a `.` wildcard that matches any letter is a short extension: at a wildcard, try **every** child.

```python
class TrieNode:
    def __init__(self):
        self.children = {}
        self.is_word = False

class Dictionary:
    def __init__(self):
        self.root = TrieNode()

    def add(self, word):
        node = self.root
        for ch in word:
            node = node.children.setdefault(ch, TrieNode())
        node.is_word = True

    def search(self, pattern):
        def go(node, i):
            if i == len(pattern):
                return node.is_word
            ch = pattern[i]
            if ch == ".":
                return any(go(child, i + 1) for child in node.children.values())
            child = node.children.get(ch)
            return child is not None and go(child, i + 1)
        return go(self.root, 0)

d = Dictionary()
for w in ["bad", "dad", "mad"]:
    d.add(w)
print(d.search("pad"), d.search("bad"), d.search(".ad"), d.search("b.."), d.search("b."))
```

```text
False True True True False
```

## Memory trade-offs

A trie with a dictionary per node can use more memory than a set of the same words, since every node pays for its own dictionary. Real systems shrink it:

- store children in a fixed array of 26 slots when the alphabet is small,
- **compress** chains of single-child nodes into one edge labelled with a whole substring (a **radix tree**),
- use a trie only when you need **prefix** operations. For plain exact-match lookups, a `set` is simpler and smaller.

Where tries show up: autocomplete and spell checkers, IP routing tables (longest matching prefix), T9-style keyboards, and word games like Boggle.

## Common mistakes

- **Forgetting the end-of-word flag.** Without it, `"car"` cannot be told apart from a mere prefix of `"card"`.
- **Using `contains` where you meant `starts_with`.** One checks the flag, the other only that the path exists.
- **Case and character issues.** Normalize input (`.lower()`) before inserting and searching.
- **Unbounded autocomplete.** Always limit results or you may return a million words.
- **Using a trie for a tiny word list.** A sorted list with `bisect` or a plain loop is simpler.

```python
def replace_words(roots, sentence):
    root_set = set(roots)
    out = []
    for word in sentence.split():
        for i in range(1, len(word) + 1):
            if word[:i] in root_set:
                word = word[:i]
                break
        out.append(word)
    return " ".join(out)

print(replace_words(["cat", "bat", "rat"], "the cattle was rattled by the battery"))
# the cat was rat by the bat
```

## Recap

- A **trie** stores words letter by letter in a tree, so words that share a prefix share a path. Each node has a children dictionary and an `is_word` flag.
- Insert and lookup cost **O(L)** for a word of length L, independent of how many words are stored.
- Its superpower is **prefix queries**: `starts_with`, autocomplete (walk to the prefix, then DFS the subtree), prefix counts and longest common prefix.
- A `.` wildcard is a loop over all children at that step.
- Tries trade memory for prefix speed. Use a `set` when you only need exact matches.
