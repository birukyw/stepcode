# Fixed & Dynamic Sliding Windows

Imagine a stock ticker and the question "what was the best three-day stretch?" Or a log file and "what is the longest run without an error?" Both ask about a **contiguous stretch** of a sequence, and the efficient way to answer is to keep a **window** that slides along the data, updating its answer instead of recomputing it from scratch.

## The slow way

The best sum of `k` consecutive items, computed by brute force:

```python
def best_window_slow(nums, k):
    best = None
    steps = 0
    for start in range(len(nums) - k + 1):
        total = 0
        for i in range(start, start + k):
            total += nums[i]
            steps += 1
        if best is None or total > best:
            best = total
    return best, steps

nums = [2, 1, 5, 1, 3, 2, 8, 1, 4, 6]
print(best_window_slow(nums, 3))
```

```text
(13, 24)
```

Each window re-adds `k` numbers it mostly added last time. That is O(n · k).

## Fixed window: add one, remove one

Moving the window one step right changes exactly two numbers: one enters on the right, one leaves on the left. So update the running total with those two:

```python
def best_window(nums, k):
    window = sum(nums[:k])
    best = window
    for i in range(k, len(nums)):
        window += nums[i] - nums[i - k]     # one in, one out
        best = max(best, window)
    return best

nums = [2, 1, 5, 1, 3, 2, 8, 1, 4, 6]
print(best_window(nums, 3))
print(best_window(nums, 5))
```

```text
13
21
```

Each step does constant work, so the whole thing is **O(n)**, however large `k` is.

## Dynamic window: grow until it breaks, then shrink

Often the window size is not given. You expand it to take in more, and **shrink from the left** when a rule is broken. The window is described by two pointers, `left` and `right`, and a bit of state about what is inside.

### Example: the longest stretch without a repeated letter

```python
def longest_unique(text):
    seen = set()
    left = 0
    best = 0
    for right, ch in enumerate(text):
        while ch in seen:           # the window is broken: shrink
            seen.remove(text[left])
            left += 1
        seen.add(ch)
        best = max(best, right - left + 1)
    return best

print(longest_unique("abcabcbb"))
print(longest_unique("bbbbb"))
print(longest_unique("pwwkew"))
```

```text
3
1
3
```

`right` visits each character once. `left` also only moves forward, so across the whole run each character enters the set once and leaves at most once. Despite the `while` inside the `for`, the total is **O(n)**.

The window invariant is the heart of the method: **everything between `left` and `right` has no repeated letter.** The `while` loop restores it whenever adding a new letter breaks it.

## Example: the shortest stretch reaching a target sum

Given positive numbers, find the shortest contiguous run whose sum is at least `target`:

```python
def shortest_run(nums, target):
    left = 0
    total = 0
    best = None
    for right, value in enumerate(nums):
        total += value
        while total >= target:
            length = right - left + 1
            if best is None or length < best:
                best = length
            total -= nums[left]
            left += 1
    return best

print(shortest_run([2, 3, 1, 2, 4, 3], 7))
print(shortest_run([1, 1, 1], 10))
```

```text
2
None
```

Here the window **grows** until it is big enough, then **shrinks** as far as it can while staying valid, recording the best length at each step. It relies on every number being positive, because that is what guarantees that shrinking can only reduce the sum.

## A recipe for any window problem

1. Decide what the window **state** is: a running sum, a set of letters, a count dictionary.
2. Move `right` forward one item at a time and add that item to the state.
3. While the window **violates** the rule, move `left` forward and remove that item from the state.
4. After the window is valid, **record** the answer.

Almost every sliding-window problem is this loop with a different state and a different rule.

## Windows with counts

When the rule involves how often each item appears, the state is a dictionary of counts. For example, the longest stretch with at most two distinct letters:

```python
def longest_two_distinct(text):
    counts = {}
    left = 0
    best = 0
    for right, ch in enumerate(text):
        counts[ch] = counts.get(ch, 0) + 1
        while len(counts) > 2:
            gone = text[left]
            counts[gone] -= 1
            if counts[gone] == 0:
                del counts[gone]
            left += 1
        best = max(best, right - left + 1)
    return best

print(longest_two_distinct("eceba"))
print(longest_two_distinct("ccaabbb"))
```

```text
3
5
```

Removing a key when its count reaches zero keeps `len(counts)` equal to the number of distinct letters in the window.

## Fixed or dynamic?

| Clue in the problem | Window type |
|---|---|
| "of size k", "every k items" | fixed |
| "longest", "shortest", "at most", "at least" | dynamic |
| contains negative numbers and a target sum | not a plain window (see lesson 2.1.5) |

## Common mistakes

- **Recomputing the window sum from scratch** instead of adding one and subtracting one.
- **Forgetting to remove the leaving item** from the state when `left` moves.
- **Using `if` where you need `while`.** Shrinking may take several steps.
- **Applying the shrinking trick to data with negatives**, where a smaller window can have a larger sum.
- **Off-by-one in the window length.** It is `right - left + 1`.

## Practice

1. Find the maximum average of any 4 consecutive numbers in `[1, 12, -5, -6, 50, 3]`.
2. Write `max_ones(bits)` that returns the length of the longest run of `1`s in a list of 0s and 1s.
3. Write `longest_at_most_k(text, k)` returning the longest stretch containing at most `k` distinct letters. Verify `longest_at_most_k("aabbcc", 2)` is 4.
4. For which of these would a sliding window work, and why: "longest run with sum exactly 10 in a list that contains negatives", or "longest run of equal items"?

+++ Solutions
```python
def best_average(nums, k):
    window = sum(nums[:k])
    best = window
    for i in range(k, len(nums)):
        window += nums[i] - nums[i - k]
        best = max(best, window)
    return best / k

print(best_average([1, 12, -5, -6, 50, 3], 4))   # 12.75
```

```python
def max_ones(bits):
    best = run = 0
    for b in bits:
        run = run + 1 if b == 1 else 0
        best = max(best, run)
    return best

print(max_ones([1, 1, 0, 1, 1, 1]))   # 3
```

```python
def longest_at_most_k(text, k):
    counts = {}
    left = best = 0
    for right, ch in enumerate(text):
        counts[ch] = counts.get(ch, 0) + 1
        while len(counts) > k:
            counts[text[left]] -= 1
            if counts[text[left]] == 0:
                del counts[text[left]]
            left += 1
        best = max(best, right - left + 1)
    return best

print(longest_at_most_k("aabbcc", 2))   # 4
```

"Longest run of equal items" is a window problem. The sum-10 question with negatives is not, because removing an item from the left can increase the sum, so you cannot decide when to shrink. Lesson 2.1.5 shows a better tool.

## Recap

- A sliding window answers questions about contiguous stretches in O(n) by updating, not recomputing.
- A **fixed** window adds the new item and removes the old one. A **dynamic** window grows on the right and shrinks on the left to keep a rule true.
- State can be a running sum, a set, or a dictionary of counts. The invariant says what is always true inside the window.
- Each pointer only moves forward, so even a `while` inside a `for` stays linear.
- Plain windows need data where shrinking has a predictable effect, such as positive numbers.
