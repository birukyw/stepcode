# Converging & Parallel Two Pointers

Many "check every pair" problems look like they need two nested loops. A surprising number of them do not. If the data has a useful structure, such as being sorted, you can walk **two pointers** through it in a single pass and get the answer in O(n). This is one of the most reusable patterns in all of programming.

## The problem: two numbers that add to a target

You are given a **sorted** list and a target. Find two numbers that add up to it.

The obvious solution checks every pair:

```python
def two_sum_brute(nums, target):
    steps = 0
    for i in range(len(nums)):
        for j in range(i + 1, len(nums)):
            steps += 1
            if nums[i] + nums[j] == target:
                return (i, j), steps
    return None, steps

nums = [1, 3, 4, 6, 8, 11, 15, 19, 23, 30]
print(two_sum_brute(nums, 34))
```

```text
((2, 9), 24)
```

It works, and it needs up to n²/2 checks. For a million numbers that is hundreds of billions of steps.

## Converging pointers

Put one pointer, `left`, at the start and one, `right`, at the end. Look at their sum.

- If the sum is **too small**, the only way to increase it is to move `left` right, to a bigger number.
- If the sum is **too big**, the only way to decrease it is to move `right` left.
- If it matches, you are done.

```python
def two_sum_sorted(nums, target):
    left, right = 0, len(nums) - 1
    steps = 0
    while left < right:
        steps += 1
        total = nums[left] + nums[right]
        if total == target:
            return (left, right), steps
        if total < target:
            left += 1
        else:
            right -= 1
    return None, steps

nums = [1, 3, 4, 6, 8, 11, 15, 19, 23, 30]
print(two_sum_sorted(nums, 34))
print(two_sum_sorted(nums, 100))
```

```text
((2, 9), 3)
(None, 9)
```

Three steps instead of 24. Each iteration moves a pointer by at least one place and neither ever moves back, so the loop runs at most `n - 1` times: **O(n)**.

## Why it is correct

The reasoning is what makes this a technique and not a trick. Suppose the answer is the pair `(i, j)`.

The pointers start outside `i` and `j`. Could a pointer ever jump past one of them? If `left` is at `i` and `right` is beyond `j`, the sum is too big, so `right` moves in. If `right` is at `j` and `left` is before `i`, the sum is too small, so `left` moves in. The pointers can never skip over a valid answer.

That claim, "the answer always stays between the pointers", is called an **invariant**, and checking one is how you prove a two-pointer algorithm works.

## Reversing in place

Pointers also meet in the middle to **swap** from both ends, which reverses a list without making a copy:

```python
def reverse_in_place(items):
    left, right = 0, len(items) - 1
    while left < right:
        items[left], items[right] = items[right], items[left]
        left += 1
        right -= 1

letters = ["a", "b", "c", "d", "e"]
reverse_in_place(letters)
print(letters)
```

```text
['e', 'd', 'c', 'b', 'a']
```

It uses O(1) extra space, where `items[::-1]` would build a whole new list.

## Palindromes

The same idea checks whether text reads the same in both directions, skipping anything that is not a letter:

```python
def is_palindrome(text):
    left, right = 0, len(text) - 1
    while left < right:
        if not text[left].isalnum():
            left += 1
        elif not text[right].isalnum():
            right -= 1
        elif text[left].lower() != text[right].lower():
            return False
        else:
            left += 1
            right -= 1
    return True

print(is_palindrome("A man, a plan, a canal: Panama"))
print(is_palindrome("race a car"))
```

```text
True
False
```

## Parallel pointers: merging two sorted lists

The second flavour uses two pointers on **different** sequences, both moving forward. Merging two sorted lists into one sorted list:

```python
def merge(a, b):
    i, j = 0, 0
    result = []
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:
            result.append(a[i])
            i += 1
        else:
            result.append(b[j])
            j += 1
    result.extend(a[i:])
    result.extend(b[j:])
    return result

print(merge([1, 4, 9], [2, 3, 10, 11]))
```

```text
[1, 2, 3, 4, 9, 10, 11]
```

At every step the smaller of the two front items is the next item overall, so you take it and advance that pointer. When one list runs out, the rest of the other is already in order. This is exactly the merge step of merge sort, which you will meet in module 2.3.

## In-place filtering: the read and write pointers

A third flavour uses a **fast** pointer that reads and a **slow** pointer that writes. Removing duplicates from a sorted list in place:

```python
def remove_duplicates(nums):
    if not nums:
        return 0
    write = 1
    for read in range(1, len(nums)):
        if nums[read] != nums[write - 1]:
            nums[write] = nums[read]
            write += 1
    return write

data = [1, 1, 2, 2, 2, 3, 4, 4]
k = remove_duplicates(data)
print(k, data[:k])
```

```text
4 [1, 2, 3, 4]
```

The read pointer scans every item, and the write pointer only advances when a new value turns up. One pass, no extra list.

## When to reach for two pointers

Look for these signs:

- The data is **sorted**, or can be sorted cheaply.
- You are looking for a **pair** or a **triple**.
- You need to work from **both ends** towards the middle.
- You want to modify a list **in place** without copying.

If the data is not sorted and you cannot sort it, a dictionary or set is usually the better tool.

## Common mistakes

- **Forgetting the data must be sorted** for the converging sum technique.
- **Using `left <= right`** when the pointers must be distinct. `left < right` avoids using one element twice.
- **Moving the wrong pointer.** Work out which direction changes the sum.
- **Off-by-one on the slices at the end of `merge`.** `a[i:]` is correct, `a[i+1:]` loses an item.

def squares_sorted(nums):
    left, right = 0, len(nums) - 1
    result = [0] * len(nums)
    for pos in range(len(nums) - 1, -1, -1):
        if abs(nums[left]) > abs(nums[right]):

            left += 1
        else:
            result[pos] = nums[right] ** 2
            right -= 1
    return result

    left, right = 0, len(nums) - 1
    while left < right:
        if nums[left] % 2 == 0:
            left += 1
        elif nums[right] % 2 == 1:
            right -= 1
        else:

## Recap

- Two pointers replace a nested loop with a single pass, turning O(n²) into O(n).
- **Converging**: start at both ends of sorted data and move inward, deciding which pointer moves by comparing.
- **Parallel**: one pointer per sequence, as in merging. **Read/write**: filter or deduplicate in place.
- Justify the technique with an invariant: the answer always stays between the pointers.
- Use it for sorted data, pairs, and in-place work. Otherwise reach for a set or dictionary.
