# Prefix Sums & Difference Arrays

Suppose you have a million daily sales figures and a thousand questions of the form "what were the total sales between day 400 and day 900?" Adding up each range from scratch takes up to a million steps per question. With one cleverly prepared list, each question takes **one subtraction**. That list is a prefix sum, and it is one of the most useful tricks in the whole course.

## Prefix sums

A **prefix sum** list stores, at each position, the running total of everything before it. Index `i` holds the sum of the first `i` items, so it starts with `0`.

```python
nums = [3, 1, 4, 1, 5, 9, 2, 6]

prefix = [0]
for x in nums:
    prefix.append(prefix[-1] + x)

print(prefix)
```

```text
[0, 3, 4, 8, 9, 14, 23, 25, 31]
```

Building it takes one pass: O(n). The standard library has a function for it, `itertools.accumulate`:

```python
from itertools import accumulate

nums = [3, 1, 4, 1, 5, 9, 2, 6]
prefix = [0] + list(accumulate(nums))
print(prefix)
```

```text
[0, 3, 4, 8, 9, 14, 23, 25, 31]
```

## Range sums in O(1)

The sum of `nums[i:j]` (from `i` up to but not including `j`) is the total up to `j` minus the total up to `i`:

```python
nums = [3, 1, 4, 1, 5, 9, 2, 6]
prefix = [0]
for x in nums:
    prefix.append(prefix[-1] + x)

def range_sum(i, j):
    return prefix[j] - prefix[i]

print(range_sum(0, 8))
print(range_sum(2, 5))
print(range_sum(3, 4))
```

```text
31
10
1
```

`range_sum(2, 5)` is `4 + 1 + 5 = 10`. Preparation costs O(n) once, and then every query is O(1). For a thousand queries on a million numbers, that is about a million steps in total instead of a billion.

> **Tip:** The leading `0` is not decoration. It makes the formula `prefix[j] - prefix[i]` work even when `i` is 0, without a special case.

## Counting subarrays with a target sum

Here is where prefix sums become powerful. How many contiguous subarrays add up to `k`?

A subarray from `i` to `j` has sum `k` exactly when `prefix[j] - prefix[i] == k`, which means `prefix[i] == prefix[j] - k`. So as you scan, you only need to know **how many earlier prefix values equal `current - k`**. A dictionary of counts answers that in O(1):

```python
def count_subarrays(nums, k):
    counts = {0: 1}        # the empty prefix
    total = 0
    result = 0
    for x in nums:
        total += x
        result += counts.get(total - k, 0)
        counts[total] = counts.get(total, 0) + 1
    return result

print(count_subarrays([1, 2, 3], 3))
print(count_subarrays([1, 1, 1], 2))
print(count_subarrays([3, 4, -3, 2, 1], 3))
```

```text
2
2
3
```

For `[1, 2, 3]` and `k = 3` the subarrays are `[1, 2]` and `[3]`. The whole thing runs in **O(n)**, and unlike the sliding window from lesson 2.1.4 it works with **negative numbers** too.

The brute-force alternative checks every pair of positions:

```python
def count_subarrays_slow(nums, k):
    result = 0
    for i in range(len(nums)):
        total = 0
        for j in range(i, len(nums)):
            total += nums[j]
            if total == k:
                result += 1
    return result

print(count_subarrays_slow([3, 4, -3, 2, 1], 3))
```

```text
3
```

Same answer, O(n²).

## The difference array: the reverse trick

Prefix sums answer many range **queries**. The **difference array** answers many range **updates**.

Suppose you must add `+5` to every day from day 2 through day 4, and `+3` to days 3 through 6, and many more ranges like that, and only at the end read the final values. Applying each range one item at a time is O(length) per update.

Instead, record only the **boundaries**: add the amount where the range starts, and subtract it just after the range ends. Then a single prefix sum at the end turns those boundary marks into the final values.

```python
from itertools import accumulate

def apply_updates(n, updates):
    diff = [0] * (n + 1)
    for start, end, amount in updates:      # inclusive range
        diff[start] += amount
        diff[end + 1] -= amount
    return list(accumulate(diff))[:n]

print(apply_updates(8, [(2, 4, 5), (3, 6, 3)]))
```

```text
[0, 0, 5, 8, 8, 3, 3, 0]
```

Each update costs O(1), no matter how long the range is. One final pass recovers every value in O(n). Look at day 3: it received `+5` from the first update and `+3` from the second, and indeed shows `8`.

## Why it works

A difference array is the **inverse** of a prefix sum. The prefix sum adds things up, and the difference array holds the changes between neighbours. If you start with `diff = [0, 0, 5, 0, 0, -5, ...]`, summing from the left gives `5` that begins at index 2 and cancels at index 5, which is exactly "add 5 to the range 2 to 4".

```python
from itertools import accumulate

values = [0, 0, 5, 8, 8, 3, 3, 0]
diff = [values[0]] + [values[i] - values[i - 1] for i in range(1, len(values))]
print(diff)
print(list(accumulate(diff)))
```

```text
[0, 0, 5, 3, 0, -5, 0, -3]
[0, 0, 5, 8, 8, 3, 3, 0]
```

Going from values to differences and back again returns the original, so the two are exact opposites. (The square brackets inside that first list build it with a **list comprehension**, a compact loop covered in Track 3.)

## Two-dimensional prefix sums

The same idea extends to grids. A 2D prefix table lets you sum any rectangle in O(1) after O(rows × cols) preparation, by adding two overlapping rectangles and subtracting what they share. It is how image software computes things like blur and average brightness quickly.

## Choosing the right tool

| Problem | Tool |
|---|---|
| many range sum queries, data fixed | prefix sum |
| many range updates, read at the end | difference array |
| count subarrays with a target sum, negatives allowed | prefix sums plus a dictionary |
| longest or shortest stretch, positive numbers | sliding window |

## Common mistakes

- **Forgetting the leading 0** in the prefix list, which causes off-by-one errors.
- **Mixing up inclusive and exclusive ends.** Decide once whether `range_sum(i, j)` includes `j`.
- **Forgetting the extra slot** in the difference array. It needs `n + 1` entries, so that `end + 1` is always valid.
- **Using a difference array when you need values between updates.** It only gives you the result at the end.
- **Forgetting `{0: 1}`** in the subarray counter, which misses subarrays that start at the beginning.

## Recap

- A prefix sum list (with a leading 0) answers any range-sum query as `prefix[j] - prefix[i]` in O(1), after O(n) preparation.
- Combined with a dictionary of counts, prefix sums count subarrays with a target sum in O(n), even with negative numbers.
- A difference array records `+amount` at a range start and `-amount` just after the end, so many range updates cost O(1) each.
- One `accumulate` at the end turns the differences into the final values. The two ideas are exact inverses.
