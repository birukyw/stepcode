# First-Class Functions & Lambdas

In many languages a function is a special thing that you can only call. In Python a function is **just a value**, like a number or a string. You can store it in a variable, put it in a list, pass it to another function, and return it from one. That single idea unlocks a style of programming where behaviour itself is data, and it is the foundation of decorators, callbacks, sorting keys and most frameworks you will meet.

## Functions are objects

```python
def shout(text):
    """Return the text in capitals."""
    return text.upper() + "!"

print(type(shout).__name__)
print(shout.__name__, shout.__doc__)

louder = shout                    # a second name for the same function
print(louder("hello"))
print(louder is shout)
print(callable(shout), callable(42))
```

```text
function
shout Return the text in capitals.
HELLO!
True
True False
```

A function has a type (`function`), a name, a docstring and attributes, exactly like any other object. Assigning `louder = shout` does **not** call it: no parentheses means "the function itself". With parentheses it means "run it now".

## Passing functions as arguments

A function that takes another function is called a **higher-order function**. The function you hand it is often called a **callback**:

```python
def apply_twice(func, value):
    return func(func(value))

def add_three(n):
    return n + 3

print(apply_twice(add_three, 10))
print(apply_twice(str.upper, "ab"))
print(apply_twice(lambda s: s + "!", "hi"))
```

```text
16
AB
hi!!
```

You have already used this idea. The `key=` argument of `sorted`, `min` and `max` is a function you pass in:

```python
words = ["pear", "Fig", "banana", "kiwi"]
print(sorted(words))
print(sorted(words, key=str.lower))
print(sorted(words, key=len))
print(max(words, key=len))
```

```text
['Fig', 'banana', 'kiwi', 'pear']
['banana', 'Fig', 'kiwi', 'pear']
['Fig', 'pear', 'kiwi', 'banana']
banana
```

`sorted` does not know how to compare by length. You **tell it how** by giving it a function. That is what makes it reusable.

## Lambda: a tiny anonymous function

`lambda args: expression` creates a small function without a name. It is limited to a **single expression** (no statements, no assignments), which keeps it tiny:

```python
double = lambda n: n * 2          # fine for a demo, but a def is clearer when you name it
print(double(21))

pairs = [(1, "one"), (3, "three"), (2, "two")]
print(sorted(pairs, key=lambda p: p[1]))
print(list(map(lambda n: n ** 2, [1, 2, 3, 4])))
print(list(filter(lambda n: n % 2 == 0, [1, 2, 3, 4, 5, 6])))
```

```text
42
[(1, 'one'), (3, 'three'), (2, 'two')]
[1, 4, 9, 16]
[2, 4, 6]
```

Rule of thumb: use a `lambda` for a throwaway function passed straight into another call. If you give it a name (`double = lambda ...`), write a normal `def` instead, because it gets a proper name in error messages and can have a docstring.

## Dispatch tables: functions in a dictionary

A chain of `if`/`elif` that picks an action can become a **dictionary of functions**. Adding an action is just adding an entry:

```python
def add(a, b): return a + b
def sub(a, b): return a - b
def mul(a, b): return a * b
def div(a, b): return a / b

OPERATIONS = {"+": add, "-": sub, "*": mul, "/": div}

def calculate(a, op, b):
    try:
        func = OPERATIONS[op]
    except KeyError:
        return f"unknown operator {op!r}"
    return func(a, b)

print(calculate(6, "*", 7))
print(calculate(1, "/", 4))
print(calculate(1, "^", 2))
```

```text
42
0.25
unknown operator '^'
```

This is how command parsers, menu systems and web frameworks route requests: **look up the function by name, then call it**.

## Functions that return functions

A function can build and return a new function. This is a **function factory**:

```python
def make_multiplier(factor):
    def multiply(n):
        return n * factor
    return multiply

triple = make_multiplier(3)
tenfold = make_multiplier(10)
print(triple(7), tenfold(7))
print(make_multiplier(2)(50))
```

```text
21 70
100
```

`triple` remembers that `factor` was 3, even though `make_multiplier` finished long ago. That memory is called a **closure**, and lesson 3.1.5 explores it fully.

## map, filter and reduce

These three classic tools apply a function across data. `map` transforms, `filter` selects, and `reduce` folds many values into one:

```python
from functools import reduce

nums = [1, 2, 3, 4, 5]
print(list(map(lambda n: n * n, nums)))
print(list(filter(lambda n: n > 2, nums)))
print(reduce(lambda total, n: total + n, nums))
print(reduce(lambda total, n: total * n, nums, 1))
print(reduce(max, [3, 9, 2, 7]))
```

```text
[1, 4, 9, 16, 25]
[3, 4, 5]
15
120
9
```

`reduce(func, items, start)` calls `func(running_total, next_item)` repeatedly. The optional third argument is the starting value, which also makes an empty list safe. In everyday Python, comprehensions and `sum`/`max` are usually clearer than `map` and `filter`, and `reduce` is best kept for genuinely custom folds.

## functools.partial: pre-fill some arguments

`partial` creates a new function with some arguments already fixed:

```python
from functools import partial

def power(base, exponent):
    return base ** exponent

square = partial(power, exponent=2)
cube = partial(power, exponent=3)
print(square(9), cube(3))

int_from_binary = partial(int, base=2)
print(int_from_binary("1011"))
print(list(map(partial(power, 2), [1, 2, 3, 4])))
```

```text
81 27
11
[2, 4, 8, 16]
```

The last line pre-fills `base=2`, so `map` supplies the exponent for each item. `partial` is the clean replacement for a lambda that merely forwards arguments.

## The operator module: functions for operators

Instead of `lambda a, b: a + b` or `lambda p: p[1]`, the `operator` module offers ready-made, faster functions:

```python
from operator import add, mul, itemgetter, attrgetter, methodcaller
from functools import reduce

print(reduce(mul, [1, 2, 3, 4]))
print(add(2, 3))

people = [("ada", 36), ("linus", 28), ("grace", 45)]
print(sorted(people, key=itemgetter(1)))
print(max(people, key=itemgetter(1)))

rows = [{"n": "b", "v": 2}, {"n": "a", "v": 2}, {"n": "c", "v": 1}]
print(sorted(rows, key=itemgetter("v", "n")))

class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y

pts = [Point(3, 1), Point(1, 2), Point(2, 0)]
print([p.x for p in sorted(pts, key=attrgetter("x"))])
print(list(map(methodcaller("upper"), ["a", "b"])))
```

```text
24
5
[('linus', 28), ('ada', 36), ('grace', 45)]
('grace', 45)
[{'n': 'c', 'v': 1}, {'n': 'a', 'v': 2}, {'n': 'b', 'v': 2}]
[1, 2, 3]
['A', 'B']
```

`itemgetter("v", "n")` returns a tuple, so it sorts by several fields at once. Because it is implemented in C, it is also quicker than the equivalent lambda.

## Composing functions

If functions are values, you can combine them. `compose` builds a new function that runs several in order:

```python
from functools import reduce

def compose(*funcs):
    def pipeline(value):
        return reduce(lambda acc, f: f(acc), funcs, value)
    return pipeline

clean = compose(str.strip, str.lower, lambda s: s.replace(" ", "-"))
print(clean("  Hello Big World  "))

add_one = lambda n: n + 1
double = lambda n: n * 2
print(compose(add_one, double)(5), compose(double, add_one)(5))
```

```text
hello-big-world
12 11
```

Order matters: `compose(add_one, double)(5)` is `(5 + 1) * 2 = 12`, while the other order gives `5 * 2 + 1 = 11`. This is the declarative pipeline of lesson 3.1.1, assembled out of functions.

## A trap: lambdas in loops

Functions made in a loop do **not** capture the loop variable's current value. They all share the variable itself:

```python
adders = [lambda n: n + i for i in range(3)]
print([f(10) for f in adders])

fixed = [lambda n, i=i: n + i for i in range(3)]
print([f(10) for f in fixed])
```

```text
[12, 12, 12]
[10, 11, 12]
```

By the time you call the first version, the loop has finished and `i` is 2 for all three. The fix `i=i` freezes the **current** value as a default. Lesson 3.1.5 explains why in detail.

## Common mistakes

- **Calling instead of passing.** `sorted(words, key=len())` fails. Write `key=len`, with no parentheses.
- **Complicated lambdas.** If it needs a second line, use a `def`.
- **Forgetting that `map` and `filter` return lazy objects.** Wrap with `list(...)` to see the results.
- **Late binding in loops.** Capture with a default argument or `partial`.
- **Using `reduce` for everything.** `sum`, `max`, `any` and `all` are clearer.

## Recap

- In Python a function is an **object**: assign it, store it, pass it to other functions and return it. Parentheses call it, no parentheses refer to it.
- A **higher-order function** takes or returns functions. The `key=` argument of `sorted`/`min`/`max` is the everyday example.
- `lambda` makes a one-expression anonymous function, and is best for throwaway callbacks.
- A **dispatch table** (dictionary of functions) replaces long `if`/`elif` chains.
- `map`/`filter`/`reduce` apply a function across data. `functools.partial` fixes some arguments. `operator.itemgetter`/`attrgetter`/`methodcaller` replace simple lambdas.
- **Function factories** return new functions that remember their inputs, which is the closure idea of lesson 3.1.5. Beware late binding when making lambdas in a loop.
