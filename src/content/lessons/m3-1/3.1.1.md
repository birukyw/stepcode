# Declarative Data Pipelines

In module 1.7 you met comprehensions as a shortcut for loops. This lesson is about the bigger idea underneath: writing code that says **what** you want, not **how** to step through it. Real programs spend most of their time moving data through stages: read it, clean it, filter it, reshape it, summarise it. When you write those stages as a **pipeline**, programs get shorter, easier to test, and much harder to get wrong.

## Imperative or declarative?

**Imperative** code tells the computer each step: make a list, loop, test, append, repeat. **Declarative** code describes the result: "the names of customers who spent over 100".

```python
orders = [
    {"id": 1, "customer": "ada", "total": 120.0, "status": "paid"},
    {"id": 2, "customer": "linus", "total": 35.5, "status": "paid"},
    {"id": 3, "customer": "ada", "total": 80.0, "status": "refunded"},
    {"id": 4, "customer": "grace", "total": 230.0, "status": "paid"},
    {"id": 5, "customer": "linus", "total": 99.0, "status": "pending"},
]

# imperative: the how
big_spenders = []
for order in orders:
    if order["status"] == "paid" and order["total"] > 100:
        if order["customer"] not in big_spenders:
            big_spenders.append(order["customer"])

# declarative: the what
declared = sorted({o["customer"] for o in orders if o["status"] == "paid" and o["total"] > 100})

print(big_spenders)
print(declared)
```

```text
['ada', 'grace']
['ada', 'grace']
```

Both give the same answer. The second reads like the requirement itself, and it cannot forget to initialise a list or append in the wrong place.

## The three-stage pattern

Almost every data question has the same shape: **filter** (which rows?), **transform** (what do I want from each?), **aggregate** (combine them). Spot the stages and the code writes itself:

```python
orders = [
    {"id": 1, "customer": "ada", "total": 120.0, "status": "paid"},
    {"id": 2, "customer": "linus", "total": 35.5, "status": "paid"},
    {"id": 3, "customer": "ada", "total": 80.0, "status": "refunded"},
    {"id": 4, "customer": "grace", "total": 230.0, "status": "paid"},
    {"id": 5, "customer": "linus", "total": 99.0, "status": "pending"},
]

paid = [o for o in orders if o["status"] == "paid"]          # filter
amounts = [o["total"] for o in paid]                          # transform
revenue = sum(amounts)                                        # aggregate
print(revenue, round(revenue / len(amounts), 2))

# the same pipeline in one line, with a generator so no intermediate lists exist
print(sum(o["total"] for o in orders if o["status"] == "paid"))
```

```text
385.5 128.5
385.5
```

Notice the generator expression inside `sum(...)`: no square brackets, so no temporary list. Lesson 3.1.3 explains why that matters when the data is large.

## Grouping: one pass, many buckets

"Revenue per customer" is a **group by**. A `defaultdict` keeps the loop to two lines:

```python
from collections import defaultdict

orders = [
    {"customer": "ada", "total": 120.0}, {"customer": "linus", "total": 35.5},
    {"customer": "ada", "total": 80.0}, {"customer": "grace", "total": 230.0},
    {"customer": "linus", "total": 99.0},
]

per_customer = defaultdict(float)
for o in orders:
    per_customer[o["customer"]] += o["total"]

print(dict(per_customer))
print(max(per_customer, key=per_customer.get))
print(sorted(per_customer.items(), key=lambda kv: kv[1], reverse=True)[:2])
```

```text
{'ada': 200.0, 'linus': 134.5, 'grace': 230.0}
grace
[('grace', 230.0), ('ada', 200.0)]
```

`max(..., key=...)` returns the **key** with the biggest value. `sorted(..., key=..., reverse=True)` ranks everything. Pair this with slicing for "top 2".

## Counting with Counter

When the aggregate is "how many", `Counter` is the declarative tool:

```python
from collections import Counter

words = "the cat and the hat and the bat sat".split()
counts = Counter(words)
print(counts.most_common(2))
print(counts["the"], counts["dog"])
print(Counter(len(w) for w in words))
```

```text
[('the', 3), ('and', 2)]
3 0
Counter({3: 9})
```

A `Counter` counts anything hashable, including the result of a computation like `len(w)`. Counters even support arithmetic: `Counter(a) + Counter(b)` adds counts.

## Reshaping data

**Flatten** nested lists, **transpose** a table, and **invert** a mapping are three reshapes you will do constantly:

```python
nested = [[1, 2], [3], [4, 5, 6]]
flat = [x for row in nested for x in row]
print(flat)

table = [[1, 2, 3], [4, 5, 6]]
columns = [list(col) for col in zip(*table)]
print(columns)

ages = {"ada": 36, "linus": 28, "grace": 36}
by_age = {}
for name, age in ages.items():
    by_age.setdefault(age, []).append(name)
print(by_age)
```

```text
[1, 2, 3, 4, 5, 6]
[[1, 4], [2, 5], [3, 6]]
{36: ['ada', 'grace'], 28: ['linus']}
```

`zip(*table)` unpacks the rows as separate arguments to `zip`, which then pairs up the first items, the second items and so on. That is a transpose in one expression.

## Sorting by more than one thing

A tuple key sorts by the first item, and uses the second only to break ties. Negating a number reverses just that part:

```python
players = [("ada", 90), ("linus", 75), ("grace", 90), ("guido", 75)]
ranked = sorted(players, key=lambda p: (-p[1], p[0]))
print(ranked)

words = ["banana", "fig", "apple", "kiwi", "cherry", "date"]
print(sorted(words, key=lambda w: (len(w), w)))
```

```text
[('ada', 90), ('grace', 90), ('guido', 75), ('linus', 75)]
['fig', 'date', 'kiwi', 'apple', 'banana', 'cherry']
```

The first result is "highest score first, then by name". The second is "shortest word first, then alphabetically".

## The walrus operator: compute once, use twice

Sometimes the filter and the transform need the **same expensive value**. The assignment expression `:=` (the "walrus") names it inside the comprehension:

```python
calls = 0

def score(text):
    global calls
    calls += 1
    return len(text) * 2

words = ["pear", "fig", "banana", "kiwi"]

wasteful = [score(w) for w in words if score(w) > 6]
print(wasteful, calls)

calls = 0
efficient = [s for w in words if (s := score(w)) > 6]
print(efficient, calls)
```

```text
[8, 12, 8] 7
[8, 12, 8] 4
```

The first version calls `score` twice for every word that passes. The walrus version computes it **once** per word. Use it sparingly, only when it removes duplicated work.

## Pipelines as small named functions

A long one-liner becomes unreadable. Instead, give each stage a **name** and chain them. Each tiny function is easy to test alone:

```python
def parse(line):
    name, _, score = line.partition(",")
    return name.strip(), score.strip()

def valid(pair):
    name, score = pair
    return bool(name) and score.isdigit()

def to_record(pair):
    name, score = pair
    return {"name": name.title(), "score": int(score)}

raw = ["ada, 90", "linus,75", "oops", ",12", "grace , 88", "bad,x"]
records = [to_record(p) for p in map(parse, raw) if valid(p)]
print(records)
print(sum(r["score"] for r in records) / len(records))
```

```text
[{'name': 'Ada', 'score': 90}, {'name': 'Linus', 'score': 75}, {'name': 'Grace', 'score': 88}]
84.33333333333333
```

Read it top to bottom: parse each line, keep the valid ones, convert them. Each stage can be changed without touching the others. This habit is what "declarative" really buys you.

## Combining dictionaries and sets declaratively

```python
defaults = {"color": "blue", "size": 10, "debug": False}
overrides = {"size": 14, "debug": True}
settings = defaults | overrides              # right side wins
print(settings)

a = {1, 2, 3, 4}
b = {3, 4, 5}
print(a & b, a | b, a - b, a ^ b)

inventory = {"apple": 3, "pear": 0, "fig": 5}
print({name: n for name, n in inventory.items() if n > 0})
```

```text
{'color': 'blue', 'size': 14, 'debug': True}
{3, 4} {1, 2, 3, 4, 5} {1, 2} {1, 2, 5}
{'apple': 3, 'fig': 5}
```

## Common mistakes

- **Cramming everything into one comprehension.** If it needs three conditions and two nested loops, use named functions or a normal loop.
- **Building lists you only sum.** `sum([x for x in data])` wastes memory. Drop the brackets.
- **Forgetting that dictionary comprehensions overwrite duplicate keys.** The last one wins.
- **Sorting by a negated string.** You can negate numbers, not text. For descending text use `reverse=True`.
- **Using `[...]` side effects.** `[print(x) for x in data]` builds a useless list. Use a loop.

from collections import defaultdict

def average_by_group(pairs):
    totals, counts = defaultdict(float), defaultdict(int)
    for group, value in pairs:
        totals[group] += value
        counts[group] += 1
    return {g: totals[g] / counts[g] for g in totals}

## Recap

- **Declarative** code states the result you want. A data question is usually **filter, transform, aggregate**.
- `defaultdict` groups in one pass, `Counter` counts anything, and `max`/`min`/`sorted` with a `key` rank things.
- Reshape with comprehensions: **flatten** with two `for`s, **transpose** with `zip(*rows)`, **invert** a dictionary with a comprehension or `setdefault`.
- Tuple keys sort by several fields, and negating a number reverses just that field.
- The walrus operator `:=` computes a value once for both the filter and the result.
- Break long pipelines into small **named functions** that you can test separately, and use generator expressions (no brackets) when you only need a total.
