# Closures & Function Decorators

Since functions are objects (lesson 3.1.2), one function can be written **inside** another, and the inner one can **remember** the outer one's variables long after the outer one has finished. That memory is a **closure**. Add the `@` syntax and you get **decorators**: a way to wrap extra behaviour, such as timing, caching, logging or retrying, around any function without touching its code. Decorators run through almost every serious Python framework, so this lesson is worth taking slowly.

## Closures: functions that remember

```python
def make_greeter(greeting):
    def greet(name):
        return greeting + ", " + name + "!"
    return greet

hello = make_greeter("Hello")
hey = make_greeter("Hey")
print(hello("Ada"))
print(hey("Linus"))
```

```text
Hello, Ada!
Hey, Linus!
```

`make_greeter` returned `greet` and finished. Normally its local variable `greeting` would vanish. But `greet` **uses** `greeting`, so Python keeps that variable alive, attached to the inner function. Each call to `make_greeter` creates a new, separate set of remembered variables, so `hello` and `hey` do not interfere.

You can peek inside:

```python
def make_greeter(greeting):
    def greet(name):
        return greeting + ", " + name + "!"
    return greet

hello = make_greeter("Hello")
print(hello.__closure__[0].cell_contents)
print(hello.__code__.co_freevars)
```

```text
Hello
('greeting',)
```

A variable that an inner function uses from an enclosing function is called a **free variable**. The set of them, stored with the function, is the **closure**.

## Closures with changing state: nonlocal

A closure can read what it remembers. To **change** it, declare it `nonlocal`; otherwise Python assumes you are creating a new local variable:

```python
def make_counter(start=0):
    count = start
    def increment(step=1):
        nonlocal count
        count += step
        return count
    return increment

a = make_counter()
b = make_counter(100)
print(a(), a(), a(5))
print(b(), b())
```

```text
1 2 7
101 102
```

`a` and `b` each carry their own `count`. This is a lightweight alternative to a class when all you need is one piece of private state and one action. Without `nonlocal count`, the line `count += step` would raise an `UnboundLocalError`, because Python would treat `count` as a brand-new local.

```python
def broken_counter():
    count = 0
    def increment():
        count += 1
        return count
    return increment

c = broken_counter()
try:
    c()
except UnboundLocalError as err:
    print("UnboundLocalError")
```

```text
UnboundLocalError
```

## The classic trap: late binding

A closure remembers the **variable**, not its value at the time. If the variable changes later, the closure sees the new value:

```python
def make_all():
    funcs = []
    for i in range(3):
        funcs.append(lambda: i)
    return funcs

print([f() for f in make_all()])

def make_all_fixed():
    funcs = []
    for i in range(3):
        funcs.append(lambda i=i: i)       # i=i captures the CURRENT value
    return funcs

print([f() for f in make_all_fixed()])
```

```text
[2, 2, 2]
[0, 1, 2]
```

All three lambdas share one `i`, and by the time they are called the loop has left it at 2. Giving the lambda a **default argument** `i=i` evaluates `i` once, at creation time. You can also fix it with `functools.partial` or by making a separate function that takes `i` as a parameter.

## From closures to decorators

Suppose you want to log every call to a function. Without touching the function's code, you could wrap it:

```python
def add(a, b):
    return a + b

def logged(func):
    def wrapper(*args, **kwargs):
        print("calling", func.__name__, args, kwargs)
        result = func(*args, **kwargs)
        print("returned", result)
        return result
    return wrapper

add = logged(add)           # replace add with the wrapped version
print(add(2, 3))
```

```text
calling add (2, 3) {}
returned 5
5
```

`logged` takes a function and returns a new function that calls the old one with extra behaviour around it. Because `wrapper` uses `func`, that is a closure. The wrapper accepts `*args, **kwargs` so it works for **any** signature, and it **returns** the original result.

Python gives that "wrap and replace" pattern a clean syntax. This is **exactly** equivalent to the code above:

```python
def logged(func):
    def wrapper(*args, **kwargs):
        print("calling", func.__name__)
        return func(*args, **kwargs)
    return wrapper

@logged
def add(a, b):
    return a + b

print(add(2, 3))
```

```text
calling add
5
```

`@logged` above `def add` means `add = logged(add)`, applied the moment the function is defined. That is all a decorator is.

## Keeping the identity: functools.wraps

There is a side effect. The wrapped function lost its name and docstring:

```python
def logged(func):
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

@logged
def add(a, b):
    """Add two numbers."""
    return a + b

print(add.__name__, add.__doc__)
```

```text
wrapper None
```

The name is now `wrapper`, which confuses debuggers and documentation. `functools.wraps` copies the original's metadata across. **Always use it in a decorator:**

```python
from functools import wraps

def logged(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

@logged
def add(a, b):
    """Add two numbers."""
    return a + b

print(add.__name__, add.__doc__)
print(add.__wrapped__(2, 3))
```

```text
add Add two numbers.
5
```

`wraps` also stores the original as `__wrapped__`, which is handy for testing.

## A decorator that counts calls

Decorators can keep state, either in a closure or as an attribute on the wrapper:

```python
from functools import wraps

def count_calls(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        wrapper.calls += 1
        return func(*args, **kwargs)
    wrapper.calls = 0
    return wrapper

@count_calls
def greet(name):
    return "hi " + name

greet("a"); greet("b"); greet("c")
print(greet.calls)
```

```text
3
```

Functions are objects, so `wrapper.calls = 0` simply sets an attribute on it.

## A decorator that caches: memoization

Remember lesson 2.6.3? Memoization stores results so repeated calls are free. As a decorator it is reusable on any pure function:

```python
from functools import wraps

def memoize(func):
    cache = {}
    @wraps(func)
    def wrapper(*args):
        if args not in cache:
            cache[args] = func(*args)
        return cache[args]
    wrapper.cache = cache
    return wrapper

calls = 0

@memoize
def slow_square(n):
    global calls
    calls += 1
    return n * n

print(slow_square(9), slow_square(9), slow_square(9))
print(calls)

@memoize
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)

print(fib(80))
```

```text
81 81 81
1
23416728348467685
```

`calls` is 1: the body ran once and the other two calls came from the cache. The dictionary `cache` lives in the closure, private to this one decorated function. The standard library has a polished version, `functools.cache` (and `lru_cache`), which you should use in real code.

## Timing a function

```python
import time
from functools import wraps

def timed(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        try:
            return func(*args, **kwargs)
        finally:
            wrapper.last_seconds = time.perf_counter() - start
    wrapper.last_seconds = None
    return wrapper

@timed
def busy():
    return sum(range(200_000))

busy()
print(busy.last_seconds is not None and busy.last_seconds >= 0)
```

```text
True
```

The `try`/`finally` records the time even if the function raises an error.

## Decorators with arguments

What if you want `@retry(3)`? Now the thing after `@` is a **call** that must return a decorator. That makes **three layers**: the outer function takes your settings, the middle one takes the function, the inner one is the wrapper:

```python
from functools import wraps

def repeat(times):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            result = None
            for _ in range(times):
                result = func(*args, **kwargs)
            return result
        return wrapper
    return decorator

@repeat(3)
def say(text):
    print(text)

say("hi")
```

```text
hi
hi
hi
```

`@repeat(3)` first calls `repeat(3)`, which returns `decorator`, and then applies `decorator` to `say`. A realistic one is a retry:

```python
from functools import wraps

def retry(times, exceptions=(Exception,)):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            last = None
            for attempt in range(1, times + 1):
                try:
                    return func(*args, **kwargs)
                except exceptions as err:
                    last = err
            raise last
        return wrapper
    return decorator

attempts = {"n": 0}

@retry(3, exceptions=(ConnectionError,))
def flaky():
    attempts["n"] += 1
    if attempts["n"] < 3:
        raise ConnectionError("down")
    return "connected"

print(flaky(), attempts["n"])

@retry(2)
def always_fails():
    raise ValueError("nope")

try:
    always_fails()
except ValueError as err:
    print("gave up:", err)
```

```text
connected 3
gave up: nope
```

## Stacking decorators

Several decorators can be stacked. They apply from the **bottom up** (the one nearest the function wraps first):

```python
from functools import wraps

def tag(name):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            return "<" + name + ">" + func(*args, **kwargs) + "</" + name + ">"
        return wrapper
    return decorator

@tag("b")
@tag("i")
def text():
    return "hello"

print(text())
```

```text
<b><i>hello</i></b>
```

`@tag("i")` wraps `text` first, and `@tag("b")` wraps that result. So the outer tag is the top decorator.

## Decorating methods and a class decorator

Because the wrapper accepts `*args`, it works on methods too (the first argument is `self`):

```python
from functools import wraps

def log_call(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        print("->", func.__name__)
        return func(*args, **kwargs)
    return wrapper

class Account:
    def __init__(self):
        self.balance = 0

    @log_call
    def deposit(self, amount):
        self.balance += amount
        return self.balance

acct = Account()
print(acct.deposit(50))
```

```text
-> deposit
50
```

## When to reach for a decorator

Decorators are for **cross-cutting concerns**: behaviour that applies to many functions but is not part of what they do. Timing, caching, retrying, logging, permission checks, registering a function in a table. If it is specific to one function, just write it inside.

## Common mistakes

- **Forgetting to return the wrapper** from the decorator, which makes the decorated name `None`.
- **Forgetting to return the result** from the wrapper, so the function appears to return `None`.
- **Not using `@wraps`,** which loses the name and docstring.
- **Writing `@retry` without arguments** when it needs them (or `@repeat(3)` without the call). Count the layers.
- **Late binding** when creating closures in a loop. Capture with a default argument.
- **Modifying a closure variable without `nonlocal`.**

## Practice

1. Write `make_accumulator()` that returns a function; each call `acc(n)` adds `n` to a private total and returns it.
2. Write a decorator `shout` that uppercases a function's string result.
3. Write `@validate_positive` that raises `ValueError` if any positional argument is negative.
4. Write `once`, a decorator that runs the function the first time, and returns that same result on every later call.

+++ Solutions
```python
from functools import wraps

def make_accumulator():
    total = 0
    def acc(n):
        nonlocal total
        total += n
        return total
    return acc

acc = make_accumulator()
print(acc(5), acc(10), acc(-3))   # 5 15 12

def shout(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs).upper()
    return wrapper

@shout
def greet(name):
    return "hello " + name

print(greet("ada"))   # HELLO ADA
```

```python
from functools import wraps

def validate_positive(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        if any(a < 0 for a in args):
            raise ValueError("arguments must not be negative")
        return func(*args, **kwargs)
    return wrapper

def once(func):
    done = False
    result = None
    @wraps(func)
    def wrapper(*args, **kwargs):
        nonlocal done, result
        if not done:
            result = func(*args, **kwargs)
            done = True
        return result
    return wrapper

@validate_positive
def area(w, h):
    return w * h

@once
def setup():
    print("setting up")
    return 42

print(area(3, 4))
print(setup(), setup())   # setting up, then 42 42
```
+++

## Recap

- A **closure** is an inner function that remembers variables from its enclosing function, even after the outer one has returned. Each call of the outer function creates a fresh, separate set.
- Use `nonlocal` to **change** a remembered variable. Beware **late binding**: closures capture the variable, not its value, so freeze it with a default argument.
- A **decorator** is a function that takes a function and returns a wrapped replacement. `@deco` above a `def` means `f = deco(f)`.
- The wrapper takes `*args, **kwargs`, calls the original, and **returns its result**. Always add `@functools.wraps(func)`.
- A decorator **with arguments** has three layers: settings, then the function, then the wrapper.
- Decorators stack from the bottom up, and suit cross-cutting jobs such as timing, caching, retrying, logging and registering.
