# Black Boxes & Signatures

Until now every program has been one long script. That works for ten lines and collapses at a hundred. The tool that fixes it is the **function**: a named, reusable piece of code with a clear job. You have been **calling** functions since lesson 1.1.1 (`print`, `len`, `range`). Now you will **define** your own.

## Why functions

Imagine a game that calculates damage in three places:

```python
print("Sword hit:", 12 * 2 + 5)
print("Axe hit:", 15 * 2 + 5)
print("Bow hit:", 9 * 2 + 5)
```

```text
Sword hit: 29
Axe hit: 35
Bow hit: 23
```

The formula `power * 2 + 5` is written three times. If the rule changes, you must find and edit every copy, and missing one creates a bug. Programmers call this a violation of **DRY**: Don't Repeat Yourself. A function lets you write the rule once, give it a name, and reuse it.

## Defining a function

```python
def damage(power):
    return power * 2 + 5

print("Sword hit:", damage(12))
print("Axe hit:", damage(15))
print("Bow hit:", damage(9))
```

```text
Sword hit: 29
Axe hit: 35
Bow hit: 23
```

The pieces:

- `def` starts the definition.
- `damage` is the function's **name**. Follow the same `snake_case` rule as variables.
- `(power)` lists the **parameters**: the inputs the function expects.
- The colon and the indented block form the **body**.
- `return` sends a value back to whoever called the function.

Defining a function does **not** run it. It only stores the instructions under a name. The body runs each time you **call** the function with parentheses.

## Parameters and arguments

These two words are easy to mix up:

- A **parameter** is the name in the definition: `power`.
- An **argument** is the actual value you pass in a call: `12`.

When you call `damage(12)`, Python creates a local variable `power` and attaches it to `12`, then runs the body. It is ordinary assignment: `power = 12`.

Functions can take several parameters. Arguments are matched **by position** unless you name them:

```python
def rectangle_area(width, height):
    return width * height

print(rectangle_area(4, 5))
print(rectangle_area(height=5, width=4))
```

```text
20
20
```

Passing the wrong number of arguments is a clear error:

```python error
def rectangle_area(width, height):
    return width * height

print(rectangle_area(4))
```

```text
Traceback (most recent call last):
  File "main.py", line 4, in <module>
    print(rectangle_area(4))
TypeError: rectangle_area() missing 1 required positional argument: 'height'
```

## The signature is a contract

The first line of a function, its name and parameters, is its **signature**. It tells a caller what to provide. Think of the function as a **black box**: you hand it the inputs, it hands back a result, and you do not need to know how it works inside. That is what lets you use `len()` without reading its source code.

A good function does one job and has a name that says what it is. `calculate_damage` beats `do_stuff`. If you struggle to name a function, it is probably doing too much.

## Docstrings

A string on the first line of the body is a **docstring**. It documents the function, and tools like `help()` display it.

```python
def damage(power):
    """Return the damage for a weapon with the given power."""
    return power * 2 + 5

print(damage.__doc__)
```

```text
Return the damage for a weapon with the given power.
```

Write one sentence saying what the function returns. Future you will be grateful.

## Define before you call

Python runs top to bottom, so a function must be **defined before the line that calls it runs**.

```python error
print(double(4))

def double(n):
    return n * 2
```

```text
Traceback (most recent call last):
  File "main.py", line 1, in <module>
    print(double(4))
NameError: name 'double' is not defined
```

The usual layout is definitions first, then the code that uses them.

## Functions calling functions

Once defined, a function is just another tool, and other functions can use it.

```python
def damage(power):
    return power * 2 + 5

def critical(power):
    return damage(power) * 3

print(critical(10))
```

```text
75
```

Each function stays small, and the pieces combine. This is the heart of **abstraction**: hiding detail behind a name so you can think at a higher level.

## Functions that do not return

A function without a `return` statement still works, but it gives back the special value `None`. Functions like that exist for what they **do**, such as printing, and not for a value.

```python
def greet(name):
    print(f"Hello, {name}")

greet("Ada")
```

```text
Hello, Ada
```

The next lesson is about the difference between printing and returning, which is the most important distinction in this module.

## Common mistakes

- **Forgetting the colon** after the signature.
- **Forgetting to indent the body.**
- **Defining but never calling.** Nothing runs until you call the function with `()`.
- **Calling with the wrong number of arguments.**
- **Calling before defining.**
- **Using one giant function.** If a function needs "and" to describe it, split it.

## Recap

- `def name(parameters):` defines a function, and calling it with `name(arguments)` runs it.
- Parameters are the names in the definition and arguments are the values you pass.
- `return` sends a value back. Without it a function returns `None`.
- Define functions before the code that calls them. Give each one a clear name and one job.
- A docstring documents what a function does.
