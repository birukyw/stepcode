# The Call Stack & LEGB Scope

When you call a function, Python gives it a private workspace. Variables created inside live there and vanish when the function ends. This is **scope**, and it is why functions can use short names like `x` and `total` without colliding. This lesson explains where Python looks for a name, and the call stack that tracks which function is running.

## Local variables

A variable assigned inside a function is **local**: it exists only while that function runs.

```python
def make_total():
    total = 10 + 5
    return total

print(make_total())
```

```text
15
```

Trying to reach it from outside fails:

```python error
def make_total():
    total = 10 + 5
    return total

make_total()
print(total)
```

```text
Traceback (most recent call last):
  File "main.py", line 6, in <module>
    print(total)
NameError: name 'total' is not defined
```

The `total` inside the function and any `total` outside it are **different variables**. Parameters are local too.

## Separate workspaces

```python
def double(n):
    n = n * 2
    return n

n = 5
print(double(n))
print(n)
```

```text
10
5
```

The function's `n` is its own local name. Reassigning it did not touch the outer `n`. Each call gets a fresh set of locals, which is what makes functions safe to reuse.

## Reading outer variables

A function can **read** a variable from outside:

```python
TAX = 0.2

def with_tax(price):
    return price * (1 + TAX)

print(with_tax(50))
```

```text
60.0
```

`TAX` is not local to `with_tax`, so Python looks further out and finds it in the global workspace. Reading module-level **constants** this way is normal and safe.

## LEGB: where Python looks

When Python meets a name, it searches four places, in this order, and stops at the first match:

| Order | Scope | Where |
|---|---|---|
| **L** | Local | inside the current function |
| **E** | Enclosing | inside any function that contains this one |
| **G** | Global | the top level of the file |
| **B** | Built-in | names Python provides: `print`, `len`, `sum` ... |

```python
x = "global"

def outer():
    x = "enclosing"

    def inner():
        x = "local"
        print(x)

    inner()
    print(x)

outer()
print(x)
```

```text
local
enclosing
global
```

Each `x` is a separate variable. Python picked the nearest one in each case. Functions defined inside other functions are called **nested** functions, and the outer one's variables form the **enclosing** scope.

## Shadowing

When a local name matches a global or built-in one, the local **shadows** it. That is legal and occasionally disastrous:

```python
def count_items(items):
    len = 0
    for item in items:
        len += 1
    return len

print(count_items([1, 2, 3]))
```

```text
3
```

This works, but now `len` is a plain number inside that function, and calling `len(items)` there would fail. Avoid reusing built-in names like `len`, `sum`, `list`, `max` and `input` for your own variables.

## The assignment trap

Python decides whether a name is local by looking at the **whole function body**. If you assign to a name anywhere inside, it is local everywhere in that function, even on lines before the assignment.

```python error
count = 0

def increment():
    count = count + 1
    return count

increment()
```

```text
Traceback (most recent call last):
  File "main.py", line 7, in <module>
    increment()
  File "main.py", line 4, in increment
    count = count + 1
UnboundLocalError: cannot access local variable 'count' where it is not associated with a value
```

Because `count` is assigned inside, Python treats it as local, so on the right-hand side it has no value yet. Reading a global and assigning to a name are different operations.

You could fix it with the `global` keyword:

```python
count = 0

def increment():
    global count
    count = count + 1

increment()
increment()
print(count)
```

```text
2
```

`global count` says "this name refers to the module-level variable". It works, but functions that quietly change global state are hard to test and reason about. The better design is to **pass values in and return values out**:

```python
def increment(count):
    return count + 1

count = 0
count = increment(count)
count = increment(count)
print(count)
```

```text
2
```

> **Tip:** If you find yourself writing `global`, ask whether the value should be a parameter and a return value instead. Nearly always, it should.

## The call stack

Python keeps track of running functions with a **call stack**. Each call pushes a new **frame** holding that call's local variables. When the function returns, its frame is popped and discarded, and execution resumes in the frame below.

```python
def c():
    print("in c")

def b():
    print("start b")
    c()
    print("end b")

def a():
    print("start a")
    b()
    print("end a")

a()
```

```text
start a
start b
in c
end b
end a
```

While `c` runs, the stack holds `a`, `b` and `c`, from bottom to top. `c` finishes first and its frame disappears, then `b`, then `a`. It is last in, first out, like a stack of plates.

This is also what the **traceback** shows when an error occurs: the chain of calls that led to it, innermost last.

## A taste of recursion

A function may call itself. Each call gets its own frame with its own locals, which is how recursion works.

```python
def factorial(n):
    if n <= 1:
        return 1
    return n * factorial(n - 1)

print(factorial(5))
```

```text
120
```

`factorial(5)` waits for `factorial(4)`, which waits for `factorial(3)`, and so on down to `factorial(1)`. Five frames stack up, then each returns and multiplies on the way back. Every recursive function needs a **base case** that stops the calls, here `n <= 1`. Without one the stack grows until Python raises a `RecursionError`.

## Common mistakes

- **Using a variable outside the function that made it.** Locals disappear when the function returns.
- **Assigning to a global inside a function without `global`.** It silently creates a new local.
- **Reusing built-in names** like `list` or `sum` for variables.
- **Overusing `global`.** Prefer parameters and return values.
- **Recursion without a base case.**

## Recap

- Variables assigned in a function are **local**, and each call gets its own set.
- Python looks up names in LEGB order: Local, Enclosing, Global, Built-in.
- A local name **shadows** an outer one. Do not shadow built-ins.
- Assigning to a name anywhere in a function makes it local everywhere in that function.
- The call stack holds one frame per running call, and returns pop frames. Recursion needs a base case.
