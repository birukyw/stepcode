# return vs. print (The Classic Trap)

In the terminal, a function that prints a number and a function that returns a number look identical. They are completely different things, and mixing them up is the most common mistake in this module. This lesson draws the line clearly.

## Two different jobs

- `print()` **shows** a value to a human in the terminal. The value is then gone.
- `return` **hands** a value back to the code that called the function, so that code can keep using it.

```python
def add_print(a, b):
    print(a + b)

def add_return(a, b):
    return a + b

add_print(2, 3)
add_return(2, 3)
```

```text
5
```

Only one `5` appeared. `add_print` displayed its result. `add_return` produced a value, but nobody asked to display it, so nothing showed. To see it, you must print the returned value yourself: `print(add_return(2, 3))`.

## Why the difference matters

A returned value can be stored, computed with, and passed to other functions. A printed value cannot.

```python
def add_print(a, b):
    print(a + b)

def add_return(a, b):
    return a + b

result = add_return(2, 3)
print(result * 10)

broken = add_print(2, 3)
print(broken)
```

```text
50
5
None
```

`add_return` gave back `5`, so `result * 10` is `50`. `add_print` printed `5` as a side effect, then returned **`None`**, and so `broken` holds `None`. Anything you try to do with it fails:

```python error
def add_print(a, b):
    print(a + b)

total = add_print(2, 3) + 10
```

```text
5
Traceback (most recent call last):
  File "main.py", line 4, in <module>
    total = add_print(2, 3) + 10
TypeError: unsupported operand type(s) for +: 'NoneType' and 'int'
```

> **Warning:** An error that mentions `NoneType` almost always means a function printed its answer where it should have returned it.

## Implicit None

Every function returns something. If execution reaches the end without a `return`, Python quietly returns `None`.

```python
def shout(text):
    text.upper()

print(shout("hello"))
```

```text
None
```

The method `text.upper()` computed a new string, then the function threw it away because it never returned it. Written correctly:

```python
def shout(text):
    return text.upper()

print(shout("hello"))
```

```text
HELLO
```

## return ends the function

The moment Python executes `return`, the function stops. Nothing after it runs.

```python
def first_even(a, b):
    if a % 2 == 0:
        return a
    return b

print(first_even(4, 7))
print(first_even(3, 8))
```

```text
4
8
```

Using `return` early to handle special cases keeps the main logic unindented. This is called an **early return**, and it often removes the need for `else`.

```python
def grade(score):
    if score >= 90:
        return "A"
    if score >= 80:
        return "B"
    if score >= 70:
        return "C"
    return "F"

print(grade(85))
```

```text
B
```

## Returning several values

A function returns one object, but that object can be a tuple, which you can unpack right away.

```python
def min_max(numbers):
    return min(numbers), max(numbers)

low, high = min_max([4, 9, 2, 7])
print(low, high)
```

```text
2 9
```

## Composition

Because a function call is an expression with a value, you can use it anywhere a value is allowed, including as the argument to another call. This is **composition**: `f(g(x))`.

```python
def double(n):
    return n * 2

def add_one(n):
    return n + 1

print(add_one(double(5)))
print(double(add_one(5)))
```

```text
11
12
```

Python evaluates from the inside out. In `add_one(double(5))`, `double(5)` runs first and gives `10`, and then `add_one(10)` gives `11`. The order of composition changes the answer.

This is exactly why returning matters: a chain like this only works if each function **returns** its result. Put a `print` in the middle and the next function receives `None`.

## Pipelines

Small functions that each take a value and return a new one can be chained into a pipeline.

```python
def clean(text):
    return text.strip().lower()

def tokenize(text):
    return text.split()

def count_words(text):
    return len(tokenize(clean(text)))

print(count_words("  The Quick Brown FOX  "))
```

```text
4
```

Each step has one job, and the last function composes the others.

## When to print and when to return

A good default: **functions should return values, and only the outermost part of the program should print.** That keeps your functions reusable and testable. A function that prints cannot be reused somewhere you want a number, but a function that returns can be printed, stored or combined anywhere.

Reserve `print` inside a function for functions whose whole purpose is to display something, such as `show_scoreboard()`.

## Common mistakes

- **Printing where you meant to return.** The caller receives `None`.
- **Calling a function and ignoring the result.** `text.upper()` on its own line does nothing useful.
- **Code after `return`.** It never runs.
- **Forgetting `return` on some path.** A function that returns on one branch but not another gives back `None` for the other.
- **Expecting `return` to print.** It only hands the value back.

## Recap

- `print` displays a value and then it is gone. `return` hands the value back so it can be used.
- A function with no `return` gives back `None`.
- `return` ends the function immediately. Use early returns for special cases.
- Return a tuple to give back several values, and unpack it at the call site.
- Nested calls evaluate from the inside out, so each step must return its result.
