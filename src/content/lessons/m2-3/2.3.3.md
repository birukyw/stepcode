# Hash Tables Under the Hood

A Python `dict` or `set` finds a key in roughly the same time whether it holds ten items or ten million. That feels like magic until you build one. This lesson opens the hood: hash functions, buckets, collisions and resizing. By the end you will have written a working hash table and you will know why some keys are allowed and others are not.

## The goal: jump straight to the item

A list finds an item by position in O(1) and by value in O(n). A hash table turns a **key into a position**, so lookups by key are O(1) on average. The tool that does it is a **hash function**: it turns any key into an integer.

```python
print(hash(42))
print(hash("a") == hash("a"))
print(hash((1, 2)) == hash((1, 2)))
print(hash(1) == hash(1.0))
```

```text
42
True
True
True
```

Equal keys must have equal hashes. Python's string hashes change between runs on purpose (for security), so never rely on specific numbers.

## From hash to bucket

A table is an array of **buckets**. To place a key, take its hash modulo the number of buckets:

```python
buckets = 8
for key in ["ada", "linus", "grace", "guido"]:
    print(key, hash(key) % buckets >= 0)
```

```text
ada True
linus True
grace True
guido True
```

Two different keys can land in the same bucket. That is a **collision**, and it is unavoidable: infinitely many possible keys, a finite number of buckets. Every hash table is defined by how it handles them.

## Collision strategy 1: chaining

Each bucket holds a small list. A collision just means a longer list:

```python
class ChainedMap:
    def __init__(self, size=8):
        self.buckets = [[] for _ in range(size)]
        self.count = 0

    def _bucket(self, key):
        return self.buckets[hash(key) % len(self.buckets)]

    def put(self, key, value):
        bucket = self._bucket(key)
        for i, (k, _) in enumerate(bucket):
            if k == key:
                bucket[i] = (key, value)       # update existing key
                return
        bucket.append((key, value))
        self.count += 1
        if self.count > 2 * len(self.buckets):
            self._grow()

    def get(self, key, default=None):
        for k, v in self._bucket(key):
            if k == key:
                return v
        return default

    def _grow(self):
        old = [pair for bucket in self.buckets for pair in bucket]
        self.buckets = [[] for _ in range(len(self.buckets) * 2)]
        self.count = 0
        for k, v in old:
            self.put(k, v)

m = ChainedMap()
for i in range(20):
    m.put(f"key{i}", i * i)
print(m.get("key7"), m.get("nope", "missing"), m.count, len(m.buckets))
```

```text
49 missing 20 16
```

The **load factor** is items divided by buckets. When it grows too large, chains lengthen and lookups slow down, so the table **resizes**: it doubles the bucket count and reinserts every key (the new modulo moves them). Resizing is O(n) but happens rarely, so each insert is **O(1) amortized**, the same argument as for list `append` in module 2.1.

## Collision strategy 2: open addressing

Instead of chains, store everything in the array itself. On a collision, **probe** the next slot until you find an empty one. This is what CPython's dict does (with a cleverer probe sequence).

```python
class ProbingMap:
    EMPTY = object()

    def __init__(self, size=8):
        self.keys = [self.EMPTY] * size
        self.values = [None] * size
        self.count = 0

    def _find(self, key):
        i = hash(key) % len(self.keys)
        while self.keys[i] is not self.EMPTY and self.keys[i] != key:
            i = (i + 1) % len(self.keys)        # linear probing
        return i

    def put(self, key, value):
        if (self.count + 1) * 3 > len(self.keys) * 2:
            self._grow()
        i = self._find(key)
        if self.keys[i] is self.EMPTY:
            self.count += 1
        self.keys[i] = key
        self.values[i] = value

    def get(self, key, default=None):
        i = self._find(key)
        return default if self.keys[i] is self.EMPTY else self.values[i]

    def _grow(self):
        pairs = [(k, v) for k, v in zip(self.keys, self.values) if k is not self.EMPTY]
        self.keys = [self.EMPTY] * (len(self.keys) * 2)
        self.values = [None] * len(self.keys)
        self.count = 0
        for k, v in pairs:
            self.put(k, v)

p = ProbingMap()
for word in "the quick brown fox jumps over the lazy dog".split():
    p.put(word, len(word))
print(p.get("quick"), p.get("fox"), p.get("cat", -1), p.count)
```

```text
5 3 -1 8
```

Open addressing keeps data compact and cache friendly, but it must keep the table **at most about two-thirds full**, or probe sequences get long. Deleting is also subtle: simply emptying a slot would break the probe chain for keys placed after it, so real implementations leave a "tombstone" marker.

## Why keys must be hashable

The table finds an item by recomputing `hash(key)`. If a key could change after insertion, its hash would change and the item would be lost in the wrong bucket. So Python only allows **immutable** keys:

```python
good = {(1, 2): "tuple works", "text": "so do strings", 7: "and numbers"}
print(good[(1, 2)])

try:
    bad = {[1, 2]: "no"}
except TypeError as e:
    print(e)
```

```text
tuple works
cannot use 'list' as a dict key (unhashable type: 'list')
```

A custom class is hashable by default (by identity). If you define `__eq__`, you should also define `__hash__` so that **equal objects have equal hashes**:

```python
class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y
    def __eq__(self, other):
        return (self.x, self.y) == (other.x, other.y)
    def __hash__(self):
        return hash((self.x, self.y))

seen = {Point(1, 2)}
print(Point(1, 2) in seen, Point(2, 1) in seen)
```

```text
True False
```

## When hashing goes bad

If every key lands in one bucket, a lookup degrades to scanning a chain: **O(n)**. Good hash functions spread keys evenly. You can see the damage with a deliberately terrible hash:

```python
import time

class Bad:
    def __init__(self, n): self.n = n
    def __eq__(self, other): return self.n == other.n
    def __hash__(self): return 1                # every key collides

def build(cls, n):
    start = time.perf_counter()
    d = {cls(i): i for i in range(n)}
    return time.perf_counter() - start

class Good(Bad):
    def __hash__(self): return hash(self.n)

print(build(Bad, 3000) > build(Good, 3000))
```

```text
True
```

This is also how "hash flooding" attacks work: an attacker crafts keys that collide to slow a server. Python randomizes string hashing to defend against it.

## Sets are the same thing

A `set` is a hash table with keys and no values. That is why `x in my_set` is O(1) while `x in my_list` is O(n), and why set items must be hashable.

```python
data = list(range(100_000))
as_set = set(data)
print(99_999 in as_set)
```

```text
True
```

## Common mistakes

- **Mutating an object used as a key.** Use immutable keys: strings, numbers, tuples.
- **Defining `__eq__` without `__hash__`.** Python then sets `__hash__` to None and your objects become unhashable.
- **Relying on dict order from hashing.** Modern dicts remember insertion order, but a set has no order guarantee.
- **Assuming O(1) always.** It is O(1) on average and with a good hash. The worst case is O(n).
- **Testing membership in a list inside a loop.** Convert it to a set first.

class ChainedMap:
    def __init__(self, size=8):
        self.buckets = [[] for _ in range(size)]

    def _bucket(self, key):
        return self.buckets[hash(key) % len(self.buckets)]

    def put(self, key, value):
        b = self._bucket(key)
        for i, (k, _) in enumerate(b):
            if k == key:
                b[i] = (key, value)
                return
        b.append((key, value))

    def delete(self, key):
        b = self._bucket(key)
        for i, (k, _) in enumerate(b):
            if k == key:
                del b[i]
                return True
        return False

m = ChainedMap()
m.put("a", 1)
print(m.delete("a"), m.delete("a"))   # True False
```

def two_sum(nums, target):
    seen = {}
    for i, n in enumerate(nums):
        if target - n in seen:
            return seen[target - n], i
        seen[n] = i
    return None

print(two_sum([2, 7, 11, 15], 9))   # (0, 1)
```

## Recap

- A hash table turns a key into an array position with a **hash function** and a modulo, giving O(1) average lookups.
- **Collisions** are unavoidable. Chaining stores a list per bucket, open addressing probes for a free slot.
- Tables **resize** (usually doubling) when the load factor gets high, which makes inserts O(1) amortized.
- Keys must be **hashable**, which means immutable, and equal keys must produce equal hashes.
- A poor hash function collapses the table to O(n) lookups, and a `set` is just a hash table without values.
