# Binary Search on Arrays & Answer Spaces

Looking up a word in a paper dictionary, you never read from page one. You open the middle, see whether your word comes before or after, and throw away half the book. **Binary search** does exactly that to a sorted list, and it turns a search of a million items into about **20 steps**. Then comes the surprising part: the same idea finds answers to questions that have no list at all.

## Linear search, and why it is slow

Without any order, the only way to find an item is to check each one:

```python
def linear_search(items, target):
    steps = 0
    for i, value in enumerate(items):
        steps += 1
        if value == target:
            return i, steps
    return -1, steps

data = list(range(0, 2_000_000, 2))
print(linear_search(data, 1_999_998))
```

```text
(999999, 1000000)
```

A million items, a million steps. That is **O(n)**.

## Halving the search space

If the list is **sorted**, one comparison with the middle item tells you which half the target lives in. Keep two bounds, `lo` and `hi`, and move one of them each round:

```python
def binary_search(items, target):
    lo, hi = 0, len(items) - 1
    steps = 0
    while lo <= hi:
        steps += 1
        mid = (lo + hi) // 2
        if items[mid] == target:
            return mid, steps
        if items[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1, steps

data = list(range(0, 2_000_000, 2))
print(binary_search(data, 1_999_998))
print(binary_search(data, 7))
```

```text
(999999, 20)
(-1, 20)
```

About 20 steps instead of a million. Doubling the list adds just **one** more step, which is what **O(log n)** means.

### The loop invariant

Binary search is famous for being easy to describe and easy to get wrong. Hold on to one sentence: **"if the target exists, it lies in `items[lo..hi]`."** Every line must keep that sentence true. After comparing with `mid`, the item at `mid` has been ruled out, so the new bound is `mid + 1` or `mid - 1`, never `mid`, otherwise the loop can run forever.

## The bisect module

Python ships a tested version. `bisect_left` returns the index where the target is, or **would be inserted** to keep the list sorted:

```python
from bisect import bisect_left, bisect_right

nums = [1, 3, 3, 3, 7, 9]
print(bisect_left(nums, 3))
print(bisect_right(nums, 3))
print(bisect_left(nums, 5))
print(bisect_right(nums, 3) - bisect_left(nums, 3))
```

```text
1
4
4
3
```

`bisect_left` finds the **first** position, `bisect_right` one past the **last**. Their difference counts duplicates in O(log n). Use `bisect_left` to build a membership test:

```python
from bisect import bisect_left

def contains(sorted_items, target):
    i = bisect_left(sorted_items, target)
    return i < len(sorted_items) and sorted_items[i] == target

print(contains([1, 3, 5, 7], 5), contains([1, 3, 5, 7], 4))
```

```text
True False
```

## First and last occurrence

A plain search returns *some* match. When duplicates exist you usually want the first one. Keep searching left even after you find it:

```python
def first_at_least(items, target):
    lo, hi = 0, len(items)          # hi is one past the end
    while lo < hi:
        mid = (lo + hi) // 2
        if items[mid] < target:
            lo = mid + 1
        else:
            hi = mid
    return lo

nums = [1, 3, 3, 3, 7, 9]
print(first_at_least(nums, 3), first_at_least(nums, 8), first_at_least(nums, 100))
```

```text
1 5 6
```

This second style, with `hi = len(items)` and `while lo < hi`, is the one worth memorizing. It always answers: "what is the first index where the condition `items[i] >= target` becomes true?" Notice that it returns `len(items)` when no such index exists.

## Binary search on the answer

Here is the leap. Binary search needs only one thing: a question whose answer flips from **False to True once** as the input grows. It does not care whether a list exists.

*A delivery has packages of weight `[3, 2, 2, 4, 1, 4]` and must ship in at most 3 days, loading in order. What is the smallest ship capacity that works?*

A capacity is either enough or not, and if capacity `c` works, every bigger one does too. That is a monotonic yes/no question, so search the range of capacities:

```python
def days_needed(weights, capacity):
    days, load = 1, 0
    for w in weights:
        if load + w > capacity:
            days += 1
            load = 0
        load += w
    return days

def min_capacity(weights, max_days):
    lo, hi = max(weights), sum(weights)     # the answer lies in this range
    while lo < hi:
        mid = (lo + hi) // 2
        if days_needed(weights, mid) <= max_days:
            hi = mid                         # mid works, try smaller
        else:
            lo = mid + 1                     # mid fails, need more
    return lo

print(min_capacity([3, 2, 2, 4, 1, 4], 3))
```

```text
6
```

The simulation costs O(n) and the search needs about log(sum) rounds, so the whole thing is **O(n log S)**, far better than trying every capacity.

The same shape solves "smallest speed to finish all tasks in time", "largest minimum distance", and the integer square root:

```python
def isqrt(n):
    lo, hi = 0, n
    while lo < hi:
        mid = (lo + hi + 1) // 2        # round up so the loop makes progress
        if mid * mid <= n:
            lo = mid
        else:
            hi = mid - 1
    return lo

print(isqrt(99), isqrt(100), isqrt(10**12))
```

```text
9 10 1000000
```

When you move `lo = mid`, you must round `mid` **up**, or the loop can stall with `lo + 1 == hi`.

## A recipe for any binary search

1. Decide the search space: indexes, or a range of possible answers.
2. Write a yes/no test that is **False...False True...True** across that space.
3. Use `while lo < hi`, with `hi = mid` on True and `lo = mid + 1` on False.
4. When the loop ends, `lo == hi` is the first True. Check whether it is valid.

## Common mistakes

- **Searching an unsorted list.** Binary search silently returns nonsense.
- **`hi = mid` and `lo = mid` with `while lo <= hi`.** The bounds never cross, so the loop never ends.
- **Overflow worries.** In Python `(lo + hi) // 2` is safe. In Java and C use `lo + (hi - lo) / 2`.
- **Off-by-one on the answer.** Decide up front whether you want the first True or the last False, and test the edges: empty list, one item, target smaller than all, larger than all.
- **Sorting inside the loop.** Sorting costs O(n log n), so sort once, outside.

## Practice

2. Write `search_insert(nums, target)` returning the index where `target` is or would be inserted.
3. A sorted list was rotated, for example `[6, 7, 9, 1, 2, 4]`. Find the minimum in O(log n).
4. Koko eats bananas from piles `[3, 6, 7, 11]` and must finish in 8 hours. What is the smallest integer speed (bananas per hour) that works? One pile per hour at most, rounded up.

+++ Solutions
```python
from bisect import bisect_left, bisect_right

def count_in_range(nums, a, b):
    return bisect_right(nums, b) - bisect_left(nums, a)

print(count_in_range([1, 3, 3, 5, 8, 9], 3, 8))   # 4
```

```python
from bisect import bisect_left

def search_insert(nums, target):
    return bisect_left(nums, target)

print(search_insert([1, 3, 5, 6], 5), search_insert([1, 3, 5, 6], 2))   # 2 1
```

```python
def find_min_rotated(nums):
    lo, hi = 0, len(nums) - 1
    while lo < hi:
        mid = (lo + hi) // 2
        if nums[mid] > nums[hi]:
            lo = mid + 1        # the minimum is to the right of mid
        else:
            hi = mid
    return nums[lo]

print(find_min_rotated([6, 7, 9, 1, 2, 4]))   # 1
```

```python
def min_speed(piles, hours):
    lo, hi = 1, max(piles)
    while lo < hi:
        mid = (lo + hi) // 2
        needed = sum((p + mid - 1) // mid for p in piles)
        if needed <= hours:
            hi = mid
        else:
            lo = mid + 1
    return lo

print(min_speed([3, 6, 7, 11], 8))   # 4
```

## Recap

- Binary search halves a **sorted** search space each step: O(log n) instead of O(n).
- Keep the invariant "the target, if present, is within `lo..hi`" and always move a bound past `mid`.
- `bisect_left` gives the first position where an item fits, `bisect_right` one past the last. Their difference counts duplicates.
- The `while lo < hi` form with `hi = mid` finds the **first index where a condition becomes true**.
- You can binary search an **answer**, not just a list, whenever a yes/no test flips from False to True exactly once.
