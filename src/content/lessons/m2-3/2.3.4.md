# Combining Hash Maps + Doubly Linked Lists (LRU Cache)

Two structures, each with one weakness. A hash map finds anything in O(1) but has no sense of order. A linked list can reorder in O(1) if you hold the node, but finding a node costs O(n). Glue them together and each covers for the other. The result, the **LRU cache**, runs in browsers, databases and operating systems, and it is one of the most asked-about designs in interviews.

## What a cache must do

A cache keeps recently used results close at hand. It has a fixed **capacity**. When it is full and a new item arrives, it evicts the **Least Recently Used** item, the one nobody has touched for the longest time.

`capacity 2:  put(a)  put(b)  get(a)  put(c)` evicts **b**, the least recently used.

The two operations, `get` and `put`, must both be **O(1)**. Think about what that demands:

- Find a key instantly: **hash map**.
- Mark an item as "just used" and find the oldest one instantly: an **ordered sequence** where you can move any item to the front and remove from the back, each in O(1).

A Python list cannot move an item in O(1). A singly linked list cannot remove a node without knowing its predecessor. A **doubly linked list** can: each node knows both neighbours.

## The doubly linked list

```python
class Node:
    def __init__(self, key=None, value=None):
        self.key = key
        self.value = value
        self.prev = None
        self.next = None

# Two dummy sentinels remove every "is this the first node?" special case
head, tail = Node(), Node()
head.next, tail.prev = tail, head

def remove(node):
    node.prev.next = node.next
    node.next.prev = node.prev

def add_front(node):
    node.next = head.next
    node.prev = head
    head.next.prev = node
    head.next = node

a, b = Node("a", 1), Node("b", 2)
add_front(a)
add_front(b)
order = []
cur = head.next
while cur is not tail:
    order.append(cur.key)
    cur = cur.next
print(order)

remove(a)
add_front(a)
order = []
cur = head.next
while cur is not tail:
    order.append(cur.key)
    cur = cur.next
print(order)
```

```text
['b', 'a']
['a', 'b']
```

The two sentinel nodes (`head` and `tail`) mean the real nodes always have a neighbour on each side, so `remove` and `add_front` are four assignments with no `if`. This is the dummy-node trick from lesson 2.2.1 again. We keep the most recent item right after `head` and the least recent right before `tail`.

## The cache

The dictionary maps a key to its node. The list orders the nodes by recency.

```python
class Node:
    def __init__(self, key=None, value=None):
        self.key = key
        self.value = value
        self.prev = None
        self.next = None


class LRUCache:
    def __init__(self, capacity):
        self.capacity = capacity
        self.map = {}                       # key -> Node
        self.head, self.tail = Node(), Node()
        self.head.next, self.tail.prev = self.tail, self.head

    def _remove(self, node):
        node.prev.next = node.next
        node.next.prev = node.prev

    def _add_front(self, node):
        node.next = self.head.next
        node.prev = self.head
        self.head.next.prev = node
        self.head.next = node

    def get(self, key):
        node = self.map.get(key)
        if node is None:
            return -1
        self._remove(node)                  # touched: move to the front
        self._add_front(node)
        return node.value

    def put(self, key, value):
        node = self.map.get(key)
        if node:
            node.value = value
            self._remove(node)
            self._add_front(node)
            return
        if len(self.map) == self.capacity:
            oldest = self.tail.prev         # least recently used
            self._remove(oldest)
            del self.map[oldest.key]
        node = Node(key, value)
        self.map[key] = node
        self._add_front(node)

cache = LRUCache(2)
cache.put("a", 1)
cache.put("b", 2)
print(cache.get("a"))
cache.put("c", 3)
print(cache.get("b"))
print(cache.get("a"), cache.get("c"))
```

```text
1
-1
1 3
```

Walk through it: after `get("a")`, `a` is the most recent. Adding `c` overflows, so the list's tail, `b`, is evicted. Every step is a dictionary lookup plus a handful of pointer changes, so `get` and `put` are **O(1)**.

Note why each node stores its **key**: when we evict `oldest` from the list we need to delete the matching entry from the dictionary.

## The shortcut: OrderedDict

Python's `collections.OrderedDict` already does this combination (a hash map plus a doubly linked list) internally. `move_to_end` and `popitem(last=False)` give you the same cache in a few lines:

```python
from collections import OrderedDict

class LRU:
    def __init__(self, capacity):
        self.capacity = capacity
        self.data = OrderedDict()

    def get(self, key):
        if key not in self.data:
            return -1
        self.data.move_to_end(key)           # most recent goes last
        return self.data[key]

    def put(self, key, value):
        self.data[key] = value
        self.data.move_to_end(key)
        if len(self.data) > self.capacity:
            self.data.popitem(last=False)     # drop the oldest

c = LRU(2)
c.put(1, "one"); c.put(2, "two"); c.get(1); c.put(3, "three")
print(list(c.data))
```

```text
[1, 3]
```

Building it by hand matters: the same recipe applies whenever you need "look up in O(1) **and** keep things in a custom order", and it is the interview question.

## Where this pattern shows up

- **Memoization with a limit.** `functools.lru_cache(maxsize=128)` is exactly this idea in the standard library.
- **Browser and CDN caches.** Keep the pages most recently visited.
- **Database buffer pools.** Keep hot disk pages in memory.
- **LFU cache**, the next variant: evict the *least frequently* used item. It adds a second map from counts to lists.

```python
from functools import lru_cache

@lru_cache(maxsize=3)
def slow_square(n):
    print("computing", n)
    return n * n

print(slow_square(4))
print(slow_square(4))
print(slow_square.cache_info().hits)
```

```text
computing 4
16
16
1
```

## Common mistakes

- **Forgetting to update the dictionary on eviction.** The cache then keeps stale entries and grows without bound.
- **Not storing the key in the node.** You cannot find which dictionary entry to delete.
- **Updating a value without marking it recently used.** A `put` on an existing key counts as a use.
- **Breaking a pointer pair.** Every move touches four pointers. Update `prev` and `next` on both sides, in a safe order.
- **Skipping sentinels.** Without them each operation needs special cases for the first and last node.

```python
class Node:
    def __init__(self, key=None, value=None):
        self.key, self.value, self.prev, self.next = key, value, None, None

class LRUCache:
    def __init__(self, capacity):
        self.capacity = capacity
        self.map = {}
        self.head, self.tail = Node(), Node()
        self.head.next, self.tail.prev = self.tail, self.head

    def _remove(self, n):
        n.prev.next, n.next.prev = n.next, n.prev

    def _add_front(self, n):
        n.next, n.prev = self.head.next, self.head
        self.head.next.prev = n
        self.head.next = n

    def put(self, key, value):
        if key in self.map:
            self.delete(key)
        if len(self.map) == self.capacity:
            self.delete(self.tail.prev.key)
        n = Node(key, value)
        self.map[key] = n
        self._add_front(n)

    def delete(self, key):
        n = self.map.pop(key, None)
        if n:
            self._remove(n)
            return True
        return False

    def __len__(self):
        return len(self.map)

    def keys(self):
        out, cur = [], self.head.next
        while cur is not self.tail:
            out.append(cur.key)
            cur = cur.next
        return out

c = LRUCache(2)
c.put("a", 1); c.put("b", 2); c.put("c", 3)
print(len(c), c.keys(), c.delete("c"), c.keys())   # 2 ['c', 'b'] True ['b']
```

```python
from collections import OrderedDict

d, cap = OrderedDict(), 2
def get(k):
    if k not in d:
        return -1
    d.move_to_end(k)
    return d[k]
def put(k, v):
    d[k] = v
    d.move_to_end(k)
    if len(d) > cap:
        d.popitem(last=False)

put(1, 1); put(2, 2); get(1); put(3, 3)
print(get(2))             # -1
put(4, 4)
print(get(1), get(3), get(4))   # -1 3 4
```

A singly linked list cannot delete a node in O(1) without its predecessor, and finding the predecessor needs a walk from the head, which is O(n).

## Recap

- A hash map gives O(1) lookup, a doubly linked list gives O(1) reordering, and together they give an O(1) **LRU cache**.
- The map stores key to **node**. The list orders nodes by recency: most recent at the front, least recent at the back.
- Sentinel head and tail nodes remove all the edge cases from insert and remove.
- On `get` and on updating `put`, move the node to the front. On overflow, evict the tail node **and** delete its key from the map.
- `OrderedDict` and `functools.lru_cache` already package this idea, but building it yourself is the lesson.
