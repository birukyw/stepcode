# Monotonic Stacks & Monotonic Deques

Some questions sound like they need a nested loop, but have a one-pass answer once you notice that **some candidates can never matter again**. A monotonic stack throws those candidates away the moment they become useless, which is what turns O(n²) into O(n). It is one of the most elegant ideas in the track, and it is a favourite in interviews.

## The problem: the next greater element

For every number in a list, find the first number to its **right** that is larger, or `-1` if there is none.

The obvious solution scans right from each position:

```python
def next_greater_slow(nums):
    result = []
    steps = 0
    for i in range(len(nums)):
        answer = -1
        for j in range(i + 1, len(nums)):
            steps += 1
            if nums[j] > nums[i]:
                answer = nums[j]
                break
        result.append(answer)
    return result, steps

print(next_greater_slow([4, 5, 2, 25, 7, 8]))
```

```text
([5, 25, 25, -1, 8, -1], 7)
```

It works, and it is O(n²) in the worst case.

## A stack of waiting items

Walk through the list once. Keep a **stack of indexes whose answer we have not found yet**. When a new number arrives, it is the answer for every waiting item that is smaller than it, so pop and settle them all.

```python
def next_greater(nums):
    result = [-1] * len(nums)
    waiting = []                      # indexes still looking for an answer
    for i, value in enumerate(nums):
        while waiting and nums[waiting[-1]] < value:
            result[waiting.pop()] = value
        waiting.append(i)
    return result

print(next_greater([4, 5, 2, 25, 7, 8]))
```

```text
[5, 25, 25, -1, 8, -1]
```

Trace it by hand. After `4` the stack holds `[4]`. Then `5` arrives: it is bigger than `4`, so `4` is answered and popped, and `5` waits. `2` is smaller than `5`, so it simply waits on top. `25` is bigger than `2` and `5`, so both are answered at once, and so on.

### Why it is monotonic

Look at the values on the stack at any moment: from bottom to top they are **never increasing**, since anything smaller than the incoming value gets popped before it is pushed. A stack that is always sorted in one direction is called **monotonic**.

### Why it is O(n)

Every index is pushed **once** and popped **at most once**. The `while` loop looks nested, but its total work over the whole run is bounded by the number of pushes. This is the same amortised argument as lesson 2.1.2 and the sliding window in 2.1.4.

## Daily temperatures

Given daily temperatures, how many days must you wait for a warmer day? It is the same pattern, except you store the **distance** between indexes:

```python
def days_until_warmer(temps):
    result = [0] * len(temps)
    stack = []
    for i, t in enumerate(temps):
        while stack and temps[stack[-1]] < t:
            j = stack.pop()
            result[j] = i - j
        stack.append(i)
    return result

print(days_until_warmer([73, 74, 75, 71, 69, 72, 76, 73]))
```

```text
[1, 1, 4, 2, 1, 1, 0, 0]
```

The temperature on day 2 (75) has to wait 4 days for 76.

## Variations

Change the comparison and you change the question.

| Question | Stack order | Pop while |
|---|---|---|
| next **greater** element | decreasing | stack top `<` new value |
| next **smaller** element | increasing | stack top `>` new value |
| previous greater/smaller | scan the same way, but read the stack top **before** pushing | |

Next smaller element, for example:

```python
def next_smaller(nums):
    result = [-1] * len(nums)
    stack = []
    for i, value in enumerate(nums):
        while stack and nums[stack[-1]] > value:
            result[stack.pop()] = value
        stack.append(i)
    return result

print(next_smaller([4, 8, 5, 2, 25]))
```

```text
[2, 5, 2, -1, -1]
```

## The skyline: stock span

The **span** of a day is how many consecutive days, ending on that day, had a price less than or equal to it. A monotonic stack finds it by remembering the most recent day that had a **higher** price:

```python
def stock_span(prices):
    spans = []
    stack = []                         # indexes with decreasing prices
    for i, p in enumerate(prices):
        while stack and prices[stack[-1]] <= p:
            stack.pop()
        spans.append(i + 1 if not stack else i - stack[-1])
        stack.append(i)
    return spans

print(stock_span([100, 80, 60, 70, 60, 75, 85]))
```

```text
[1, 1, 1, 2, 1, 4, 6]
```

On the last day, 85 beats every earlier price, so its span is 6, the whole history.

## Monotonic deques: sliding window maximum

The stack discards candidates from one end. For a **sliding window**, items also expire from the *other* end as the window moves on, which calls for a double-ended queue, a **monotonic deque**.

The task: the maximum of every window of size `k`. The brute force takes O(n·k). The deque keeps **indexes of candidates in decreasing order of value**, so the front is always the current maximum:

```python
from collections import deque

def sliding_max(nums, k):
    dq = deque()                      # indexes, values decreasing
    out = []
    for i, value in enumerate(nums):
        while dq and nums[dq[-1]] <= value:
            dq.pop()                  # smaller items behind a bigger one can never win
        dq.append(i)
        if dq[0] <= i - k:
            dq.popleft()              # the front has slid out of the window
        if i >= k - 1:
            out.append(nums[dq[0]])
    return out

print(sliding_max([1, 3, -1, -3, 5, 3, 6, 7], 3))
```

```text
[3, 3, 5, 5, 6, 7]
```

Two rules do all the work:

1. **Pop from the back** any item smaller than the new one. Anything older and smaller can never be the maximum while the newer, bigger item is in the window.
2. **Pop from the front** when the front index has slid out of the window.

Each index enters once and leaves once: **O(n) in total**, whatever `k` is.

## When to suspect a monotonic structure

- "Next greater / smaller", "previous greater / smaller".
- "How many days until ..." questions.
- "Maximum / minimum of every window".
- Largest rectangle in a histogram, trapping rain water, and many problems that talk about the nearest bigger or smaller neighbour.

The signal is a question about the **nearest item on one side that beats this one**.

## Common mistakes

- **Storing values when you need positions.** Store indexes, so you can compute distances and detect expiry.
- **Using `<` when you need `<=`** (or the reverse). Check what happens with equal values.
- **Forgetting leftover items.** Whatever remains on the stack at the end has no answer, so keep the default.
- **Forgetting to expire the deque's front** in the sliding version.
- **Calling it O(n²)** because of the nested `while`. Each element is popped at most once.

## Recap

- A monotonic stack stays sorted in one direction because useless candidates are popped as soon as a better one arrives.
- The next-greater pattern: scan once, keep a stack of unanswered indexes, and settle every smaller one when a bigger value shows up.
- Each element is pushed and popped at most once, so the whole thing is O(n) even though there is a nested `while`.
- A monotonic **deque** also expires old items from the front, which gives the sliding window maximum or minimum in O(n).
- Store indexes, choose `<` or `<=` carefully, and suspect this pattern whenever a question asks for the nearest bigger or smaller neighbour.
