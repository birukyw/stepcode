# Queues, Ring Buffers & collections.deque

If a stack is a pile of plates, a **queue** is a line at a shop. People join at the back and are served from the front: first in, first out, or **FIFO**. Queues schedule print jobs, buffer network packets, run breadth-first searches and keep fairness wherever order of arrival matters. This lesson builds one that is genuinely fast, and then shows how to bound it.

## Why a list is the wrong queue

A list makes `append` cheap but `pop(0)` expensive, since every remaining item must shift left. Here is how much shifting a queue of `n` items causes if you drain it that way:

```python
def drain_with_list(n):
    shifts = 0
    size = n
    while size:
        shifts += size - 1       # everything after the front moves
        size -= 1
    return shifts

print(drain_with_list(1000))
print(drain_with_list(100_000))
```

```text
499500
4999950000
```

Draining 100,000 items costs five billion moves. A queue needs both ends to be cheap.

## deque

`collections.deque`, short for "double-ended queue" and pronounced "deck", is built for exactly this. Adding and removing at **either** end is O(1).

```python
from collections import deque

line = deque()
line.append("Ada")
line.append("Linus")
line.append("Grace")
print(line)

print(line.popleft())
print(line.popleft())
print(line)
print(len(line), line[0])
```

```text
deque(['Ada', 'Linus', 'Grace'])
Ada
Linus
deque(['Grace'])
1 Grace
```

The vocabulary: `append` is **enqueue** (join the back), `popleft` is **dequeue** (leave the front), and `line[0]` peeks at the front. It also has `appendleft` and `pop` for working with the other end. Do not use `line[i]` for the middle in hot loops: indexing in the interior of a deque is O(n).

## Simulating a queue

A round-robin scheduler lets each task run for a fixed time slice, then sends it to the back of the line if it has work left:

```python
from collections import deque

def round_robin(tasks, slice_len):
    queue = deque(tasks)          # (name, remaining time)
    order = []
    while queue:
        name, remaining = queue.popleft()
        run = min(slice_len, remaining)
        order.append((name, run))
        if remaining > run:
            queue.append((name, remaining - run))
    return order

print(round_robin([("A", 5), ("B", 2), ("C", 4)], 2))
```

```text
[('A', 2), ('B', 2), ('C', 2), ('A', 2), ('C', 2), ('A', 1)]
```

Everyone gets a fair turn. This is how operating systems share a processor.

## Breadth-first search preview

Where a stack explores one branch deeply, a queue explores **level by level**: everything one step away, then everything two steps away. That makes it the tool for shortest paths in an unweighted graph:

```python
from collections import deque

graph = {"A": ["B", "C"], "B": ["D"], "C": ["D", "E"], "D": ["F"], "E": ["F"], "F": []}

def bfs_order(start):
    seen = {start}
    queue = deque([start])
    order = []
    while queue:
        node = queue.popleft()
        order.append(node)
        for nxt in graph[node]:
            if nxt not in seen:
                seen.add(nxt)
                queue.append(nxt)
    return order

print(bfs_order("A"))
```

```text
['A', 'B', 'C', 'D', 'E', 'F']
```

Compare it with the depth-first order from the previous lesson. Here `D` and `E` are reached before `F`, because they are closer to `A`. Module 2.5 builds on this.

## A sliding time window with a queue

A queue also handles "only the last N seconds matter". A rate limiter lets at most 3 requests through in any 10-second window by remembering the timestamps of recent requests and discarding the old ones:

```python
from collections import deque

class RateLimiter:
    def __init__(self, limit, window):
        self.limit = limit
        self.window = window
        self.times = deque()

    def allow(self, now):
        while self.times and self.times[0] <= now - self.window:
            self.times.popleft()          # forget old requests
        if len(self.times) < self.limit:
            self.times.append(now)
            return True
        return False

limiter = RateLimiter(3, 10)
for t in [0, 1, 2, 3, 9, 10, 11]:
    print(t, limiter.allow(t))
```

```text
0 True
1 True
2 True
3 False
9 False
10 True
11 True
```

At time 3 there are already three requests in the window, so the fourth is refused. By time 10 the request from time 0 has expired. Every request is added once and removed at most once, so each call is **O(1) amortized**.

## Ring buffers: a queue with a fixed size

Sometimes you only ever want the **most recent N** items: the last 5 log lines, the last 100 temperature readings. A **ring buffer** keeps a fixed-size queue where adding to a full buffer automatically drops the oldest item. `deque` supports this directly with `maxlen`:

```python
from collections import deque

recent = deque(maxlen=3)
for n in range(1, 7):
    recent.append(n)
    print(list(recent))
```

```text
[1]
[1, 2]
[1, 2, 3]
[2, 3, 4]
[3, 4, 5]
[4, 5, 6]
```

Once it is full, every append pushes the oldest item out the other end. Memory use never grows, however long the program runs.

A moving average is a natural use:

```python
from collections import deque

def moving_average(values, size):
    window = deque(maxlen=size)
    out = []
    for v in values:
        window.append(v)
        out.append(round(sum(window) / len(window), 2))
    return out

print(moving_average([10, 20, 30, 40, 50], 3))
```

```text
[10.0, 15.0, 20.0, 30.0, 40.0]
```

The name "ring" comes from how it is usually implemented: a fixed array whose end wraps around to its start, with an index that keeps cycling using the `%` operator from module 1.1.

## Stack, queue or deque?

| You need | Use |
|---|---|
| Most recent first (undo, backtracking, DFS) | stack (list) |
| Oldest first (scheduling, BFS, fairness) | queue (`deque`) |
| Both ends | `deque` |
| Only the last N items | `deque(maxlen=N)` |

## Common mistakes

- **Using `list.pop(0)` as a queue.** O(n) per removal. Use `deque.popleft()`.
- **Indexing into the middle of a `deque` in a loop.** It is O(n). Use a list if you need random access.
- **Forgetting that `maxlen` silently drops items.** That is the point, but do not rely on it by accident.
- **Dequeuing from an empty queue.** Check `if queue:` first, or expect `IndexError`.
- **Mixing up which end is which.** `append` and `popleft` give FIFO. `append` and `pop` give a stack.

+++ Solutions
```python
from collections import deque

people = deque(range(1, 8))
order = []
while people:
    people.rotate(-2)        # skip two, the third is now at the front
    order.append(people.popleft())
print(order)   # [3, 6, 2, 7, 5, 1, 4]
```

```python
from collections import deque

def last_n_lines(lines, n):
    return list(deque(lines, maxlen=n))

print(last_n_lines(["a", "b", "c", "d", "e"], 3))   # ['c', 'd', 'e']
```

```python
from collections import deque

arrivals = deque([0, 1, 2, 6])
free_at = 0
finish = []
while arrivals:
    start = max(free_at, arrivals.popleft())
    free_at = start + 3
    finish.append(free_at)
print(finish)   # [3, 6, 9, 12]
```

BFS must handle the oldest discovered node first, so that nodes closer to the start are finished before farther ones: that is FIFO. DFS wants the most recently discovered node, so it can keep following a branch: that is LIFO.

## Recap

- A queue is first-in, first-out. `collections.deque` gives O(1) `append` (enqueue) and `popleft` (dequeue).
- A list is a poor queue because `pop(0)` shifts every item.
- Queues power scheduling, breadth-first search (level by level) and time-window rate limiters.
- `deque(maxlen=N)` is a ring buffer that keeps the latest N items and drops the oldest automatically.
- Stack for "most recent first", queue for "oldest first", deque for both ends.
