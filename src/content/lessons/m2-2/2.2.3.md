# Stacks & Recursive Call Frames

A **stack** is the simplest data structure there is, and one of the most useful. It holds items in a pile, and you may only touch the **top**. Browsers use one for the Back button, editors for Undo, and Python itself for the call stack you met in lesson 1.5.3. This lesson shows how to build and use stacks, and why every recursive algorithm secretly has a stack inside it.

## Last in, first out

Think of a stack of plates. You add a plate to the top, and you take a plate from the top. The last plate in is the first one out: **LIFO**.

A Python list already works as a stack. `append` pushes onto the top and `pop()` removes from it, and both are O(1):

```python
stack = []
stack.append("a")
stack.append("b")
stack.append("c")
print(stack)

print(stack.pop())
print(stack.pop())
print(stack)
print(stack[-1])
```

```text
['a', 'b', 'c']
c
b
['a']
a
```

`stack[-1]` is a **peek**: look at the top without removing it. Popping from an empty stack raises an `IndexError`, so check `if stack:` first.

## Reversing with a stack

Pushing everything and then popping everything reverses the order, because LIFO flips it:

```python
def reverse_text(text):
    stack = []
    for ch in text:
        stack.append(ch)
    out = ""
    while stack:
        out += stack.pop()
    return out

print(reverse_text("stack"))
```

```text
kcats
```

## Matching brackets

This is the problem stacks were made for. Is every bracket in a string properly closed and nested? `"([]{})"` is fine, `"([)]"` is not.

The insight: the bracket you must close **next** is always the most recently opened one, which is exactly the top of a stack.

```python
def balanced(text):
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for ch in text:
        if ch in "([{":
            stack.append(ch)
        elif ch in pairs:
            if not stack or stack.pop() != pairs[ch]:
                return False
    return not stack

for s in ["([]{})", "([)]", "((", "", "}"]:
    print(repr(s), balanced(s))
```

```text
'([]{})' True
'([)]' False
'((' False
'' True
'}' False
```

Three ways it can fail, and the code covers each: a closer with nothing to match (`}`), a closer that does not match the top (`([)]`), and openers left over at the end (`((`). It runs in **O(n)**.

## Evaluating expressions

Reverse Polish notation (RPN) writes `3 + 4` as `3 4 +`: operands first, operator after. It needs no brackets and no precedence rules, and a stack evaluates it directly. Push numbers. When you meet an operator, pop two, apply it, and push the result.

```python
def eval_rpn(tokens):
    stack = []
    for t in tokens:
        if t in ("+", "-", "*", "/"):
            b = stack.pop()
            a = stack.pop()
            if t == "+":
                stack.append(a + b)
            elif t == "-":
                stack.append(a - b)
            elif t == "*":
                stack.append(a * b)
            else:
                stack.append(a / b)
        else:
            stack.append(float(t))
    return stack[0]

print(eval_rpn(["3", "4", "+"]))
print(eval_rpn(["2", "1", "+", "3", "*"]))
print(eval_rpn(["10", "2", "8", "*", "+", "3", "-"]))
```

```text
7.0
9.0
23.0
```

`2 1 + 3 *` means `(2 + 1) * 3`. Note the order when popping: the **second** operand comes off first, so `b = pop()` before `a = pop()` matters for `-` and `/`. Calculators and compilers use exactly this idea.

## Undo and history

A stack naturally models "most recent first":

```python
history = []
text = ""

def type_text(new):
    global text
    history.append(text)
    text += new

def undo():
    global text
    if history:
        text = history.pop()

type_text("Hello")
type_text(", world")
print(text)
undo()
print(text)
undo()
print(repr(text))
```

```text
Hello, world
Hello
''
```

Each edit saves the previous state on a stack, and Undo pops it back. (This uses `global`, which lesson 1.5.3 advised against, to keep the example short. A real editor would bundle the state into one object.)

## The call stack is a stack

Lesson 1.5.3 described how Python keeps a stack of **frames**, one per running function call. That is not an analogy: it is literally a stack, and recursion is just it growing and shrinking.

```python
def countdown(n):
    if n == 0:
        print("liftoff")
        return
    print(n)
    countdown(n - 1)
    print("back in", n)

countdown(3)
```

```text
3
2
1
liftoff
back in 1
back in 2
back in 3
```

Each call pushes a frame. The "back in" lines come out in reverse as frames are popped. The deepest call finishes first.

## Turning recursion into an explicit stack

Python limits how deep recursion can go, because every frame uses memory. Deep recursion raises a `RecursionError`. You can avoid the limit by replacing the call stack with **your own** stack, and the logic stays the same.

Visiting every node of a nested structure is a good example:

```python
def flatten_recursive(items):
    out = []
    for item in items:
        if isinstance(item, list):
            out.extend(flatten_recursive(item))
        else:
            out.append(item)
    return out

def flatten_iterative(items):
    out = []
    stack = [iter(items)]
    while stack:
        try:
            item = next(stack[-1])
        except StopIteration:
            stack.pop()
            continue
        if isinstance(item, list):
            stack.append(iter(item))
        else:
            out.append(item)
    return out

data = [1, [2, [3, 4]], 5, [[6]]]
print(flatten_recursive(data))
print(flatten_iterative(data))
```

```text
[1, 2, 3, 4, 5, 6]
[1, 2, 3, 4, 5, 6]
```

The second version has no recursion at all, so it works at any nesting depth. The stack holds "where I was in each level", which is exactly what the call stack held for you in the first version.

## Depth-first search preview

Exploring a maze, a file tree or a graph by always following the most recent branch first is **depth-first search**, and with a stack it is a short loop:

```python
graph = {"A": ["B", "C"], "B": ["D"], "C": ["D", "E"], "D": [], "E": []}

def dfs(start):
    seen = []
    stack = [start]
    while stack:
        node = stack.pop()
        if node in seen:
            continue
        seen.append(node)
        stack.extend(reversed(graph[node]))
    return seen

print(dfs("A"))
```

```text
['A', 'B', 'D', 'C', 'E']
```

You will build this properly in module 2.5. The shape is worth remembering: pop a node, mark it, push its neighbours.

## Common mistakes

- **Popping an empty stack.** Check `if stack` first.
- **Forgetting leftover items.** For bracket matching, an empty stack at the end is part of the answer.
- **Popping operands in the wrong order** in RPN, which breaks subtraction and division.
- **Using `list.pop(0)`** for a stack. It is O(n). The top is the **end** of the list.
- **Unbounded recursion.** Without a base case, the stack overflows.

## Recap

- A stack is last-in, first-out. A Python list works: `append` to push, `pop()` to pop, `[-1]` to peek, all O(1).
- Stacks solve matching and nesting problems (brackets), expression evaluation (RPN), and undo history.
- The call stack is a real stack of frames, and recursion is that stack growing and shrinking.
- Any recursion can be turned into a loop with an explicit stack, which avoids the recursion limit.
- Depth-first search is a stack loop: pop a node, mark it, push its neighbours.
