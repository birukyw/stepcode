# Singly & Doubly Linked Lists

A Python list keeps its items side by side in one block of memory, which is why inserting at the front is slow. A **linked list** takes the opposite approach: every item lives in its own small object, and each object holds a **pointer** to the next one. Nothing has to move to make room, so inserting is cheap, but jumping straight to the 500th item is not. Understanding that trade-off is the point of this lesson.

## A node

The building block is a **node**: a value plus a reference to the next node. We need a way to make our own kind of object, which is what a `class` does. Classes get a proper treatment in Track 3, so for now read this as "a template for a small record":

```python
class ListNode:
    def __init__(self, val, next=None):
        self.val = val
        self.next = next

a = ListNode(10)
b = ListNode(20)
a.next = b

print(a.val)
print(a.next.val)
print(b.next)
```

```text
10
20
None
```

`ListNode(10)` creates a node whose `val` is 10 and whose `next` is `None`. Setting `a.next = b` links the two. The last node's `next` is `None`, the marker for "the end". You already know why this works: names are labels, and a node's `next` is a label pointing at another node.

## Building a chain

Writing nodes by hand gets tedious, so here is a helper that builds a list from a Python list, and one that turns it back so you can see it:

```python
class ListNode:
    def __init__(self, val, next=None):
        self.val = val
        self.next = next

def build(values):
    head = None
    for v in reversed(values):
        head = ListNode(v, head)
    return head

def to_list(head):
    out = []
    while head:
        out.append(head.val)
        head = head.next
    return out

head = build([1, 2, 3, 4])
print(to_list(head))
```

```text
[1, 2, 3, 4]
```

`head` is the entry point: the only node you hold on to. Everything else is reached by following `next`. `build` works from the back, so each new node points at the chain built so far.

## Traversal

To visit every node, follow the pointers until you fall off the end:

```python
class ListNode:
    def __init__(self, val, next=None):
        self.val = val
        self.next = next

def build(values):
    head = None
    for v in reversed(values):
        head = ListNode(v, head)
    return head

def length(head):
    count = 0
    while head:
        count += 1
        head = head.next
    return count

def find(head, target):
    while head:
        if head.val == target:
            return True
        head = head.next
    return False

head = build([5, 8, 13, 21])
print(length(head))
print(find(head, 13), find(head, 99))
```

```text
4
True False
```

Both are **O(n)**: there is no way to reach the middle without walking through everything before it. This is the big cost of linked lists. **There is no `items[i]`.**

## Inserting at the front: O(1)

Making a new node that points at the old head is all it takes:

```python
class ListNode:
    def __init__(self, val, next=None):
        self.val = val
        self.next = next

def build(values):
    head = None
    for v in reversed(values):
        head = ListNode(v, head)
    return head

def to_list(head):
    out = []
    while head:
        out.append(head.val)
        head = head.next
    return out

def push_front(head, val):
    return ListNode(val, head)

head = build([2, 3, 4])
head = push_front(head, 1)
print(to_list(head))
```

```text
[1, 2, 3, 4]
```

Compare that with `list.insert(0, x)`, which shifts every item. The linked version touches exactly one pointer, whatever the length.

## Inserting and deleting in the middle

Once you are **standing next to** the spot, inserting or removing is just rewiring pointers, with no shifting at all:

```python
class ListNode:
    def __init__(self, val, next=None):
        self.val = val
        self.next = next

def build(values):
    head = None
    for v in reversed(values):
        head = ListNode(v, head)
    return head

def to_list(head):
    out = []
    while head:
        out.append(head.val)
        head = head.next
    return out

head = build([1, 2, 4, 5])

# insert 3 after the node holding 2
node = head.next            # the node with 2
node.next = ListNode(3, node.next)
print(to_list(head))

# delete the node after the node holding 1
head.next = head.next.next
print(to_list(head))
```

```text
[1, 2, 3, 4, 5]
[1, 3, 4, 5]
```

The order of the assignments matters. In the insert, the new node must point at the old `node.next` **before** `node.next` is overwritten, which is why they happen in a single statement. Write it the other way round and you lose the rest of the chain.

## The dummy node trick

Deleting the **head** is a special case, because there is no node before it to rewire. A **dummy** (or sentinel) node placed before the head removes the special case:

```python
class ListNode:
    def __init__(self, val, next=None):
        self.val = val
        self.next = next

def build(values):
    head = None
    for v in reversed(values):
        head = ListNode(v, head)
    return head

def to_list(head):
    out = []
    while head:
        out.append(head.val)
        head = head.next
    return out

def remove_all(head, target):
    dummy = ListNode(0, head)
    prev = dummy
    while prev.next:
        if prev.next.val == target:
            prev.next = prev.next.next
        else:
            prev = prev.next
    return dummy.next

print(to_list(remove_all(build([7, 1, 7, 2, 7]), 7)))
print(to_list(remove_all(build([7, 7]), 7)))
```

```text
[1, 2]
[]
```

Because `prev` starts at the dummy, removing the first real node works exactly like removing any other. At the end, `dummy.next` is the new head.

## Reversing a list

The classic exercise. Walk along, and flip each pointer to point backwards. You need three names: the node you are on, the one behind it, and the one ahead that you must not lose.

```python
class ListNode:
    def __init__(self, val, next=None):
        self.val = val
        self.next = next

def build(values):
    head = None
    for v in reversed(values):
        head = ListNode(v, head)
    return head

def to_list(head):
    out = []
    while head:
        out.append(head.val)
        head = head.next
    return out

def reverse(head):
    prev = None
    curr = head
    while curr:
        nxt = curr.next      # remember what comes next
        curr.next = prev     # flip the pointer
        prev = curr          # step forward
        curr = nxt
    return prev

print(to_list(reverse(build([1, 2, 3, 4, 5]))))
```

```text
[5, 4, 3, 2, 1]
```

It takes one pass and **O(1) extra space**: the nodes are reused, with only their pointers changed. If you forget the line that saves `nxt`, you lose the rest of the list the instant you overwrite `curr.next`.

## Doubly linked lists

A **doubly linked list** adds a `prev` pointer to each node, so you can walk both ways and delete a node given only that node.

```python
class DNode:
    def __init__(self, val):
        self.val = val
        self.prev = None
        self.next = None

a, b, c = DNode(1), DNode(2), DNode(3)
a.next, b.prev = b, a
b.next, c.prev = c, b

# delete b using only b itself
b.prev.next = b.next
b.next.prev = b.prev

print(a.next.val, c.prev.val)
```

```text
3 1
```

The price is an extra pointer per node and twice as many pointers to keep consistent. Doubly linked lists are what let a cache evict its oldest entry in O(1), as module 2.3 shows.

## Linked list or Python list?

| Operation | Python list | Linked list |
|---|---|---|
| Access item `i` | O(1) | O(n) |
| Insert/delete at the front | O(n) | O(1) |
| Insert/delete after a node you hold | O(n) | O(1) |
| Search by value | O(n) | O(n) |
| Memory per item | small | larger (a whole object plus a pointer) |

In everyday Python code a list is almost always the right choice, because its memory layout is friendlier to the processor. Linked lists matter because they teach pointer thinking, because they underlie other structures (queues, caches, hash-table chains), and because interviews ask about them constantly.

## Common mistakes

- **Losing the rest of the list.** Overwriting `node.next` before saving what it pointed to.
- **Forgetting the empty list.** `head` is `None`. Check before using `head.next`.
- **Looping on `head.next` when you meant `head`.** That skips the last node.
- **Special-casing the head instead of using a dummy node.**
- **Treating `==` on nodes as comparing values.** Compare `node.val`.

```python
def push_back(head, val):
    node = ListNode(val)
    if head is None:
        return node
    tail = head
    while tail.next:
        tail = tail.next
    tail.next = node
    return head
```

It is O(n), because you must walk to the end. Keeping a separate `tail` reference makes it O(1).

```python
def insert_sorted(head, val):
    dummy = ListNode(0, head)
    prev = dummy
    while prev.next and prev.next.val < val:
        prev = prev.next
    prev.next = ListNode(val, prev.next)
    return dummy.next
```

The original `head` still points at the node holding 1, which is now the **last** node of the reversed list. Reversing changes the pointers inside the nodes, not what your variable refers to, so always use the returned head.

## Recap

- A linked list is a chain of nodes, each holding a value and a pointer to the next. The last `next` is `None`.
- No indexing: reaching item `i` is O(n). In exchange, inserting or deleting next to a node you hold is O(1).
- A **dummy node** removes the special case for the head. Reversing needs three pointers and one pass.
- A doubly linked list adds `prev`, allowing deletion given just the node.
- Think in pointers: always save a reference before you overwrite one.
