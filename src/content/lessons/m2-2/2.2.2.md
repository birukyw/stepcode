# Fast & Slow Pointers (Floyd's Cycle)

Picture two runners on a track. One runs twice as fast as the other. On a straight road the fast one simply reaches the finish first. On a **circular** track, the fast runner laps the slow one and the two **meet**. That one observation solves a family of linked list problems with no extra memory, and it is one of the neatest tricks in computer science.

## Setup

Every example in this lesson uses the same small helpers:

```python
class ListNode:
    def __init__(self, val, next=None):
        self.val = val
        self.next = next

def build(values):
    head = None
    for v in reversed(values):
        head = ListNode(v, head)
    return head

def to_list(head):
    out = []
    while head:
        out.append(head.val)
        head = head.next
    return out

head = build([1, 2, 3, 4, 5])
print(to_list(head))
```

```text
[1, 2, 3, 4, 5]
```

## Finding the middle

How do you find the middle of a linked list when you do not know its length? You could count first, then walk halfway: two passes. With two pointers it takes one. Move `slow` one step and `fast` two steps. When `fast` reaches the end, `slow` is in the middle.

```python
class ListNode:
    def __init__(self, val, next=None):
        self.val = val
        self.next = next

def build(values):
    head = None
    for v in reversed(values):
        head = ListNode(v, head)
    return head

def middle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
    return slow.val

print(middle(build([1, 2, 3, 4, 5])))
print(middle(build([1, 2, 3, 4, 5, 6])))
print(middle(build([9])))
```

```text
3
4
9
```

For an even length there are two middles, and this version returns the second one. The loop condition `fast and fast.next` is important: it stops `fast` from stepping off the end when it takes its second step.

## Detecting a cycle

A linked list can contain a **cycle**: some node's `next` points back to an earlier node, so following pointers never ends. A plain traversal would loop forever.

The obvious fix is to remember every node you have seen in a set. That works, in O(n) time, but uses O(n) memory. **Floyd's algorithm** uses O(1) memory:

```python
class ListNode:
    def __init__(self, val, next=None):
        self.val = val
        self.next = next

def build(values):
    head = None
    for v in reversed(values):
        head = ListNode(v, head)
    return head

def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:
            return True
    return False

straight = build([1, 2, 3, 4])
print(has_cycle(straight))

looped = build([1, 2, 3, 4, 5])
tail = looped
while tail.next:
    tail = tail.next
tail.next = looped.next.next      # the last node points back at the node holding 3
print(has_cycle(looped))
```

```text
False
True
```

Notice `slow is fast`, comparing **identity**, not `==`. Two different nodes may hold equal values.

### Why it works

If there is no cycle, `fast` falls off the end, the loop stops, and you return `False`.

If there is a cycle, both pointers eventually enter it. Inside the loop, the gap between them shrinks by exactly **one** step per iteration (fast gains one on slow). A gap that shrinks by one each time must reach zero, so they meet. The fast pointer can never jump over the slow one, because it only closes the gap by one.

## Finding where the cycle starts

Knowing a cycle exists is good. Finding the node where it **begins** is better, and it has a lovely proof.

After the pointers meet, move one pointer back to the head. Then advance **both one step at a time**. They meet again exactly at the start of the cycle.

```python
class ListNode:
    def __init__(self, val, next=None):
        self.val = val
        self.next = next

def build(values):
    head = None
    for v in reversed(values):
        head = ListNode(v, head)
    return head

def cycle_start(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:
            slow = head
            while slow is not fast:
                slow = slow.next
                fast = fast.next
            return slow
    return None

head = build([10, 20, 30, 40, 50])
tail = head
while tail.next:
    tail = tail.next
tail.next = head.next.next       # cycle begins at the node holding 30

print(cycle_start(head).val)
print(cycle_start(build([1, 2, 3])))
```

```text
30
None
```

### The reasoning, briefly

Let the straight stretch before the cycle have length `a`, and let the pointers meet `b` steps into the cycle, with `c` steps remaining to get back to the entrance, so the cycle length is `b + c`.

When they meet, slow has walked `a + b`, and fast has walked twice that, `2(a + b)`. Fast has also walked `a + b` plus some whole number of laps `k(b + c)`. Setting those equal gives `a = k(b + c) - b`, which means `a = c` plus whole laps. So a pointer starting at the head and one starting at the meeting point, both moving one step at a time, arrive at the entrance together.

You do not need to memorise the algebra. Remember the shape of the result, and that it can be proved.

## Other uses

The idea generalises beyond linked lists to anything that can be walked step by step.

### Detecting a loop in a number sequence

Repeatedly applying a function to its own output eventually repeats, or reaches a fixed point. A "happy number" is one where repeatedly summing the squares of the digits reaches 1:

```python
def next_value(n):
    total = 0
    while n:
        n, d = divmod(n, 10)
        total += d * d
    return total

def is_happy(n):
    slow = n
    fast = next_value(n)
    while fast != 1 and slow != fast:
        slow = next_value(slow)
        fast = next_value(next_value(fast))
    return fast == 1

print(is_happy(19))
print(is_happy(2))
```

```text
True
False
```

No set of visited numbers is needed: if the sequence loops without reaching 1, the two pointers meet.

### The nth node from the end

Start two pointers at the head. Advance the first one `n` steps. Then move both until the first hits the end. The second is now `n` from the end:

```python
class ListNode:
    def __init__(self, val, next=None):
        self.val = val
        self.next = next

def build(values):
    head = None
    for v in reversed(values):
        head = ListNode(v, head)
    return head

def nth_from_end(head, n):
    lead = head
    for _ in range(n):
        lead = lead.next
    follow = head
    while lead:
        lead = lead.next
        follow = follow.next
    return follow.val

print(nth_from_end(build([1, 2, 3, 4, 5]), 2))
```

```text
4
```

The two pointers stay `n` apart the whole way, so when one reaches the end, the other is `n` back. It is a window between two pointers, like the ones in module 2.1.

## Common mistakes

- **Writing `while fast.next.next`** instead of `while fast and fast.next`. It crashes on short lists.
- **Using `==` instead of `is`** to compare nodes.
- **Forgetting the empty list.** `head` may be `None`.
- **Moving only one pointer per loop** in the start-of-cycle phase. Both move one step.
- **Using a visited set** when the problem asks for O(1) space.

```python
def reverse(head):
    prev = None
    while head:
        head.next, prev, head = prev, head, head.next
    return prev

def is_palindrome_list(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
    second = reverse(slow)
    first = head
    while second:
        if first.val != second.val:
            return False
        first = first.next
        second = second.next
    return True
```

```python
def cycle_length(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:
            count = 1
            node = slow.next
            while node is not slow:
                node = node.next
                count += 1
            return count
    return 0
```

```python
def remove_nth_from_end(head, n):
    dummy = ListNode(0, head)
    lead = follow = dummy
    for _ in range(n + 1):
        lead = lead.next
    while lead:
        lead = lead.next
        follow = follow.next
    follow.next = follow.next.next
    return dummy.next
```

With speeds of 1 and 2 the gap changes by exactly 1 each step, so it must pass through 0. With speeds 1 and 3 the gap changes by 2 and can step over 0 and miss it, for example if the cycle length is such that the parity is wrong.

## Recap

- Two pointers moving at different speeds solve linked list problems in one pass with O(1) memory.
- When `fast` (2 steps) reaches the end, `slow` (1 step) is at the middle.
- If there is a cycle, the gap between the pointers shrinks by 1 each step, so they must meet. That is Floyd's algorithm.
- To find the cycle entrance, reset one pointer to the head and move both one step at a time. They meet at the entrance.
- The same pattern finds loops in sequences and the nth node from the end. Use `is` to compare nodes, and guard with `while fast and fast.next`.
