# Multi-Way Decision Trees

Two branches are often not enough. Grades have five levels, shipping rates have several weight bands, and game loot has tiers. This lesson covers `elif`, the tool for choosing among many options, and the single most important rule about it: **order matters**.

## The elif chain

`elif` is short for "else if". Python checks conditions from top to bottom and runs the block for the **first** one that is true. After that block runs, the rest of the chain is skipped.

```python
score = 82

if score >= 90:
    grade = "A"
elif score >= 80:
    grade = "B"
elif score >= 70:
    grade = "C"
else:
    grade = "F"

print(grade)
```

```text
B
```

With a score of 82, the first test fails, the second passes, and Python assigns `"B"` and jumps to the end. The `>= 70` test is never even evaluated.

Notice how the chain relies on the earlier tests. By the time Python checks `score >= 80`, it already knows the score is below 90. That is why the second condition does not need to say "and less than 90".

A chain can have any number of `elif` blocks. The final `else` is optional and catches everything that no earlier condition matched.

## elif versus separate ifs

Replacing `elif` with plain `if` changes the meaning. Every `if` is checked independently, so several blocks can run.

```python
temperature = 35

if temperature > 30:
    print("hot")
if temperature > 20:
    print("warm")
if temperature > 10:
    print("mild")
```

```text
hot
warm
mild
```

All three are true, so all three run. With `elif`, only `hot` would print. Choose by asking one question: are these options **mutually exclusive**, where exactly one applies? Use `elif`. Can more than one apply at once? Use separate `if` statements.

## Order and specificity

Because the first match wins, you must put the most specific condition first. Here is a loot classifier with a bug:

```python
roll = 95

if roll >= 50:
    tier = "rare"
elif roll >= 90:
    tier = "legendary"
else:
    tier = "common"

print(tier)
```

```text
rare
```

A roll of 95 should be legendary, but `roll >= 50` is true for it, so the chain stops at the first branch. The `>= 90` branch can never run. This is called a **shadowed** condition: an earlier, broader test hides a later, narrower one.

The fix is to order from most specific to least specific:

```python
roll = 95

if roll >= 90:
    tier = "legendary"
elif roll >= 50:
    tier = "rare"
else:
    tier = "common"

print(tier)
```

```text
legendary
```

> **Tip:** When a chain gives the wrong answer for one input, trace it by hand. Walk through the conditions in order and note the first one that is true. A shadowed branch shows up immediately.

## Getting boundaries right

Most decision bugs happen at the edges, so test the values where the answer changes. For a rule such as "free under 5, child 5 to 12, adult 13 to 64, senior 65 and over", the values that matter are 4, 5, 12, 13, 64 and 65.

```python
age = 13

if age < 5:
    category = "infant"
elif age < 13:
    category = "child"
elif age < 65:
    category = "adult"
else:
    category = "senior"

print(category)
```

```text
adult
```

Writing each condition as an upper bound (`< 5`, `< 13`, `< 65`) lets the chain handle the lower bounds automatically. Compare that with the alternative of writing both ends of every range, which is longer and invites mistakes.

## Using else for the unexpected

An `else` at the end is a good place to deal with values you did not plan for. For input, that often means rejecting it.

```python
answer = input("Continue? (yes/no): ").lower()

if answer == "yes":
    print("Continuing")
elif answer == "no":
    print("Stopping")
else:
    print("Please type yes or no")
```

Calling `.lower()` first means `YES`, `Yes` and `yes` all work.

## Default, then override

An alternative to a long chain is to set a default and let conditions adjust it. This suits cases where only a few values differ from the norm.

```python
shipping = 5.00
weight = 12

if weight > 10:
    shipping = 9.50
if weight > 25:
    shipping = 18.00

print(shipping)
```

```text
9.5
```

Here the two `if` statements are deliberately independent: a weight of 30 passes both, and the later one overrides the earlier. Both styles are valid, so pick whichever makes the rule easiest to read.

## Decision tables

When you are unsure how to structure a chain, write the rule as a table first.

| Condition | Result |
|---|---|
| score >= 90 | A |
| score >= 80 | B |
| score >= 70 | C |
| otherwise | F |

Reading from top to bottom gives you the `elif` chain directly, in the correct order. If you cannot write the table cleanly, the logic is not clear yet, and that is better discovered before you write code.

## Common mistakes

- **Wrong order.** Broad conditions above narrow ones hide the narrow ones.
- **Using `if` where you meant `elif`.** Several blocks run when you expected one.
- **Off-by-one boundaries.** `>` versus `>=`. Always test the exact boundary values.
- **Repeating conditions.** Writing `elif score >= 80 and score < 90` when the chain already guarantees the upper bound.
- **Forgetting the final `else`.** An input outside every range silently does nothing.

## Recap

- `elif` chains check conditions top to bottom and run only the first match.
- Separate `if` statements are independent, and several can run.
- Order from most specific to least specific, or earlier branches shadow later ones.
- Write ranges as upper bounds so the chain handles the lower bounds.
- Test boundary values, and use `else` to handle the unexpected.
