# Short-Circuiting & Truthiness

Conditions do not have to be comparisons. Python will happily use any value as a condition, and the logical operators do not always return booleans. These two behaviours, **truthiness** and **short-circuiting**, are behind many idiomatic Python patterns, and behind some subtle bugs.

## Truthy and falsy

When a value is used where a boolean is expected, Python converts it with `bool()`. A small, fixed set of values count as **falsy**. Everything else is **truthy**.

| Falsy | Truthy examples |
|---|---|
| `False` | `True` |
| `0`, `0.0` | `1`, `-5`, `0.1` |
| `""` (empty string) | `"a"`, `" "`, `"0"`, `"False"` |
| `[]`, `{}`, `()`, `set()` (empty collections) | `[0]`, `[None]`, `{"a": 1}` |
| `None` | almost everything else |

```python
print(bool(0), bool(1))
print(bool(""), bool("hello"))
print(bool("0"), bool(" "))
print(bool([]), bool([0]))
print(bool(None))
```

```text
False True
False True
True True
False True
False
```

Note `bool("0")` and `bool(" ")` are `True`. These strings are not empty, so the content is irrelevant. An empty collection is falsy, and a collection containing a falsy value is still non-empty, so `[0]` is truthy.

This lets you write conditions in the natural way:

```python
name = ""

if name:
    print("Hello,", name)
else:
    print("Please enter a name")
```

```text
Please enter a name
```

For collections, `if items:` reads as "if there are any items". Lists are covered fully in module 1.4. For now, a list is an ordered group of values written in square brackets.

## Do not compare to True

Writing `if x == True:` is a common beginner habit. It is longer, and worse, it behaves differently from `if x:` for values that are truthy but not equal to `True`.

```python
value = 5

print(value == True)
if value:
    print("truthy")
```

```text
False
truthy
```

`5 == True` is `False`, because `True` equals `1`, but `5` is perfectly truthy. Use the condition directly: `if value:`.

## and / or return an operand

`and` and `or` do not always return `True` or `False`. They return one of the **operands**.

- `a or b` returns `a` if `a` is truthy, otherwise `b`.
- `a and b` returns `a` if `a` is falsy, otherwise `b`.

```python
print(0 or 5)
print("" or "guest")
print("Ada" or "guest")
print(0 and 5)
print(3 and 5)
```

```text
5
guest
Ada
0
5
```

The first three lines show the most common use: supplying a **default**. If the left side is empty or missing, fall back to the right side.

```python
username = ""
display_name = username or "guest"
print(display_name)
```

```text
guest
```

## Short-circuit evaluation

Python evaluates `and` and `or` from left to right, and **stops as soon as the answer is known**.

- In `a and b`, if `a` is falsy the answer is already falsy, so `b` is never evaluated.
- In `a or b`, if `a` is truthy the answer is already truthy, so `b` is never evaluated.

This is not just an optimisation. It lets you write a safety check before a risky operation.

```python
denominator = 0
print(denominator != 0 and 10 / denominator > 1)
```

```text
False
```

The left side is `False`, so Python never tries `10 / denominator`. Reverse the order and it breaks:

```python error
denominator = 0
print(10 / denominator > 1 and denominator != 0)
```

```text
Traceback (most recent call last):
  File "main.py", line 2, in <module>
    print(10 / denominator > 1 and denominator != 0)
ZeroDivisionError: division by zero
```

The guard must come **first**. The same idea protects against missing data:

```python
items = []
first = items and items[0]
print(first)
```

```text
[]
```

When `items` is empty, `items and items[0]` stops at the falsy left side, so `items[0]`, which would raise an `IndexError`, never runs. When `items` has content, the expression returns the first element.

Short-circuiting also works the other way round. In `a or b`, the right side only runs if the left is falsy:

```python
cache = 0
result = cache or 10 * 10
print(result)
```

```text
100
```

## Testing for None

`None` means "no value". Compare against it with `is` and `is not`, not with `==`.

```python
result = None

if result is None:
    print("nothing yet")
if result is not None:
    print("has a value")
```

```text
nothing yet
```

The distinction from truthiness matters. `0` and `""` are falsy, but they are real values. If `0` is a valid answer (a score of zero, a balance of zero), then `if not value:` wrongly treats it as missing, and `if value is None:` is the correct test.

```python
score = 0

if not score:
    print("falsy: could be zero or missing")
if score is None:
    print("missing")
else:
    print("a real score of", score)
```

```text
falsy: could be zero or missing
a real score of 0
```

## any and all

Two built-in functions apply `or` and `and` across many values at once:

```python
checks = [True, 1, "ok"]
print(all(checks))
print(any([0, "", None]))
print(any([0, "", 7]))
```

```text
True
False
True
```

`all` is true when every value is truthy and `any` is true when at least one is. Both also short-circuit.

## Common mistakes

- **Treating `0` as missing.** `if not count:` is true for `0`. Use `is None` when zero is a legitimate value.
- **Putting the guard on the wrong side.** `x != 0 and 10 / x` is safe. `10 / x and x != 0` is not.
- **`== True` and `== False`.** Use the value or `not` directly.
- **Assuming `and` / `or` return booleans.** They return an operand. That is useful, but surprising if you print the result.
- **`"False"` is truthy.** A string that says `False` is non-empty, so it counts as true.

## Practice

1. A user types a name into `input()`. Print `Hello, <name>` if they typed something, otherwise print `Hello, stranger`. Do it twice: once with `if`/`else`, and once with `or`.
2. Write a safe average. Given `total = 0` and `count = 0`, print `total / count` only when `count` is not zero, and print `no data` otherwise.
3. Predict the output, then check:

```python
print(None or 0 or "" or "fallback")
print(1 and 2 and 3)
print(1 and 0 and 3)
```

+++ Solutions
```python
name = input("Name: ")
if name:
    print("Hello,", name)
else:
    print("Hello, stranger")

print("Hello,", name or "stranger")
```

```python
total = 0
count = 0
if count != 0:
    print(total / count)
else:
    print("no data")
```

The output is `fallback`, then `3`, then `0`. `or` returns the first truthy operand, or the last operand if none is truthy. `and` returns the first falsy operand, or the last operand if all are truthy.

## Recap

- Falsy values: `False`, `0`, `0.0`, `""`, empty collections and `None`. Everything else is truthy.
- Use `if x:` and `if not x:` directly. Never compare to `True`.
- `a or b` returns the first truthy operand, which is handy for defaults. `a and b` returns the first falsy one.
- Short-circuiting skips the right side when the answer is known, so put guards first.
- Use `is None` when `0` or `""` could be valid values.
