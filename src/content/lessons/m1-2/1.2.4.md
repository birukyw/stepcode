# Combining Logic Gates

Real conditions are rarely a single comparison. A discount applies if you are a member **and** the cart is large, a door opens if you have a key **or** an override code, an alert fires when the system is **not** healthy. Python's three logical operators let you combine simple questions into precise ones.

## and, or, not

| Operator | Meaning | True when |
|---|---|---|
| `a and b` | both | both `a` and `b` are true |
| `a or b` | either | at least one of `a`, `b` is true |
| `not a` | opposite | `a` is false |

```python
age = 25
has_ticket = True

if age >= 18 and has_ticket:
    print("Welcome in")

if age < 18 or not has_ticket:
    print("Entry refused")
```

```text
Welcome in
```

Each side of `and` or `or` is a complete expression. That detail matters in a mistake covered below.

## Truth tables

A **truth table** lists every combination of inputs and the result. With two inputs there are four rows, and you can have Python print them for you:

```python
print("a      b      a and b   a or b")
print("True   True   ", True and True, "   ", True or True)
print("True   False  ", True and False, "  ", True or False)
print("False  True   ", False and True, "  ", False or True)
print("False  False  ", False and False, "  ", False or False)
```

```text
a      b      a and b   a or b
True   True    True     True
True   False   False    True
False  True    False    True
False  False   False    False
```

Two facts worth memorising:

- `and` is true only when **everything** is true.
- `or` is false only when **everything** is false.

## Precedence

When you mix operators without parentheses, Python applies `not` first, then `and`, then `or`. That is the same relationship as multiplication before addition.

```python
print(True or False and False)
print((True or False) and False)
print(not True or True)
print(not (True or True))
```

```text
True
False
True
False
```

On the first line `False and False` is evaluated before `or`, giving `True or False`, which is `True`. Parentheses change that completely, as the second line shows. Do not rely on memory here. Whenever you mix `and` with `or`, add parentheses so the intent is obvious.

## De Morgan's laws

Negating a combined condition has a neat shortcut. To distribute `not` across `and` or `or`, flip the operator and negate each part.

- `not (a and b)` is the same as `(not a) or (not b)`
- `not (a or b)` is the same as `(not a) and (not b)`

You can confirm both with a truth table, or simply read them aloud. "It is **not** true that I have both a ticket and an ID" means "I am missing a ticket **or** I am missing an ID".

```python
has_ticket = True
has_id = False

print(not (has_ticket and has_id))
print((not has_ticket) or (not has_id))
```

```text
True
True
```

These laws are practical. They let you rewrite a condition that reads awkwardly into one that reads naturally.

```python
temperature = 40

# Awkward
if not (temperature >= 10 and temperature <= 30):
    print("Outside comfort range")

# Clearer: apply De Morgan's law
if temperature < 10 or temperature > 30:
    print("Outside comfort range")
```

Both versions print the same thing. The second reads as the sentence you would say aloud.

## The classic bug: x == 1 or 2

A condition such as `x == 1 or 2` looks like it asks whether `x` is 1 or 2. It does not. Python reads it as `(x == 1) or 2`, and the bare `2` is always truthy, so the whole expression is always true.

```python
x = 7

if x == 1 or 2:
    print("always runs")
```

```text
always runs
```

Each side of `or` must be a full comparison. There are two correct forms:

```python
x = 2

if x == 1 or x == 2:
    print("one or two")

if x in (1, 2):
    print("one or two")
```

```text
one or two
one or two
```

The `in` form scales much better when the list of options grows.

## Range checks

Two comparisons joined with `and` can be written as a chained comparison, as you saw earlier. To test for being outside a range, use `or`.

```python
x = 120

print(0 <= x <= 100)
print(x < 0 or x > 100)
```

```text
False
True
```

## XOR: exactly one

Sometimes you need "one or the other, but not both". Python has no `xor` keyword for booleans, but comparing two booleans with `!=` does it:

```python
a = True
b = False
print(a != b)
print(True != True)
```

```text
True
False
```

## Naming conditions

Long conditions become readable when you give the pieces names.

```python
age = 70
is_member = True
cart_total = 90

is_senior = age >= 65
big_cart = cart_total >= 80

if (is_senior or is_member) and big_cart:
    print("Discount applies")
```

```text
Discount applies
```

Reading the final line, you immediately see the rule without decoding the comparisons.

## Common mistakes

- **`x == 1 or 2`.** Repeat the comparison on both sides, or use `in`.
- **Mixing `and` and `or` with no parentheses.** The precedence is unintuitive.
- **Double negatives.** `if not x != 5` is hard to read. Write `if x == 5`.
- **Splitting a range wrongly.** `x < 0 and x > 100` can never be true. Outside a range is `or`.
- **Forgetting that `not` binds tightly.** `not a == b` means `not (a == b)`, which works, but write `a != b` instead.

```python
has_key = False
```

```python
year = int(input("Year: "))

```

By De Morgan's law: `a < 5 or b >= 3`.

## Recap

- `and` needs both sides true. `or` needs at least one. `not` flips.
- Precedence is `not`, then `and`, then `or`. Use parentheses when you mix them.
- De Morgan: `not (a and b)` equals `(not a) or (not b)`, and likewise for `or`.
- Each side of `and` and `or` must be a full expression: `x == 1 or x == 2`, or `x in (1, 2)`.
- Give long conditions named parts so they read like the rule.
