# Loop Control: break, continue & else

A plain loop visits every item. Real tasks often need to stop early when the answer is found, skip over items that do not qualify, or notice that a search finished without finding anything. Python gives you three tools for that: `break`, `continue` and the loop `else`.

## break: stop the loop now

`break` ends the loop immediately and execution resumes after it.

```python
for n in range(1, 100):
    if n * n > 200:
        print("First square above 200:", n * n)
        break
```

```text
First square above 200: 225
```

Without `break` the loop would keep checking numbers up to 99 long after the answer was known. `break` is how you express "I found it, stop searching".

## continue: skip to the next iteration

`continue` abandons the rest of the current iteration and jumps straight to the next one.

```python
for n in range(1, 10):
    if n % 2 == 0:
        continue
    print(n, end=" ")
print()
```

```text
1 3 5 7 9 
```

Even numbers hit `continue`, so `print` is skipped for them. This keeps the main logic unindented and flat. Compare it with the alternative of wrapping the whole body in `if n % 2 != 0:`. With a long body, `continue` plus an early filter reads much better.

## while True and break

Sometimes the natural shape of a loop is "do this forever until something tells me to stop". `while True` loops indefinitely, and `break` is the exit.

```python
count = 0

while True:
    count += 1
    if count ** 2 >= 50:
        break

print(count)
```

```text
8
```

This is the standard pattern for reading input until it is valid:

```python
while True:
    answer = input("Enter a positive number: ")
    if answer.isdigit() and int(answer) > 0:
        break
    print("That is not a positive number. Try again.")

print("You entered", answer)
```

Try it in the editor with `abc`, `-5`, `0` and then `12` on separate lines in the **Input** box. The first three are rejected, and the last one ends the loop.

## The else clause on a loop

Loops have an `else` clause, and it is one of the most misunderstood features in Python. The rule is simple: **the `else` block runs when the loop finishes normally, without hitting `break`**.

```python
for n in range(2, 6):
    if n == 7:
        print("found 7")
        break
else:
    print("7 was not in the range")
```

```text
7 was not in the range
```

The loop ran to the end without a `break`, so the `else` ran. Read it as "if no break happened". If a `break` had fired, the `else` would be skipped.

This is the natural way to write a search that needs to report failure.

## A real example: is it prime

A number is prime if no integer from 2 up to just below it divides it evenly. Search for a divisor, and if the search ends without finding one, the number is prime.

```python
n = 29

for d in range(2, n):
    if n % d == 0:
        print(n, "is not prime, divisible by", d)
        break
else:
    print(n, "is prime")
```

```text
29 is prime
```

Change `n` to `35` to see the other branch: it prints `35 is not prime, divisible by 5` and skips the `else`.

Without loop-`else` you would need a separate flag variable, set before the loop, changed inside it and tested after it. The `else` removes that extra bookkeeping.

You only need to test divisors up to the square root of `n`, because any larger divisor has a matching smaller one. That makes the search far faster for big numbers:

```python
n = 1_000_003

for d in range(2, int(n ** 0.5) + 1):
    if n % d == 0:
        print(n, "is not prime")
        break
else:
    print(n, "is prime")
```

```text
1000003 is prime
```

## break only exits one loop

When loops are nested, `break` and `continue` apply to the **innermost** loop only.

```python
for row in range(3):
    for col in range(3):
        if col == 2:
            break
        print(row, col)
```

```text
0 0
0 1
1 0
1 1
2 0
2 1
```

The `break` ends each inner loop when `col` reaches 2, but the outer loop carries on to the next `row`. To leave both loops at once you would need a flag, or to move the loops into a function, which module 1.5 covers.

## The pass statement

`pass` is a placeholder that does nothing. It is useful when a block is syntactically required but you have nothing to put there yet.

```python
for n in range(3):
    pass   # TODO
print("loop finished")
```

```text
loop finished
```

## break versus continue versus else

| Tool | Effect |
|---|---|
| `break` | Leave the loop entirely |
| `continue` | Skip to the next iteration |
| `else` on a loop | Runs if the loop ended **without** `break` |

## Common mistakes

- **Putting `else` at the wrong indentation.** It must line up with `for` or `while`, not with the `if` inside. An `else` under the `if` runs for **every** non-matching item.
- **`continue` before the update step in a `while` loop.** The state never changes, and the loop runs forever.
- **Expecting `break` to leave an outer loop.** It exits only the innermost loop.
- **Reading loop-`else` as "if the loop did not run".** It runs when the loop did not `break`, including when the loop body never executed.

## Recap

- `break` ends the loop. `continue` skips to the next iteration.
- `while True:` plus `break` is the standard shape for "repeat until valid".
- A loop's `else` runs only if the loop finished **without** `break`. Use it for searches that can fail.
- `break` and `continue` affect only the innermost loop.
- Check that every `continue` still reaches the update step in a `while` loop.
