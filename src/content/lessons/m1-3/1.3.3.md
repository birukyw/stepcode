# The Accumulator Pattern

Most loops exist to **build something up**: a total, a count, the biggest value seen so far, a string assembled piece by piece. The recipe is always the same, and it is one of the most important patterns in programming: set up a variable before the loop, update it inside, and use it afterwards. This lesson names the pattern, shows its variations, and walks through the classic bug that hits everyone once.

## The shape

```python
total = 0                    # 1. initialise before the loop

for n in range(1, 6):
    total += n               # 2. update inside the loop

print(total)                 # 3. use after the loop
```

```text
15
```

The variable that carries the result across iterations is the **accumulator**. The three steps are always in this order, and the **initial value** matters: it must be the neutral starting point for the operation.

| Goal | Start with | Update |
|---|---|---|
| Sum | `0` | `total += x` |
| Count | `0` | `count += 1` |
| Product | `1` | `product *= x` |
| Build text | `""` | `text += piece` |
| Largest | something very small | `if x > best: best = x` |
| Smallest | something very large | `if x < best: best = x` |

Starting a product at `0` would make every result zero, and starting a sum at `1` would be off by one. Always ask what value changes nothing for the operation.

## Counting

A counter accumulates `1` each time something happens. This counts the vowels in a phrase:

```python
phrase = "accumulator"
vowels = 0

for ch in phrase:
    if ch in "aeiou":
        vowels += 1

print(vowels)
```

```text
5
```

The `if` filters which items count. Counting and summing are the same shape: count adds `1` for each match, sum adds the value itself.

## Products

A product starts at `1`. This computes 10 factorial, written 10!, the product of 1 through 10:

```python
product = 1
for n in range(1, 11):
    product *= n
print(product)
```

```text
3628800
```

## Building a string

Strings accumulate too, starting from the empty string `""`.

```python
result = ""
for ch in "hello":
    result = ch + result    # put each new letter in front
print(result)
```

```text
olleh
```

Adding each character to the **front** reverses the text. Adding to the back, `result = result + ch`, would reproduce the original.

## Averages

An average combines two accumulators: a sum and a count.

```python
digits = "3141592653"
total = 0
count = 0

for ch in digits:
    total += int(ch)
    count += 1

print(total, count, total / count)
```

```text
39 10 3.9
```

## Tracking the largest value

To find a maximum, keep the best value seen so far and replace it whenever something larger appears. The tricky part is the starting value. Here is a first attempt that looks fine:

```python
readings = "4,9,2,7"
highest = 0

for token in readings.split(","):
    value = int(token)
    if value > highest:
        highest = value

print(highest)
```

```text
9
```

(`split(",")` cuts the text at each comma and returns the pieces as a list, which module 1.4 covers fully. For now, treat it as "give me the pieces to loop over".)

It works, and that is exactly why the bug is dangerous.

## The classic bug

Now try readings that are all **negative**, like temperatures on an arctic stream:

```python
readings = "-4,-9,-2,-7"
highest = 0

for token in readings.split(","):
    value = int(token)
    if value > highest:
        highest = value

print(highest)
```

```text
0
```

The highest temperature is `-2`, but the program says `0`. Nothing in the data is zero. The starting value `0` was **larger than every reading**, so no reading ever replaced it. The accumulator's initial value leaked into the answer.

There are two correct fixes.

**Fix 1: start at negative infinity.** `float("-inf")` is smaller than any number, so the first real reading always replaces it.

```python
readings = "-4,-9,-2,-7"
highest = float("-inf")

for token in readings.split(","):
    value = int(token)
    if value > highest:
        highest = value

print(highest)
```

```text
-2
```

**Fix 2: start from the first real value.** This works with any data and needs no special constant, but it needs a way to take the first item, which module 1.4 covers.

For minimums, the mirror image applies: start at `float("inf")`, which is larger than any number.

> **Why it matters:** An accumulator's initial value is part of your logic. Whenever the answer comes back as exactly your starting value, ask whether the data ever had a chance to change it.

## Remembering whether something happened

A boolean accumulator records whether any item matched:

```python
word = "python"
has_digit = False

for ch in word:
    if ch.isdigit():
        has_digit = True

print(has_digit)
```

```text
False
```

Start with `False` and switch to `True` if anything matches. Start with `True` and switch to `False` if anything fails, to check that **all** items pass.

## Several accumulators at once

One pass over the data can fill several accumulators, which is more efficient than looping repeatedly:

```python
digits = "8172635490"
evens = 0
odds = 0
biggest = -1

for ch in digits:
    d = int(ch)
    if d % 2 == 0:
        evens += 1
    else:
        odds += 1
    if d > biggest:
        biggest = d

print(evens, odds, biggest)
```

```text
5 5 9
```

## Common mistakes

- **Wrong starting value.** `0` for a product, or `0` for a maximum over negative data.
- **Resetting inside the loop.** Putting `total = 0` inside the body wipes the accumulator every iteration.
- **Forgetting to update.** Computing the value but never assigning it back.
- **Using the accumulator before the loop.** It should be set up first, or you get a `NameError`.
- **Doing the division too early.** Divide for an average after the loop, not inside it.

1. Compute the sum of the squares of 1 through 10.
2. Count how many characters of `"Mississippi"` are the letter `s` (lower case).
3. Find the smallest value in `"7,-3,12,-8,5"`, taking care with the starting value.
4. Compute the average of the digits of `2718281828`, printed to two decimals.

```python
total = 0
for n in range(1, 11):
    total += n * n
print(total)   # 385
```

```python
count = 0
for ch in "Mississippi":
    if ch == "s":
        count += 1
print(count)   # 4
```

```python
for token in "7,-3,12,-8,5".split(","):
    value = int(token)
    if value < smallest:
        smallest = value
print(smallest)   # -8
```

```python
total = 0
count = 0
for ch in "2718281828":
    total += int(ch)
    count += 1
print(f"{total / count:.2f}")   # 4.70
```

## Recap

- The accumulator pattern is initialise, update in the loop, use afterwards.
- Choose the neutral starting value: `0` for sums and counts, `1` for products, `""` for text.
- For maximum and minimum, start at `float("-inf")` and `float("inf")` so the data always wins.
- Boolean accumulators answer "did anything match?" or "did everything pass?".
- If the result equals your starting value, check whether the data ever had a chance to change it.
