# Modern Dataclasses & Structural Matching

A huge share of classes are just **bundles of data**: a point, a product, a user, a config. Writing `__init__`, `__repr__` and `__eq__` for each one is the same boilerplate every time. Python's **dataclasses** generate it for you from a list of fields. And once your data has clear shapes, `match` / `case` lets you take it apart with patterns instead of long `if`/`elif` ladders. Together they are the modern way to model data.

## The boilerplate problem

```python
class PointOld:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __repr__(self):
        return f"PointOld(x={self.x!r}, y={self.y!r})"

    def __eq__(self, other):
        return isinstance(other, PointOld) and (self.x, self.y) == (other.x, other.y)

print(PointOld(1, 2), PointOld(1, 2) == PointOld(1, 2))
```

```text
PointOld(x=1, y=2) True
```

Nine lines to describe two fields. Adding a field means editing three methods.

## @dataclass: describe the fields, get the rest

```python
from dataclasses import dataclass

@dataclass
class Point:
    x: float
    y: float

p = Point(1, 2)
print(p)
print(p == Point(1, 2), p == Point(2, 1))
p.x = 10
print(p.x, p)
```

```text
Point(x=1, y=2)
True False
10 Point(x=10, y=2)
```

The class body is just a list of fields with **type annotations**. `@dataclass` writes `__init__`, `__repr__` and `__eq__` for you. (The annotations are hints for readers and tools. Python does not enforce them at run time, as lesson 3.5.1 explains.)

## Defaults and field()

Fields can have defaults. Those with defaults must come **after** those without:

```python
from dataclasses import dataclass, field

@dataclass
class Task:
    title: str
    priority: int = 3
    done: bool = False
    tags: list = field(default_factory=list)       # a NEW list per instance

a = Task("write")
b = Task("test", priority=1, tags=["qa"])
a.tags.append("docs")
print(a)
print(b)
print(Task("x").tags)
```

```text
Task(title='write', priority=3, done=False, tags=['docs'])
Task(title='test', priority=1, done=False, tags=['qa'])
[]
```

Remember the mutable default trap (lessons 1.5.4 and 3.2.1)? `tags: list = []` would share one list among all tasks, so dataclasses **refuse it** with an error. Use `field(default_factory=list)`, which calls `list()` for each new object.

`field()` has more options:

```python
from dataclasses import dataclass, field

@dataclass
class User:
    name: str
    password: str = field(repr=False)             # hide from the printout
    id: int = field(default=0, compare=False)     # ignore when comparing
    scores: list = field(default_factory=list)

u1 = User("ada", "secret", id=1)
u2 = User("ada", "secret", id=2)
print(u1)
print(u1 == u2)
```

```text
User(name='ada', id=1, scores=[])
True
```

## Validation and derived fields: `__post_init__`

`__post_init__` runs right after the generated `__init__`. Use it for validation or to compute extra fields:

```python
from dataclasses import dataclass, field

@dataclass
class Rectangle:
    width: float
    height: float
    area: float = field(init=False)

    def __post_init__(self):
        if self.width <= 0 or self.height <= 0:
            raise ValueError("sides must be positive")
        self.area = self.width * self.height

r = Rectangle(3, 4)
print(r)
try:
    Rectangle(-1, 5)
except ValueError:
    print("rejected")
```

```text
Rectangle(width=3, height=4, area=12)
rejected
```

`init=False` means the caller does not pass `area`. It is calculated instead.

## Immutable, ordered and slotted

Three options change what the generated class can do:

```python
from dataclasses import dataclass

@dataclass(frozen=True, order=True)
class Version:
    major: int
    minor: int = 0
    patch: int = 0

v1 = Version(1, 2, 3)
v2 = Version(1, 10)
print(v1 < v2, sorted([v2, v1, Version(0, 9)]))
print(hash(v1) == hash(Version(1, 2, 3)))

try:
    v1.major = 5
except AttributeError:
    print("frozen: cannot change")

lookup = {v1: "stable", v2: "latest"}
print(lookup[Version(1, 10)])
```

```text
True [Version(major=0, minor=9, patch=0), Version(major=1, minor=2, patch=3), Version(major=1, minor=10, patch=0)]
True
frozen: cannot change
latest
```

- **`frozen=True`** makes instances **immutable** and gives them a `__hash__`, so they work as dictionary keys and in sets.
- **`order=True`** generates `<`, `<=`, `>`, `>=` by comparing the fields **in order**, as a tuple.
- **`slots=True`** (Python 3.10+) adds `__slots__` for lower memory and typo protection.

## Converting and copying

```python
from dataclasses import dataclass, asdict, astuple, replace, fields

@dataclass(frozen=True)
class Item:
    name: str
    price: float
    qty: int = 1

item = Item("pen", 1.5, 4)
print(asdict(item))
print(astuple(item))
print(replace(item, qty=10))
print([f.name for f in fields(item)])
```

```text
{'name': 'pen', 'price': 1.5, 'qty': 4}
('pen', 1.5, 4)
Item(name='pen', price=1.5, qty=10)
['name', 'price', 'qty']
```

`replace` builds a **modified copy**, which is how you "change" a frozen object. `asdict` turns it into a plain dictionary, perfect for JSON.

## Inheritance and methods

Dataclasses are ordinary classes: add methods, properties and inheritance.

```python
from dataclasses import dataclass

@dataclass
class Shape:
    name: str

@dataclass
class Circle(Shape):
    radius: float = 1.0

    @property
    def area(self):
        return 3.14159 * self.radius ** 2

    def scale(self, factor):
        return Circle(self.name, self.radius * factor)

c = Circle("round", 2)
print(c, round(c.area, 2))
print(c.scale(2))
```

```text
Circle(name='round', radius=2) 12.57
Circle(name='round', radius=4)
```

## NamedTuple and Enum: two light alternatives

For immutable records that should also behave like tuples, `NamedTuple`:

```python
from typing import NamedTuple
from enum import Enum, auto

class Coord(NamedTuple):
    lat: float
    lon: float

c = Coord(51.5, -0.12)
lat, lon = c
print(c, c.lat, c[1], lat == 51.5)

class Status(Enum):
    PENDING = auto()
    ACTIVE = auto()
    DONE = auto()

s = Status.ACTIVE
print(s, s.name, s.value, Status["DONE"], s is Status.ACTIVE)
print([m.name for m in Status])
```

```text
Coord(lat=51.5, lon=-0.12) 51.5 -0.12 True
Status.ACTIVE ACTIVE 2 Status.DONE True
['PENDING', 'ACTIVE', 'DONE']
```

An **Enum** is the right type for a fixed set of choices: it prevents typos (`"actve"` is silently wrong, `Status.ACTVE` is an error) and lets tools list the options.

## Structural pattern matching

Python 3.10 added `match`/`case`. It looks like a `switch`, but it matches the **shape** of data and can take values out of it. Start with simple values and alternatives:

```python
def http_message(code):
    match code:
        case 200:
            return "ok"
        case 301 | 302:
            return "redirect"
        case 404:
            return "not found"
        case _:
            return "other"

print([http_message(c) for c in (200, 302, 404, 500)])
```

```text
['ok', 'redirect', 'not found', 'other']
```

`|` means "or", and `_` is the wildcard that matches anything. The real power is **destructuring**: matching a shape and naming its parts at the same time:

```python
def describe(command):
    match command:
        case []:
            return "nothing"
        case ["quit"]:
            return "bye"
        case ["go", direction]:
            return f"going {direction}"
        case ["take", item, "from", place]:
            return f"taking {item} from {place}"
        case ["say", *words]:
            return "saying " + " ".join(words)
        case _:
            return "unknown"

for cmd in ([], ["quit"], ["go", "north"], ["take", "key", "from", "desk"], ["say", "hello", "there"], ["dance"]):
    print(describe(cmd))
```

```text
nothing
bye
going north
taking key from desk
saying hello there
unknown
```

Each `case` is a **pattern**. `["go", direction]` matches a two-item list whose first item is `"go"`, and **binds** the second to the name `direction`. `*words` captures the rest. This replaces a mess of `len(cmd) == 2 and cmd[0] == "go"` checks.

## Matching dictionaries and adding guards

Dictionary patterns match when the keys are present and ignore extra keys. A **guard** (`if ...`) adds a condition:

```python
def handle(event):
    match event:
        case {"type": "click", "x": x, "y": y}:
            return f"click at {x},{y}"
        case {"type": "key", "key": key} if key.isupper():
            return f"shout key {key}"
        case {"type": "key", "key": key}:
            return f"key {key}"
        case {"type": t}:
            return f"unhandled {t}"
        case _:
            return "not an event"

events = [
    {"type": "click", "x": 3, "y": 4, "button": "left"},
    {"type": "key", "key": "A"},
    {"type": "key", "key": "a"},
    {"type": "scroll"},
    "garbage",
]
print([handle(e) for e in events])
```

```text
['click at 3,4', 'shout key A', 'key a', 'unhandled scroll', 'not an event']
```

## Matching classes

Patterns can match **objects** by type and attributes, which is where dataclasses and `match` shine together:

```python
from dataclasses import dataclass

@dataclass
class Circle:
    radius: float

@dataclass
class Rect:
    width: float
    height: float

@dataclass
class Square:
    side: float

def area(shape):
    match shape:
        case Circle(radius=r):
            return round(3.14159 * r * r, 2)
        case Rect(width=w, height=h):
            return w * h
        case Square(side=s):
            return s * s
        case _:
            raise TypeError("unknown shape")

print([area(s) for s in (Circle(1), Rect(2, 3), Square(4))])
```

```text
[3.14, 6, 16]
```

Dataclasses also support **positional** patterns (`Rect(w, h)`), because they define the order of their fields:

```python
from dataclasses import dataclass

@dataclass
class Point:
    x: int
    y: int

def where(p):
    match p:
        case Point(0, 0):
            return "origin"
        case Point(x, 0):
            return f"on the x-axis at {x}"
        case Point(0, y):
            return f"on the y-axis at {y}"
        case Point(x, y) if x == y:
            return "on the diagonal"
        case Point():
            return "somewhere else"

print([where(Point(*xy)) for xy in ((0, 0), (5, 0), (0, 3), (2, 2), (1, 9))])
```

```text
['origin', 'on the x-axis at 5', 'on the y-axis at 3', 'on the diagonal', 'somewhere else']
```

## A realistic example: evaluating expressions

Pattern matching makes tree-shaped data pleasant. Here an arithmetic expression is nested tuples:

```python
def evaluate(expr):
    match expr:
        case int() | float():
            return expr
        case ("add", left, right):
            return evaluate(left) + evaluate(right)
        case ("mul", left, right):
            return evaluate(left) * evaluate(right)
        case ("neg", value):
            return -evaluate(value)
        case _:
            raise ValueError("bad expression")

print(evaluate(("add", 2, ("mul", 3, 4))))
print(evaluate(("neg", ("add", 1, 1.5))))
```

```text
14
-2.5
```

## When to use which

| You have... | Reach for |
|---|---|
| a bundle of fields, possibly mutable, with defaults | `@dataclass` |
| an immutable value used as a key | `@dataclass(frozen=True)` |
| a tuple that needs field names | `NamedTuple` |
| a fixed set of choices | `Enum` |
| JSON-like or tree-shaped data to take apart | `match` / `case` |

## Common mistakes

- **A mutable default** (`tags: list = []`). Use `field(default_factory=list)`.
- **A non-default field after a default one.** Reorder, or use `kw_only=True`.
- **Expecting the annotations to be enforced.** `Point("a", "b")` works. Validate in `__post_init__`.
- **Changing a frozen dataclass.** Use `dataclasses.replace`.
- **Forgetting `_` last** in a `match`, so unmatched values fall through silently.
- **Using `case Point:` instead of `case Point():`.** Without parentheses it is a name that **captures** everything.
- **Putting a general `case` before a specific one.** The first match wins, so order patterns from specific to general.

## Practice

1. Make a frozen, ordered dataclass `Card(rank, suit)` and sort a small hand.
2. Add `__post_init__` validation to a `Product(name, price, quantity)` dataclass: no negative price or quantity, and a default `quantity=1`.
3. Write `handle_command(parts)` with `match` for `["add", name, price]`, `["remove", name]` and `["list"]`.
4. Write `flatten(data)` with `match`: a list is flattened recursively, anything else is returned as a single-item list.

+++ Solutions
```python
from dataclasses import dataclass

@dataclass(frozen=True, order=True)
class Card:
    rank: int
    suit: str

hand = [Card(10, "H"), Card(2, "S"), Card(10, "C")]
print(sorted(hand))   # [Card(rank=2, suit='S'), Card(rank=10, suit='C'), Card(rank=10, suit='H')]

@dataclass
class Product:
    name: str
    price: float
    quantity: int = 1

    def __post_init__(self):
        if self.price < 0 or self.quantity < 0:
            raise ValueError("negative")

print(Product("pen", 1.5))
```

```python
def handle_command(parts):
    match parts:
        case ["add", name, price]:
            return f"added {name} at {price}"
        case ["remove", name]:
            return f"removed {name}"
        case ["list"]:
            return "listing"
        case _:
            return "unknown"

print([handle_command(p) for p in (["add", "pen", "2"], ["remove", "pen"], ["list"], ["x"])])

def flatten(data):
    match data:
        case list():
            return [x for item in data for x in flatten(item)]
        case _:
            return [data]

print(flatten([1, [2, [3, "a"]], 4]))   # [1, 2, 3, 'a', 4]
```

## Recap

- `@dataclass` generates `__init__`, `__repr__` and `__eq__` from annotated fields. Use `field(default_factory=...)` for mutable defaults, `__post_init__` for validation, and `field(repr=False, compare=False, init=False)` to tune a field.
- `frozen=True` makes instances immutable and hashable, `order=True` adds comparisons, and `slots=True` saves memory. `replace`, `asdict` and `astuple` convert and copy.
- `NamedTuple` is an immutable tuple with names, and `Enum` is the right type for a fixed set of choices.
- `match`/`case` matches the **shape** of data and binds parts: literals and `|`, sequences with `*rest`, dictionaries, class patterns (keyword or positional), and `if` guards. The first matching case wins, and `_` is the wildcard.
- Dataclasses plus `match` make tree-shaped and event-shaped data easy to model and take apart.
