# Encapsulation, Invariants & Descriptors

A class is a promise: *"if you use me through my methods, I will always be in a valid state."* An account never has a negative balance, a temperature is never below absolute zero, an email address always contains an `@`. That rule about what must always be true is an **invariant**, and protecting it is called **encapsulation**. This lesson shows Python's tools for it: naming conventions, **properties**, `__slots__`, and finally **descriptors**, the mechanism underneath all of them.

## The problem: public attributes have no protection

```python
class Account:
    def __init__(self, balance):
        self.balance = balance

acct = Account(100)
acct.balance = -5000                # nothing stops this
print(acct.balance)
```

```text
-5000
```

Anyone can set any attribute to anything. The invariant "balance is never negative" lives only in the programmer's head.

## Conventions: single and double underscores

Python does not have `private` keywords. It uses **naming conventions** that tell readers what is internal:

```python
class Box:
    def __init__(self):
        self.public = "anyone may use this"
        self._internal = "by convention: for use inside the class and subclasses"
        self.__hidden = "name-mangled: harder to reach by accident"

b = Box()
print(b.public, "|", b._internal)
print([name for name in vars(b)])
print(b._Box__hidden)
```

```text
anyone may use this | by convention: for use inside the class and subclasses
['public', '_internal', '_Box__hidden']
name-mangled: harder to reach by accident
```

- `_name`: "this is internal, please do not rely on it". Nothing enforces it, but breaking the convention is on you.
- `__name`: Python **mangles** it to `_ClassName__name`, which avoids accidental clashes in subclasses. It is **not** real privacy, as the last line shows.

Python's attitude is "we are all consenting adults": conventions and clear APIs, not locked doors.

## Properties: attributes with rules

A **property** looks like an ordinary attribute to the caller but runs code when read or written. It is the Pythonic way to add validation **without changing how the class is used**:

```python
class Temperature:
    def __init__(self, celsius):
        self.celsius = celsius          # goes through the setter below

    @property
    def celsius(self):
        return self._celsius

    @celsius.setter
    def celsius(self, value):
        if value < -273.15:
            raise ValueError("below absolute zero")
        self._celsius = value

    @property
    def fahrenheit(self):               # computed, read-only
        return self._celsius * 9 / 5 + 32

t = Temperature(25)
print(t.celsius, t.fahrenheit)
t.celsius = 100
print(t.fahrenheit)

try:
    t.celsius = -500
except ValueError as err:
    print("rejected:", err)
print(t.celsius)

try:
    t.fahrenheit = 50
except AttributeError:
    print("fahrenheit is read-only")
```

```text
25 77.0
212.0
rejected: below absolute zero
100
fahrenheit is read-only
```

Walk through it:

- `@property` above a method makes it a **getter**: `t.celsius` calls it, with no parentheses.
- `@celsius.setter` defines what happens on `t.celsius = value`. Here it validates.
- The real data lives in `_celsius`. The leading underscore signals "go through the property".
- `fahrenheit` has only a getter, so it is **read-only** and **computed on demand**: it can never be out of sync.
- Even `__init__` uses `self.celsius = celsius`, so the validation applies from the very first moment.

This is why Python programmers do not write `get_x()` and `set_x()` methods. Start with a plain attribute. If you later need a rule, turn it into a property and **no calling code changes**.

## Computed and cached properties

A property is a good home for anything **derived** from other data:

```python
class Rectangle:
    def __init__(self, width, height):
        self.width = width
        self.height = height

    @property
    def area(self):
        return self.width * self.height

    @property
    def is_square(self):
        return self.width == self.height

r = Rectangle(3, 4)
print(r.area, r.is_square)
r.width = 4
print(r.area, r.is_square)
```

```text
12 False
16 True
```

Because `area` is computed each time, it can never go stale. For expensive computations, `functools.cached_property` computes once and remembers:

```python
from functools import cached_property

class Report:
    computations = 0

    def __init__(self, data):
        self.data = data

    @cached_property
    def total(self):
        Report.computations += 1
        return sum(self.data)

r = Report([1, 2, 3])
print(r.total, r.total, r.total)
print(Report.computations)
```

```text
6 6 6
1
```

## Protecting an invariant across several fields

When two fields must agree, protect them together in one method rather than in separate setters:

```python
class DateRange:
    def __init__(self, start, end):
        self.set_range(start, end)

    def set_range(self, start, end):
        if end < start:
            raise ValueError("end before start")
        self._start, self._end = start, end

    @property
    def start(self):
        return self._start

    @property
    def end(self):
        return self._end

    @property
    def length(self):
        return self._end - self._start

r = DateRange(5, 12)
print(r.start, r.end, r.length)
r.set_range(1, 3)
print(r.length)
try:
    r.set_range(9, 2)
except ValueError:
    print("invalid range rejected; still", r.start, r.end)
```

```text
5 12 7
2
invalid range rejected; still 1 3
```

A single method that checks everything before changing anything guarantees that the object **never exists in a half-updated state**. If `set_range` had assigned `_start` first and then raised, the object would be left inconsistent.

## `__slots__`: no surprise attributes, less memory

Remember that a typo like `obj.colour = "red"` silently creates an attribute? `__slots__` declares the **only** attributes allowed:

```python
class Point:
    __slots__ = ("x", "y")

    def __init__(self, x, y):
        self.x = x
        self.y = y

p = Point(1, 2)
p.x = 10
print(p.x, p.y)

try:
    p.z = 3
except AttributeError:
    print("cannot add new attributes")

print(hasattr(p, "__dict__"))
```

```text
10 2
cannot add new attributes
False
```

With `__slots__` the instance has no `__dict__`, so each object uses less memory and typos fail loudly. It is worth it for classes with millions of instances.

## Descriptors: the engine behind properties

A **descriptor** is any object that defines `__get__`, `__set__` or `__delete__` and lives as a **class attribute**. Python calls those methods whenever the attribute is read or written through an instance. Properties, methods, `classmethod` and `staticmethod` are all descriptors.

Why write your own? To **reuse validation across many attributes**. Without descriptors you would copy the same property over and over:

```python
class Positive:
    """A reusable validated attribute: any value assigned must be above zero."""

    def __set_name__(self, owner, name):
        self.private_name = "_" + name

    def __get__(self, obj, objtype=None):
        if obj is None:
            return self
        return getattr(obj, self.private_name)

    def __set__(self, obj, value):
        if value <= 0:
            raise ValueError(self.private_name[1:] + " must be positive")
        setattr(obj, self.private_name, value)

class Product:
    price = Positive()
    quantity = Positive()

    def __init__(self, name, price, quantity):
        self.name = name
        self.price = price
        self.quantity = quantity

    @property
    def total(self):
        return self.price * self.quantity

p = Product("pen", 2.5, 4)
print(p.total)
p.quantity = 10
print(p.total)

for field, bad in (("price", -1), ("quantity", 0)):
    try:
        setattr(p, field, bad)
    except ValueError as err:
        print(err)
```

```text
10.0
25.0
price must be positive
quantity must be positive
```

How it works:

- `price = Positive()` creates **one** descriptor object stored on the **class**.
- `__set_name__` is called once when the class is created, and tells the descriptor which attribute name it received (`price`).
- Reading `p.price` calls `Positive.__get__`. Writing `p.price = 5` calls `Positive.__set__`.
- The actual values are stored per instance under `_price` and `_quantity`, while the rule is written **once**.

Two attributes, one validation rule, no duplicated code. Real libraries (Django models, SQLAlchemy columns, `dataclasses`) are built from this idea.

## Data you must not change: read-only objects

If an object should never change after creation, make that explicit. Properties without setters work, and so does freezing a dataclass (lesson 3.2.5). A lighter option is a tuple-like class:

```python
class Money:
    __slots__ = ("_amount", "_currency")

    def __init__(self, amount, currency):
        object.__setattr__(self, "_amount", amount)
        object.__setattr__(self, "_currency", currency)

    @property
    def amount(self):
        return self._amount

    @property
    def currency(self):
        return self._currency

    def __setattr__(self, name, value):
        raise AttributeError("Money is immutable")

    def plus(self, other):
        return Money(self._amount + other.amount, self._currency)

m = Money(10, "EUR")
total = m.plus(Money(5, "EUR"))
print(total.amount, total.currency, m.amount)
try:
    m.amount = 99
except AttributeError:
    print("immutable")
```

```text
15 EUR 10
immutable
```

`plus` returns a **new** `Money` instead of changing the old one. Immutable value objects are easy to reason about: once built, they cannot surprise you later.

## Common mistakes

- **A property setter that assigns to its own name.** `self.celsius = v` inside the `celsius` setter recurses forever. Store in `_celsius`.
- **Forgetting that `__init__` bypasses validation** when it assigns to `self._x` directly. Assign to the property to validate the first value too.
- **Validating in one place, not in another,** so an invariant holds for some code paths only.
- **Treating `__name` as real privacy.** It is mangling, not security.
- **A descriptor that stores values on itself,** which makes every instance share them. Store on the instance (`obj`).
- **Expensive work inside a plain `@property`** that is read in a loop. Use `cached_property`.

```python
import math

class Person:
    def __init__(self, name):
        self.name = name

    @property
    def name(self):
        return self._name

    @name.setter
    def name(self, value):
        value = value.strip()
        if not value:
            raise ValueError("name cannot be empty")
        self._name = value

class Circle:
    def __init__(self, radius):
        self.radius = radius

    @property
    def radius(self):
        return self._radius

    @radius.setter
    def radius(self, value):
        if value <= 0:
            raise ValueError("radius must be positive")
        self._radius = value

    @property
    def diameter(self):
        return self._radius * 2

    @property
    def area(self):
        return math.pi * self._radius ** 2

print(Person("  Ada ").name, Circle(2).diameter, round(Circle(1).area, 3))   # Ada 4 3.142
```

```python
class NonEmpty:
    def __set_name__(self, owner, name):
        self.private = "_" + name

    def __get__(self, obj, objtype=None):
        return self if obj is None else getattr(obj, self.private)

    def __set__(self, obj, value):
        if not value:
            raise ValueError("empty")
        setattr(obj, self.private, value)

class User:
    first = NonEmpty()
    last = NonEmpty()

    def __init__(self, first, last):
        self.first, self.last = first, last

u = User("Ada", "Lovelace")
print(u.first, u.last)   # Ada Lovelace
```

## Recap

- **Encapsulation** protects an object's **invariants**, the facts that must always be true, so that nothing can put it into an invalid state.
- Python uses conventions: `_name` means internal, `__name` is mangled to avoid clashes (not true privacy).
- A **property** (`@property`, `@x.setter`) looks like an attribute but runs code, so validation can be added later without changing callers. Computed, read-only properties never go out of date, and `cached_property` computes once.
- Protect fields that must agree **together**, with one method that checks before it changes anything.
- `__slots__` forbids undeclared attributes and saves memory.
- A **descriptor** (`__get__`, `__set__`, `__set_name__`) is a reusable attribute rule stored on the class. Properties are built on the same mechanism.
- Immutable value objects (no setters, methods return new objects) are the safest design for plain data.
