# Blueprints, Instances & self Mechanics

In lesson 1.7.6 you wrote your first class: a blueprint, objects built from it, and methods that use `self`. This lesson looks underneath. **Where does Python actually keep an object's data? What is `self`, really? How does `obj.name` find its answer?** Once you can answer those, strange bugs (shared lists, methods that "forget" their object, attributes appearing from nowhere) stop being strange.

## An object is a namespace

Every instance carries a dictionary holding its attributes:

```python
class Dog:
    def __init__(self, name, age):
        self.name = name
        self.age = age

rex = Dog("Rex", 4)
print(rex.__dict__)
print(vars(rex) == rex.__dict__)

rex.color = "brown"            # attributes can be added at any time
print(sorted(vars(rex)))
print(hasattr(rex, "color"), hasattr(rex, "weight"))
print(getattr(rex, "weight", "unknown"))
setattr(rex, "weight", 30)
print(rex.weight)
```

```text
{'name': 'Rex', 'age': 4}
True
['age', 'color', 'name']
True False
unknown
30
```

`self.name = name` is nothing magical: it stores a key in the instance's `__dict__`. Attributes can be added later, read by name with `getattr`, and tested with `hasattr`. This flexibility is also a trap: a typo like `rex.colour = "red"` quietly creates a new attribute instead of failing. Lesson 3.2.2 shows how to lock that down.

## Instance versus class attributes

Data written in the class body belongs to the **class** and is shared. Data stored through `self` belongs to **one instance**:

```python
class Counter:
    total_created = 0                  # shared by every Counter

    def __init__(self, label):
        self.label = label             # one per instance
        self.clicks = 0
        Counter.total_created += 1

    def click(self):
        self.clicks += 1

a = Counter("a")
b = Counter("b")
a.click(); a.click(); b.click()
print(a.clicks, b.clicks, Counter.total_created)
print(a.total_created, b.total_created)
```

```text
2 1 2
2 2
```

Reading `a.total_created` works because of how Python **looks attributes up**: first in the instance's own `__dict__`, then in the class, then in its parents. The instance does not have `total_created`, so Python finds it on the class.

### The lookup rule and a shadowing surprise

Assigning through an instance **always** writes to the instance, which can hide a class attribute:

```python
class Config:
    debug = False

c1 = Config()
c2 = Config()
c1.debug = True                 # creates an instance attribute that shadows the class one
print(c1.debug, c2.debug, Config.debug)
print("debug" in vars(c1), "debug" in vars(c2))

Config.debug = True             # change the class attribute
print(c1.debug, c2.debug)       # c1 still sees its own
```

```text
True False False
True False
True True
```

`c1.debug = True` did not change the class. It created a separate attribute on `c1`. Later changes to `Config.debug` reach `c2` but not `c1`.

### The mutable class attribute trap

You met this with default arguments in lesson 1.5.4. The same bug appears with class attributes:

```python
class Bad:
    items = []                  # ONE list, shared by every instance

    def add(self, x):
        self.items.append(x)

class Good:
    def __init__(self):
        self.items = []         # a new list per instance

    def add(self, x):
        self.items.append(x)

b1, b2 = Bad(), Bad()
b1.add("x")
print(b2.items)

g1, g2 = Good(), Good()
g1.add("x")
print(g2.items)
```

```text
['x']
[]
```

The rule: **mutable per-object data belongs in `__init__`**, never in the class body.

## What `self` really is

`self` is not a keyword. It is just the **first parameter**, and Python fills it in for you. These two lines do exactly the same thing:

```python
class Greeter:
    def __init__(self, name):
        self.name = name

    def greet(self, other):
        return self.name + " greets " + other

g = Greeter("Ada")
print(g.greet("Linus"))
print(Greeter.greet(g, "Linus"))     # what Python really does: pass the object explicitly
```

```text
Ada greets Linus
Ada greets Linus
```

When you write `g.greet("Linus")`, Python looks up `greet` on the class, sees it is a function, and **binds** `g` as the first argument. The result of `g.greet` (before the call) is a **bound method**: a function with its `self` already attached:

```python
class Greeter:
    def __init__(self, name):
        self.name = name

    def greet(self):
        return "hi from " + self.name

g = Greeter("Ada")
method = g.greet                       # no call yet
print(type(method).__name__)
print(method())
print(method.__self__ is g, method.__func__ is Greeter.greet)

callbacks = [Greeter("A").greet, Greeter("B").greet]
print([cb() for cb in callbacks])
```

```text
method
hi from Ada
True True
['hi from A', 'hi from B']
```

A bound method remembers its object, so you can pass it around as a callback (lesson 3.1.2) and it still knows which object it belongs to. Calling a method on a class instead of an instance (`Greeter.greet()`) fails because there is no `self` to supply.

## Three kinds of method

Not every method needs an instance. Python has three flavours:

| Kind | First parameter | Decorator | Use it for |
|---|---|---|---|
| instance method | `self` (the object) | none | behaviour that needs the object's data |
| class method | `cls` (the class) | `@classmethod` | alternative constructors, class-level data |
| static method | nothing special | `@staticmethod` | a helper that belongs to the class but uses neither |

```python
class Temperature:
    def __init__(self, celsius):
        self.celsius = celsius

    @classmethod
    def from_fahrenheit(cls, f):
        return cls((f - 32) * 5 / 9)           # an alternative constructor

    @staticmethod
    def is_valid(celsius):
        return celsius >= -273.15              # needs no object at all

    def to_fahrenheit(self):
        return self.celsius * 9 / 5 + 32

t = Temperature.from_fahrenheit(212)
print(t.celsius)
print(t.to_fahrenheit())
print(Temperature.is_valid(-300), Temperature.is_valid(20))
```

```text
100.0
212.0
False True
```

`@classmethod` is the standard way to give a class **several ways to be created**. Because it receives `cls`, it also works correctly for subclasses:

```python
class Shape:
    def __init__(self, name):
        self.name = name

    @classmethod
    def create(cls, *args):
        return cls(*args)

class Circle(Shape):
    pass

c = Circle.create("circle")
print(type(c).__name__, c.name)
```

```text
Circle circle
```

`Circle.create(...)` builds a `Circle`, not a `Shape`, because `cls` is whichever class the method was called on. That is why alternative constructors are written with `cls(...)` rather than naming the class.

## Creating objects: `__new__` and `__init__`

Two steps happen when you write `Dog("Rex", 4)`. First `__new__` **creates** the empty object, then `__init__` **fills it in**. You almost never touch `__new__`, but seeing the order demystifies construction:

```python
class Traced:
    def __new__(cls, *args):
        print("1. __new__ creates the object")
        return super().__new__(cls)

    def __init__(self, value):
        print("2. __init__ fills it in")
        self.value = value

t = Traced(5)
print(t.value)
```

```text
1. __new__ creates the object
2. __init__ fills it in
5
```

`__init__` must not return anything. If you ever need to control **whether a new object is created at all** (for example, a singleton), that is a job for `__new__`. For everything else, `__init__` is enough.

## Introspection: asking an object about itself

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def norm(self):
        return (self.x ** 2 + self.y ** 2) ** 0.5

p = Point(3, 4)
print(type(p).__name__, isinstance(p, Point), isinstance(p, object))
print([name for name in dir(p) if not name.startswith("_")])
print(callable(p.norm), callable(p.x))
print(p.norm())
```

```text
Point True True
['norm', 'x', 'y']
True False
5.0
```

`isinstance(obj, Class)` is the right test for "is this a kind of Class" (it also respects inheritance, which you meet in lesson 3.2.4). `dir()` lists everything reachable on an object, including methods and inherited names.

## A small design exercise: a bank account

Putting the mechanics together, here is a class with an alternative constructor, a class-level counter, and a private-looking helper:

```python
class Account:
    count = 0

    def __init__(self, owner, balance=0):
        self.owner = owner
        self.balance = balance
        Account.count += 1

    @classmethod
    def from_string(cls, text):
        owner, _, amount = text.partition(":")
        return cls(owner.strip(), int(amount))

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("deposit must be positive")
        self.balance += amount
        return self.balance

a = Account("Ada", 100)
b = Account.from_string("Linus: 250")
a.deposit(50)
print(a.balance, b.owner, b.balance, Account.count)
```

```text
150 Linus 250 2
```

## Common mistakes

- **Forgetting `self`** in a method's parameters, or using `balance` where you meant `self.balance`.
- **A mutable class attribute** (`items = []`) shared by all instances. Create it in `__init__`.
- **Assigning to a class attribute through an instance,** which creates a shadowing instance attribute instead.
- **Calling `Class.method()` and getting a missing-argument error.** Call it on an instance, or use `@classmethod` / `@staticmethod`.
- **A typo in an attribute name** silently creating a new attribute.
- **Naming a class method's first parameter `self`.** Use `cls` so readers know it is the class.

## Practice

1. Write a `Student` class where `Student.count` tracks how many have been created, and each student has their own `grades` list with `add_grade` and `average` methods.
2. Add a `@classmethod` `from_csv("name,grade1,grade2")` that builds a student with grades.
3. Add a `@staticmethod` `is_passing(average)` that returns `True` for 50 or more.
4. Show with a few lines of code that two students do not share their `grades` list.

+++ Solutions
```python
class Student:
    count = 0

    def __init__(self, name):
        self.name = name
        self.grades = []
        Student.count += 1

    @classmethod
    def from_csv(cls, line):
        name, *grades = line.split(",")
        student = cls(name)
        student.grades = [int(g) for g in grades]
        return student

    @staticmethod
    def is_passing(average):
        return average >= 50

    def add_grade(self, grade):
        self.grades.append(grade)

    def average(self):
        return sum(self.grades) / len(self.grades) if self.grades else 0

a = Student.from_csv("Ada,90,70")
b = Student("Linus")
b.add_grade(40)
print(a.average(), b.average(), Student.count, Student.is_passing(a.average()))   # 80.0 40.0 2 True
print(a.grades is b.grades, a.grades, b.grades)   # False [90, 70] [40]
```

## Recap

- An instance stores its data in a dictionary, `obj.__dict__`. `self.x = 1` just writes to it, and attributes can be added, read and tested with `setattr`, `getattr` and `hasattr`.
- Attribute lookup goes **instance, then class, then parents**. Assigning through an instance creates an instance attribute that can **shadow** a class one.
- Per-object mutable data belongs in `__init__`. A mutable class attribute is shared by everyone.
- `self` is just the first parameter. `obj.method(x)` is `Class.method(obj, x)`, and `obj.method` alone is a **bound method** that remembers its object.
- `@classmethod` receives `cls` and gives alternative constructors that work for subclasses. `@staticmethod` is a plain function that lives in the class.
- Creating an object runs `__new__` (build it) then `__init__` (fill it in). `isinstance`, `dir`, `vars` let you inspect any object.
