# The Python Data Model (Dunder Protocols)

Why does `len(x)` work on a list, a string and a dictionary? Why does `a + b` add numbers but join strings? Why can you loop over a file? The answer is one of Python's best ideas: **the data model**. Python defines a set of special methods with double underscores, nicknamed **dunder methods**, and the language's own syntax calls them. Implement the right ones in your class and your objects can behave like built-in types: printable, comparable, sortable, iterable, callable, indexable.

You have already used `__init__` and `__str__`. This lesson is the tour of the rest.

## The idea: syntax calls your methods

```python
class Echo:
    def __len__(self):
        return 42

    def __repr__(self):
        return "Echo()"

e = Echo()
print(len(e))
print(repr(e))
print(e.__len__() == len(e))
```

```text
42
Echo()
True
```

`len(e)` is not magic: Python calls `e.__len__()`. You almost never write `e.__len__()` yourself. You write the dunder method **once**, and the built-in function or operator does the rest. The names are fixed, because the language looks them up.

## Representing objects: `__repr__` and `__str__`

Two methods turn an object into text, for different readers:

- `__repr__`: for **developers**. Unambiguous, ideally something you could paste back into code. Used by the REPL, in lists, and by `repr()`.
- `__str__`: for **users**. Readable. Used by `print()` and f-strings. If missing, `__repr__` is used instead.

```python
class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __repr__(self):
        return f"Point({self.x!r}, {self.y!r})"

    def __str__(self):
        return f"({self.x}, {self.y})"

p = Point(3, 4)
print(p)
print(repr(p))
print([p, Point(0, 1)])
print(f"point is {p}, debug: {p!r}")
```

```text
(3, 4)
Point(3, 4)
[Point(3, 4), Point(0, 1)]
point is (3, 4), debug: Point(3, 4)
```

Notice that printing a **list** of points uses `__repr__` for each item. The rule of thumb: **always write `__repr__`**. Add `__str__` only if the friendly form should differ.

## Equality and hashing: `__eq__` and `__hash__`

By default two objects are equal only if they are the **same object**. For value-like classes, define equality by content:

```python
class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __eq__(self, other):
        if not isinstance(other, Point):
            return NotImplemented
        return (self.x, self.y) == (other.x, other.y)

    def __hash__(self):
        return hash((self.x, self.y))

a, b = Point(1, 2), Point(1, 2)
print(a == b, a is b, a != Point(9, 9))
print(len({a, b, Point(3, 4)}))
print(a == "not a point")
```

```text
True False True
2
False
```

Two rules:

- Returning `NotImplemented` (not `False`) for an unknown type lets Python try the other side or fall back safely.
- If you define `__eq__`, define `__hash__` too, using the **same fields**. Equal objects **must** have equal hashes, or sets and dictionaries break (lesson 2.3.3). Without `__hash__`, Python makes the class unhashable.

## Ordering: `<`, `>` and sorting

Define `__lt__` (less than) and `sorted`, `min`, `max` work on your objects. `functools.total_ordering` fills in the rest from `__eq__` and one comparison:

```python
from functools import total_ordering

@total_ordering
class Version:
    def __init__(self, text):
        self.parts = tuple(int(p) for p in text.split("."))

    def __eq__(self, other):
        return self.parts == other.parts

    def __lt__(self, other):
        return self.parts < other.parts

    def __repr__(self):
        return "Version(" + ".".join(map(str, self.parts)) + ")"

versions = [Version("1.10.0"), Version("1.2.0"), Version("1.2.10"), Version("0.9")]
print(sorted(versions))
print(max(versions), Version("2.0") >= Version("1.99.99"))
```

```text
[Version(0.9), Version(1.2.0), Version(1.2.10), Version(1.10.0)]
Version(1.10.0) True
```

Comparing tuples gives the right order for version numbers (`1.10` is newer than `1.2`), where comparing text would not.

## Arithmetic: operators on your own types

`a + b` calls `a.__add__(b)`. If that returns `NotImplemented`, Python tries `b.__radd__(a)`, which makes mixed types work in either order:

```python
class Vector:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __repr__(self):
        return f"Vector({self.x}, {self.y})"

    def __add__(self, other):
        return Vector(self.x + other.x, self.y + other.y)

    def __sub__(self, other):
        return Vector(self.x - other.x, self.y - other.y)

    def __mul__(self, scalar):
        return Vector(self.x * scalar, self.y * scalar)

    __rmul__ = __mul__                    # so 3 * v works too

    def __neg__(self):
        return Vector(-self.x, -self.y)

    def __abs__(self):
        return (self.x ** 2 + self.y ** 2) ** 0.5

    def __eq__(self, other):
        return isinstance(other, Vector) and (self.x, self.y) == (other.x, other.y)

    def __bool__(self):
        return bool(self.x or self.y)

a, b = Vector(1, 2), Vector(3, 4)
print(a + b, a - b, a * 3, 3 * a, -a)
print(abs(Vector(3, 4)))
print(bool(Vector(0, 0)), bool(a))
print(sum([a, b, Vector(1, 1)], Vector(0, 0)))
```

```text
Vector(4, 6) Vector(-2, -2) Vector(3, 6) Vector(3, 6) Vector(-1, -2)
5.0
False True
Vector(5, 7)
```

| Operator | Method | Reflected (right-hand) |
|---|---|---|
| `a + b` | `__add__` | `__radd__` |
| `a - b` | `__sub__` | `__rsub__` |
| `a * b` | `__mul__` | `__rmul__` |
| `a / b` | `__truediv__` | `__rtruediv__` |
| `-a` | `__neg__` | |
| `abs(a)` | `__abs__` | |
| `a += b` | `__iadd__` (falls back to `__add__`) | |

`__bool__` controls truthiness in `if v:`. If it is missing, Python tries `__len__`, then treats the object as true.

## Containers: `__len__`, `__getitem__`, `__contains__`, `__iter__`

Implement a few methods and your class behaves like a sequence:

```python
class Deck:
    def __init__(self):
        self.cards = [rank + suit for suit in "SH" for rank in "A23"]

    def __len__(self):
        return len(self.cards)

    def __getitem__(self, index):
        return self.cards[index]

    def __contains__(self, card):
        return card in self.cards

deck = Deck()
print(len(deck), deck[0], deck[-1], deck[1:3])
print("AS" in deck, "KD" in deck)
print([c for c in deck][:3])
print(list(reversed(deck))[:2])
```

```text
6 AS 3H ['2S', '3S']
True False
['AS', '2S', '3S']
['3H', '2H']
```

We only wrote `__len__`, `__getitem__` and `__contains__`, yet slicing, looping, `reversed` and `in` all work. Python falls back to calling `__getitem__` with 0, 1, 2, ... for iteration. To control iteration explicitly, add `__iter__` (a generator method is the easiest way):

```python
class Countdown:
    def __init__(self, start):
        self.start = start

    def __iter__(self):
        n = self.start
        while n > 0:
            yield n
            n -= 1

c = Countdown(4)
print(list(c), list(c))
print(sum(c), max(c))
```

```text
[4, 3, 2, 1] [4, 3, 2, 1]
10 4
```

Because `__iter__` returns a **fresh generator each time**, you can loop over a `Countdown` as often as you like, unlike a one-shot iterator (lesson 3.1.3).

For writable containers add `__setitem__` and `__delitem__`:

```python
class Grid:
    def __init__(self, width, height):
        self.width, self.height = width, height
        self.cells = {}

    def __getitem__(self, pos):
        return self.cells.get(pos, ".")

    def __setitem__(self, pos, value):
        x, y = pos
        if not (0 <= x < self.width and 0 <= y < self.height):
            raise IndexError(pos)
        self.cells[pos] = value

    def __delitem__(self, pos):
        self.cells.pop(pos, None)

g = Grid(3, 2)
g[1, 0] = "#"
g[2, 1] = "@"
print([g[x, y] for y in range(2) for x in range(3)])
del g[1, 0]
print(g[1, 0])
```

```text
['.', '#', '.', '.', '.', '@']
.
```

`g[1, 0]` passes the tuple `(1, 0)` as the index, which is how multi-dimensional indexing works.

## Calling objects: `__call__`

An object with `__call__` can be used like a function, and unlike a function it can **carry state**:

```python
class Multiplier:
    def __init__(self, factor):
        self.factor = factor
        self.calls = 0

    def __call__(self, n):
        self.calls += 1
        return n * self.factor

triple = Multiplier(3)
print(triple(5), triple(10), triple.calls)
print(callable(triple), list(map(triple, [1, 2, 3])))
```

```text
15 30 2
True [3, 6, 9]
```

You have seen the same idea as a closure (lesson 3.1.5). A callable class is the heavier version, useful when the function needs several pieces of state and extra methods.

## Context managers: `__enter__` and `__exit__`

The `with` statement calls two dunder methods. Lesson 3.3.2 covers them fully, but here is the shape:

```python
class Section:
    def __init__(self, name):
        self.name = name

    def __enter__(self):
        print("enter", self.name)
        return self

    def __exit__(self, exc_type, exc, tb):
        print("exit", self.name, "with error" if exc_type else "cleanly")
        return False                      # do not swallow exceptions

with Section("work") as s:
    print("inside", s.name)

try:
    with Section("fail"):
        raise ValueError("boom")
except ValueError:
    print("error propagated")
```

```text
enter work
inside work
exit work cleanly
enter fail
exit fail with error
error propagated
```

## Dynamic attributes: `__getattr__`

`__getattr__` runs **only when normal lookup fails**. It can answer for attributes that do not exist as real fields:

```python
class Settings:
    def __init__(self, **values):
        self._values = values

    def __getattr__(self, name):
        try:
            return self._values[name]
        except KeyError:
            raise AttributeError(name) from None

s = Settings(host="localhost", port=8080)
print(s.host, s.port)
print(getattr(s, "missing", "default"))
print(hasattr(s, "host"), hasattr(s, "nothing"))
```

```text
localhost 8080
default
True False
```

Raising `AttributeError` for unknown names is important, so `hasattr` and `getattr(..., default)` keep working.

## Choosing which dunders to write

You do not need all of them. Match the protocol to the **kind of thing** you are modelling:

| Your class is... | Implement |
|---|---|
| any class | `__repr__` |
| a value (money, point, date) | `__eq__`, `__hash__`, maybe ordering and arithmetic |
| a collection | `__len__`, `__getitem__` or `__iter__`, `__contains__` |
| a function with memory | `__call__` |
| a resource | `__enter__`, `__exit__` |

And never invent your own double-underscore names. Those are reserved for Python.

## Common mistakes

- **Defining `__eq__` without `__hash__`,** making instances unhashable (or defining a hash that uses different fields).
- **Returning `False` instead of `NotImplemented`** for unrelated types in comparisons and arithmetic.
- **A `__repr__` that is hard to read** or returns something other than a string.
- **Mutating `self` in `__add__`.** Operators should return a **new** object.
- **Calling dunders directly** (`x.__len__()`) instead of using `len(x)`.
- **A `__getattr__` that never raises `AttributeError`,** which breaks `hasattr` and can cause infinite recursion.

```python
from functools import total_ordering
from math import gcd

@total_ordering
class Ratio:
    def __init__(self, n, d=1):
        g = gcd(n, d) or 1
        self.n, self.d = n // g, d // g

    def __add__(self, other):
        return Ratio(self.n * other.d + other.n * self.d, self.d * other.d)

    def __eq__(self, other):
        return (self.n, self.d) == (other.n, other.d)

    def __lt__(self, other):
        return self.n * other.d < other.n * self.d

    def __hash__(self):
        return hash((self.n, self.d))

    def __repr__(self):
        return f"Ratio({self.n}, {self.d})"

print(Ratio(1, 2) + Ratio(1, 3), Ratio(2, 4) == Ratio(1, 2), Ratio(1, 3) < Ratio(1, 2))   # Ratio(5, 6) True True
```

```python
class Money:
    def __init__(self, amount, currency):
        self.amount, self.currency = amount, currency

    def __add__(self, other):
        if other == 0:
            return self                     # lets sum() start from 0
        if self.currency != other.currency:
            raise ValueError("currency mismatch")
        return Money(self.amount + other.amount, self.currency)

    __radd__ = __add__

    def __repr__(self):
        return f"Money({self.amount}, {self.currency!r})"

print(sum([Money(5, "EUR"), Money(3, "EUR"), Money(2, "EUR")]))   # Money(10, 'EUR')
```

## Recap

- The **data model** is a set of special `__dunder__` methods that Python's syntax and built-ins call. Implement them and your objects act like built-in types.
- `__repr__` is for developers (always write it), `__str__` for users. `__eq__` needs a matching `__hash__`, and returns `NotImplemented` for unrelated types.
- `__lt__` plus `functools.total_ordering` gives sorting and all comparisons.
- Operators (`__add__`, `__sub__`, `__mul__`, `__neg__`, `__abs__`) return **new** objects. The `__r...__` forms make mixed-type and `sum()` work, and `__bool__` controls truthiness.
- Container protocol: `__len__`, `__getitem__`, `__contains__`, `__iter__` (and `__setitem__`, `__delitem__` for writing). `__call__` makes an object callable and `__enter__`/`__exit__` make it a context manager.
- `__getattr__` answers for missing attributes and must raise `AttributeError` for unknown names.
