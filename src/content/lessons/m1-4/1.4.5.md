# Tuples & Structural Unpacking

A **tuple** is a list's quieter sibling: an ordered group of values that **cannot be changed** after it is created. That restriction turns out to be a feature. Tuples signal "this is one fixed record", they are safe from the aliasing bugs of the last lesson, and they make one of Python's nicest tricks possible: unpacking.

## Creating tuples

Tuples are usually written with parentheses.

```python
point = (3, 4)
rgb = (255, 128, 0)
single = (7,)
empty = ()

print(point)
print(type(point))
print(single)
print(len(rgb))
```

```text
(3, 4)
<class 'tuple'>
(7,)
3
```

A tuple with one item needs a trailing comma. `(7)` is just the number 7 in parentheses, while `(7,)` is a tuple. In fact it is the comma that makes the tuple, not the parentheses, so `x = 1, 2` also creates one.

## Indexing and slicing still work

Everything you learned about reading sequences applies.

```python
point = (10, 20, 30, 40)

print(point[0])
print(point[-1])
print(point[1:3])
print(20 in point)
```

```text
10
40
(20, 30)
True
```

## Immutability

What you cannot do is change one.

```python error
point = (3, 4)
point[0] = 9
```

```text
Traceback (most recent call last):
  File "main.py", line 2, in <module>
    point[0] = 9
TypeError: 'tuple' object does not support item assignment
```

There is also no `append`, `remove` or `sort`. To "modify" a tuple you build a new one:

```python
point = (3, 4)
point = (9,) + point[1:]
print(point)
```

```text
(9, 4)
```

**When should you use a tuple instead of a list?** Use a tuple for a fixed group of related values that together describe one thing: a coordinate, a colour, a name and an age. Use a list for a collection that grows, shrinks or is reordered, and whose items are all the same kind of thing.

## Unpacking

You can assign a tuple's items to separate names in one step. The number of names must match the number of items.

```python
point = (3, 4)
x, y = point
print(x)
print(y)

name, age, city = ("Ada", 36, "London")
print(f"{name} is {age} and lives in {city}")
```

```text
3
4
Ada is 36 and lives in London
```

This is far more readable than `point[0]` and `point[1]`, because the names say what each value means.

Mismatched counts are an error:

```python error
a, b = (1, 2, 3)
```

```text
Traceback (most recent call last):
  File "main.py", line 1, in <module>
    a, b = (1, 2, 3)
ValueError: too many values to unpack (expected 2)
```

## Swapping

The variable swap from lesson 1.1.2 is unpacking in disguise. The right side builds a tuple, and the left side unpacks it.

```python
a, b = 1, 2
a, b = b, a
print(a, b)
```

```text
2 1
```

## Star unpacking

Prefix one name with `*` to make it collect **everything that is left over** into a list.

```python
first, *rest = [10, 20, 30, 40]
print(first)
print(rest)

*start, last = [10, 20, 30, 40]
print(start)
print(last)

head, *middle, tail = "abcdef"
print(head, middle, tail)
```

```text
10
[20, 30, 40]
[10, 20, 30]
40
a ['b', 'c', 'd', 'e'] f
```

Only one starred name is allowed in a single unpacking. It always receives a list, even when the right side was a tuple or a string.

A telemetry-style example, where each reading is a timestamp, some coordinates and a status:

```python
reading = (1700000000, 12.5, 48.1, 3.2, "OK")
timestamp, *coords, status = reading

print(timestamp)
print(coords)
print(status)
```

```text
1700000000
[12.5, 48.1, 3.2]
OK
```

## Unpacking in loops

When a list holds tuples, unpack each one right in the `for` line. This is the most common use of all.

```python
students = [("Ada", 91), ("Linus", 84), ("Grace", 97)]

for name, score in students:
    print(f"{name:<6} {score}")
```

```text
Ada    91
Linus  84
Grace  97
```

`enumerate` hands you tuples of `(index, item)`, which is why `for i, item in enumerate(...)` works. It is unpacking in action.

## Returning several values

Python functions, introduced in module 1.5, return multiple values by packing them in a tuple. A built-in example is `divmod`:

```python
result = divmod(197, 60)
print(result)

hours, minutes = divmod(197, 60)
print(hours, minutes)
```

```text
(3, 17)
3 17
```

Unpacking the result immediately gives each part a meaningful name.

## Sorting tuples

Tuples compare position by position, so lists of tuples sort neatly: by the first item, then by the second to break ties.

```python
pairs = [(2, "b"), (1, "z"), (2, "a"), (1, "c")]
print(sorted(pairs))
```

```text
[(1, 'c'), (1, 'z'), (2, 'a'), (2, 'b')]
```

To sort by a different position, pass a `key`:

```python
students = [("Ada", 91), ("Linus", 84), ("Grace", 97)]
ranked = sorted(students, key=lambda s: s[1], reverse=True)
print(ranked)
```

```text
[('Grace', 97), ('Ada', 91), ('Linus', 84)]
```

The `lambda s: s[1]` is a tiny anonymous function that picks the second item. Lesson 1.7.5 explains `lambda` properly. For now, read it as "sort by item 1 of each tuple".

## Immutable does not mean deeply frozen

A tuple's own slots cannot change, but if one of them holds a **mutable** object, that object can still change.

```python
record = ("config", [1, 2])
record[1].append(3)
print(record)
```

```text
('config', [1, 2, 3])
```

The tuple still holds the same list, and the list itself changed. The tuple guarantees which objects it holds, not that those objects stay the same.

## Common mistakes

- **`(7)` instead of `(7,)`.** One-item tuples need a trailing comma.
- **Trying to assign to an index.** Build a new tuple, or use a list if the data needs to change.
- **Mismatched unpacking counts.** `a, b = (1, 2, 3)` raises `ValueError`. Use `*` to collect extras.
- **Using two starred names.** Only one `*` is allowed per unpacking.
- **Assuming a tuple is fully frozen.** A mutable item inside can still change.

## Recap

- A tuple is an ordered, **immutable** group of values: `(a, b)`. One-item tuples need a comma: `(a,)`.
- Indexing, slicing, `len` and `in` work as on lists. Assigning to an item raises `TypeError`.
- Unpacking assigns items to names in one step: `x, y = point`. Swaps and loops over pairs use it.
- `*name` collects the leftovers into a list.
- Use tuples for fixed records and lists for collections that change.
