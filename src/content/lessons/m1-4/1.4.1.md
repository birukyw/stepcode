# Zero-Based Indexing & Negative Offsets

So far each variable has held a single value. Real data comes in groups: the days of the week, the scores in a game, the lines of a file. A **list** holds an ordered group of values under one name. This lesson introduces lists, how to reach any item by its position, and why Python counts from zero.

## Making a list

A list is written with square brackets and commas.

```python
colors = ["red", "green", "blue"]
scores = [90, 72, 85, 100]
mixed = ["Ada", 36, True, 3.5]
empty = []

print(colors)
print(len(scores))
print(empty)
```

```text
['red', 'green', 'blue']
4
[]
```

A list can hold any values, including a mix of types, and `len()` tells you how many items it has. An empty list is falsy, as you saw in module 1.2.

## Indexing

Each item has a numbered position called its **index**. To get an item, put its index in square brackets after the list's name.

```python
colors = ["red", "green", "blue"]

print(colors[0])
print(colors[1])
print(colors[2])
```

```text
red
green
blue
```

The first item is at index **0**, not 1. A list of `n` items has indexes `0` through `n - 1`.

## Why zero?

Think of the index as an **offset**, the distance from the start. The first item is zero steps from the start, the second is one step away, and so on. This is how memory works under the hood, and it makes arithmetic with positions clean. It is also why `range(n)` starts at 0 and gives exactly `n` numbers.

```text
index:   0       1        2
       ["red", "green", "blue"]
```

> **Tip:** The last valid index is always `len(items) - 1`. A list of 4 items has indexes 0, 1, 2 and 3, and there is no index 4.

## Going past the end

Asking for an index that does not exist is an error you will meet often:

```python error
colors = ["red", "green", "blue"]
print(colors[3])
```

```text
Traceback (most recent call last):
  File "main.py", line 2, in <module>
    print(colors[3])
IndexError: list index out of range
```

Read it literally: the list has no position 3. This is the classic **off-by-one** error, and it comes from forgetting that indexes start at 0.

## Negative indexes

Python also lets you count **backward from the end**. Index `-1` is the last item, `-2` is the second to last, and so on.

```python
colors = ["red", "green", "blue"]

print(colors[-1])
print(colors[-2])
print(colors[-3])
```

```text
blue
green
red
```

| Index | 0 | 1 | 2 |
|---|---|---|---|
| Item | `"red"` | `"green"` | `"blue"` |
| Negative index | -3 | -2 | -1 |

Negative indexes are the clean way to reach the end. `items[-1]` works for a list of any length, whereas `items[len(items) - 1]` says the same thing the long way round. The valid range for a list of `n` items is `-n` to `n - 1`.

## Changing an item

Unlike strings, lists can be modified in place. Assign to an index to replace that item.

```python
scores = [90, 72, 85, 100]
scores[1] = 75
scores[-1] = 99
print(scores)
```

```text
[90, 75, 85, 99]
```

The list itself stays the same object. Only one of its slots now points at a different value. This ability to change in place is called **mutability**, and lesson 1.4.4 explains why it matters so much.

## Looping over a list

A `for` loop visits each item directly, with no index needed.

```python
colors = ["red", "green", "blue"]

for color in colors:
    print(color.upper())
```

```text
RED
GREEN
BLUE
```

When you also need the position, use `enumerate`:

```python
colors = ["red", "green", "blue"]

for i, color in enumerate(colors):
    print(i, color)
```

```text
0 red
1 green
2 blue
```

## Membership

The `in` operator checks whether a value is present anywhere in the list, and `.index()` tells you where.

```python
colors = ["red", "green", "blue"]

print("green" in colors)
print("pink" in colors)
print(colors.index("blue"))
```

```text
True
False
2
```

`.index()` raises a `ValueError` if the value is missing, so test with `in` first when you are not sure.

## Lists of lists

Items can themselves be lists, which is how you model a grid or table. Use two indexes: first the row, then the column.

```python
grid = [
    [1, 2, 3],
    [4, 5, 6],
    [7, 8, 9],
]

print(grid[0])
print(grid[1][2])
print(grid[-1][0])
```

```text
[1, 2, 3]
6
7
```

`grid[1]` is the whole second row, `[4, 5, 6]`, and `[2]` then picks the third item from it. Reading from left to right, you drill in one level at a time.

## Indexing strings too

Strings are sequences, so they support the same indexing:

```python
word = "python"

print(word[0])
print(word[-1])
print(len(word))
```

```text
p
n
6
```

Lesson 1.4.6 looks at what strings share with lists and where they differ.

## Common mistakes

- **Using `len(items)` as an index.** It is one past the end. The last index is `len(items) - 1`, or just `-1`.
- **Thinking the first item is at index 1.** It is at index 0.
- **Indexing an empty list.** `[][0]` is an `IndexError`. Check with `if items:` first.
- **Confusing `items[1]` with `items[-1]`.** The second item versus the last item.
- **Forgetting that `grid[row][col]` reads row first.**

## Recap

- A list holds an ordered group of values: `[a, b, c]`. `len()` gives its size.
- Indexes count from 0. The valid range is `0` to `len - 1`.
- Negative indexes count from the end: `-1` is the last item.
- Out-of-range access raises `IndexError`. Lists can be changed in place by assigning to an index.
- `for item in items` loops over values, `enumerate` adds positions, and `in` tests membership.
- Nested lists model grids: `grid[row][col]`.
