# The Aliasing Trap

This lesson is the payoff for the label picture you built in lesson 1.1.2. Variables are names attached to values. For numbers and strings that rarely mattered, because those values cannot change. Lists **can** change, and then two names on one list becomes one of the most common sources of bugs in Python.

## Two names, one list

```python
team_a = ["Ada", "Linus"]
team_b = team_a

team_b.append("Grace")

print(team_a)
print(team_b)
```

```text
['Ada', 'Linus', 'Grace']
['Ada', 'Linus', 'Grace']
```

`team_b = team_a` did not copy anything. It attached a second name to the **same list**. When you change the list through either name, the change shows up through both. This is called **aliasing**: two names for one object.

## Same object or equal objects

Two different questions are easy to mix up. `==` asks whether two values have **equal contents**. `is` asks whether two names point at the **same object**. `id()` shows an object's identity number.

```python
a = [1, 2, 3]
b = a
c = [1, 2, 3]

print(a == c)
print(a is b)
print(a is c)
print(id(a) == id(b))
```

```text
True
True
False
True
```

`a` and `c` have equal contents but are two separate lists, so `a == c` is true while `a is c` is false. `a` and `b` are one list with two names, so every identity check agrees.

## Why numbers and strings are safe

Numbers, strings and tuples are **immutable**: they cannot be changed after they are created. When you "change" one, you actually attach the name to a different value, so no other name is affected.

```python
x = "cat"
y = x
x = x + "s"

print(x)
print(y)
```

```text
cats
cat
```

`x + "s"` built a brand new string and moved the name `x` to it. `y` still points at the old string. Aliasing only causes surprises for **mutable** values such as lists, and, later, dictionaries and sets.

## Making a real copy

To get an independent list, copy it explicitly. There are three common ways, and they all do the same thing:

```python
original = [1, 2, 3]

copy1 = original.copy()
copy2 = original[:]
copy3 = list(original)

copy1.append(99)

print(original)
print(copy1)
print(copy2 == original, copy3 == original)
```

```text
[1, 2, 3]
[1, 2, 3, 99]
True True
```

Each of those produced a **new list** with the same items. Changing `copy1` left `original` alone.

## The inventory bug

Aliasing is usually found in code like this. Two players should have separate inventories, but they start from a shared template:

```python
template = ["sword", "potion"]

player_one = template
player_two = template

player_one.append("shield")

print(player_two)
```

```text
['sword', 'potion', 'shield']
```

Player two received a shield they never picked up. The fix is to give each player their own copy:

```python
template = ["sword", "potion"]

player_one = template.copy()
player_two = template.copy()

player_one.append("shield")

print(player_one)
print(player_two)
```

```text
['sword', 'potion', 'shield']
['sword', 'potion']
```

> **Why it matters:** In real programs the two names are rarely adjacent lines. One is a variable inside a function, and the other is a list that was passed in. Changing the list through one name silently changes the caller's data. Knowing to ask "is this a copy or the same object?" will save you hours.

## Shallow copies and nested lists

The copies above are **shallow**. They copy the outer list, but the items inside are shared. For flat lists of numbers or strings that is fine. For a list that contains other lists, the inner lists are still aliased.

```python
board = [[0, 0], [0, 0]]
shallow = board.copy()

shallow[0][0] = 9

print(board)
print(shallow)
```

```text
[[9, 0], [0, 0]]
[[9, 0], [0, 0]]
```

`shallow` is a new outer list, but its two inner lists are the very same objects as in `board`. Changing one cell through `shallow` changed `board` too.

For a fully independent copy of nested data, use `copy.deepcopy`:

```python
import copy

board = [[0, 0], [0, 0]]
deep = copy.deepcopy(board)

deep[0][0] = 9

print(board)
print(deep)
```

```text
[[0, 0], [0, 0]]
[[9, 0], [0, 0]]
```

`deepcopy` copies every level, recursively. It costs more, so use it only when you genuinely need nested independence.

## The repeated-rows bug

The most infamous aliasing bug builds a grid with multiplication:

```python
grid = [[0] * 3] * 3
grid[0][0] = 1
print(grid)
```

```text
[[1, 0, 0], [1, 0, 0], [1, 0, 0]]
```

`[[0] * 3] * 3` does not make three rows. It makes **one** row and puts three references to it in the outer list. Setting one cell changed all three "rows", because they are all the same list.

Build each row separately instead:

```python
grid = []
for _ in range(3):
    grid.append([0] * 3)

grid[0][0] = 1
print(grid)
```

```text
[[1, 0, 0], [0, 0, 0], [0, 0, 0]]
```

This time each pass through the loop created a fresh row. (`[0] * 3` is safe here because the items are numbers, which are immutable.)

## A quick rule

Ask two questions whenever you assign or pass a list around:

1. **Did I create a new list, or did I attach another name to an existing one?** `b = a`, passing it to a function, and `[row] * n` all share. Slicing, `.copy()`, `list()` and `+` all create new lists.
2. **Is it nested?** If yes, a shallow copy is not enough.

## Common mistakes

- **`b = a` to copy a list.** It aliases. Use `a.copy()` or `a[:]`.
- **Copying a nested list shallowly.** The inner lists remain shared. Use `copy.deepcopy`.
- **`[[0] * n] * m` for a grid.** Every row is the same object. Build rows in a loop.
- **Comparing with `is` when you mean `==`.** Use `is` only for `None` and identity questions.
- **Assuming strings can alias harmfully.** They cannot, because they are immutable.

## Recap

- `b = a` makes a second name for the same object. It never copies.
- Mutable values (lists) can be changed through any name, so aliases see the change. Immutable values cannot.
- `==` compares contents. `is` compares identity.
- Copy with `.copy()`, `[:]` or `list()`. Nested data needs `copy.deepcopy`.
- Never build a grid with `[[0] * n] * m`. Create each row in a loop.
