# Variables Are Labels, Not Boxes

Most people are taught that a variable is a box with a value inside. The picture works for a while and then quietly breaks. A more accurate picture is a **name tag** attached to a value. This lesson builds that picture, because everything in later modules, from lists to functions, depends on it.

## Creating a variable

Use `=` to attach a name to a value. This is called **assignment**.

```python
player = "Ada"
level = 3
print(player)
print(level)
```

```text
Ada
3
```

Read `level = 3` as "the name `level` now points at the value `3`". The `=` sign here does not mean "is equal to" as it does in maths. It means "attach this name to that value".

The right-hand side always runs first. Python works out the value, then attaches the name.

## Reassignment moves the tag

You can point a name at something else whenever you like.

```python
level = 3
level = level + 1
print(level)
```

```text
4
```

On the second line Python evaluates `level + 1` using the current value (`3`), gets `4`, and only then moves the tag. The old value is not changed. The tag simply points somewhere new.

> **Why it matters:** `level = level + 1` looks impossible in maths, since no number equals itself plus one. In programming it is perfectly normal, because it describes a sequence of steps and not an equation.

## Two names, one value

```python
a = 10
b = a
a = 99
print(a)
print(b)
```

```text
99
10
```

`b = a` does not link `b` to `a`. It attaches a second tag to the value that `a` currently points at, which is `10`. When `a` later moves to `99`, `b` stays where it was.

You can ask Python whether two names point at the very same object with `is`:

```python
a = 10
b = a
print(a is b)
a = 99
print(a is b)
```

```text
True
False
```

## A preview of why this matters

Numbers and strings never change once they exist. Some other values, like lists, **can** be changed in place. Then two tags on one value behave very differently:

```python
team_a = ["Ada", "Linus"]
team_b = team_a
team_b.append("Grace")
print(team_a)
```

```text
['Ada', 'Linus', 'Grace']
```

Nobody touched `team_a`, yet it changed. There is only one list and both names point at it. If you pictured variables as boxes you would expect two separate lists. The label picture predicts the real behaviour. Module 1.4 returns to this in depth.

## Updating a variable in place

Reassigning a variable using its own value is so common that Python has shortcuts:

```python
score = 10
score += 5     # same as score = score + 5
score -= 2     # same as score = score - 2
score *= 3     # same as score = score * 3
print(score)
```

```text
39
```

There is also `/=`, `//=`, `%=` and `**=`.

## Several names at once

You can assign more than one name in a single line. Python evaluates everything on the right first, which makes swapping two values easy:

```python
x, y = 3, 8
print(x, y)

x, y = y, x
print(x, y)
```

```text
3 8
8 3
```

Many languages need a third temporary variable for a swap. Python does not, because the right-hand side `y, x` is fully evaluated before either name moves.

## Naming rules

- Use letters, digits and underscores, and do not start with a digit. `score2` is fine and `2score` is not.
- Names are case sensitive. `Score` and `score` are different names.
- Do not use Python's reserved words such as `if`, `for`, `class` or `None`.
- Spaces and hyphens are not allowed. `max-health` would be read as `max minus health`.

## Naming well

Python programmers follow conventions so that code looks familiar to everyone.

- Use `snake_case` for variables: `max_health`, not `maxHealth` or `MaxHealth`.
- Choose names that say what the value means. `seconds_left` beats `x`, and `price_per_kg` beats `p`.
- Write constants, which are values you never intend to change, in `UPPER_CASE`: `TAX_RATE = 0.2`. Python does not enforce it, but everyone who reads your code will understand the intent.

```python
TAX_RATE = 0.2
price = 80
tax = price * TAX_RATE
total = price + tax
print(total)
```

```text
96.0
```

## Common mistakes

- **Using a name before assigning it.** That gives a `NameError`, as you saw in the previous lesson.
- **Misspelling a name.** `scroe` is a brand new name, so Python reports it as undefined.
- **Believing `b = a` links them.** It copies the tag, not a connection.
- **Reusing one name for unrelated things.** It works, but the code becomes hard to follow.

## Recap

- A variable is a name attached to a value.
- `=` evaluates the right side first, then attaches the name.
- Reassignment moves the tag. It never changes the old value.
- `b = a` gives one value two names.
- Use `snake_case`, descriptive names, and `UPPER_CASE` for constants.
