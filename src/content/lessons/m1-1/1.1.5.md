# Shape-Shifting Types & Input

Every value in Python has a **type**. The type decides which operations make sense: you can multiply numbers, but you cannot multiply a number by a word. Understanding types, and how to convert between them, removes a whole category of beginner bugs. It also unlocks `input()`, which lets a program talk to its user.

## The basic types

You have already met three. There is one more worth knowing now.

| Type | Holds | Example |
|---|---|---|
| `int` | whole numbers | `7` |
| `float` | decimal numbers | `7.5` |
| `str` | text | `"7"` |
| `bool` | `True` or `False` | `True` |

Ask Python for a value's type with `type()`:

```python
print(type(7))
print(type(7.5))
print(type("7"))
print(type(True))
print(type(None))
```

```text
<class 'int'>
<class 'float'>
<class 'str'>
<class 'bool'>
<class 'NoneType'>
```

`None` is a special value meaning "nothing here yet". It has its own type.

`7` and `"7"` look alike but are completely different things. That difference is behind a classic bug.

## The checkout bug

```python
print(15 + 20)
print("15" + "20")
```

```text
35
1520
```

The first line adds numbers and prints `35`. The second joins text and prints `1520`. The same `+` symbol does different jobs depending on the type. When a program that adds two prices prints `1520`, a number has been stored as text somewhere.

## Mixing types

Python is strict about mixing types. It will not guess.

```python error
print("Total: " + 35)
```

```text
Traceback (most recent call last):
  File "main.py", line 1, in <module>
    print("Total: " + 35)
TypeError: can only concatenate str (not "int") to str
```

There are two ways to fix it: convert the number to text, or use an f-string, which does the conversion for you.

```python
total = 35
print("Total: " + str(total))
print(f"Total: {total}")
```

```text
Total: 35
Total: 35
```

Numbers mix fine with each other. An `int` combined with a `float` becomes a `float`.

```python
print(3 + 0.5)
print(type(3 + 0.5))
```

```text
3.5
<class 'float'>
```

## Converting types

Use the type name as a function to convert a value.

```python
print(int("15") + int("20"))
print(float("2.5") * 2)
print(str(100) + " points")
print(int(3.9))
print(float(7))
```

```text
35
5.0
100 points
3
7.0
```

- `int(x)` makes a whole number. From a float it **cuts off** the decimals and does not round, so `int(3.9)` is `3` and `int(-3.9)` is `-3`.
- `float(x)` makes a decimal.
- `str(x)` makes text, so it can be joined to other text.

Conversions can fail if the text is not a valid number:

```python error
print(int("hello"))
```

```text
Traceback (most recent call last):
  File "main.py", line 1, in <module>
    print(int("hello"))
ValueError: invalid literal for int() with base 10: 'hello'
```

`int("3.5")` also fails, because `"3.5"` is not a whole number as written. Convert through a float first: `int(float("3.5"))` gives `3`. Surrounding spaces are fine, so `int(" 42 ")` is `42`.

## Truth values

`bool(x)` converts anything to `True` or `False`. Most values are `True`. A few are `False`: zero, an empty string, and `None`.

```python
print(bool(1), bool(0))
print(bool("hello"), bool(""))
print(bool("0"))
```

```text
True False
True False
True
```

Notice that `bool("0")` is `True`. It is a non-empty string, and the content does not matter. Module 1.2 explores this in detail.

## Reading input

`input()` pauses the program, optionally shows a prompt, waits for the user to type a line, and returns what they typed **as a string**, whatever they typed.

```python
name = input("Your name: ")
print("Nice to meet you, " + name)
```

In this editor, type the answers into the **Input** box under the terminal, one answer per line, before you press Run. A real terminal would wait for you to type.

Because the result is always a string, doing arithmetic on it needs a conversion:

```python
age = int(input("Age: "))
print("Next year you will be", age + 1)
```

> **Remember:** `input()` always returns a `str`. Convert it as soon as you read it: `int(input(...))` or `float(input(...))`.

Skipping the conversion is exactly the checkout bug from earlier:

```python
first = input("First number: ")
second = input("Second number: ")
print(first + second)
```

Put `15` and `20` on separate lines in the Input box. This prints `1520`, because the values are still strings.

## Putting it together

A small calculator that reads two numbers and reports the results in a tidy format:

```python
a = float(input("First number: "))
b = float(input("Second number: "))

print(f"Sum:        {a + b:.2f}")
print(f"Difference: {a - b:.2f}")
print(f"Product:    {a * b:.2f}")
print(f"Average:    {(a + b) / 2:.2f}")
```

With `15` and `20` as input:

```text
Sum:        35.00
Difference: -5.00
Product:    300.00
Average:    17.50
```

## Common mistakes

- **Skipping `int()` after `input()`.** You get string behaviour. `"15" + "20"` joins text.
- **Using `int()` to round.** It truncates. Use `round()` for rounding.
- **Converting too late.** Convert once, right after reading, and use the number from then on.
- **Trusting user input.** Users type `ten` instead of `10`. Robust handling of this arrives with decisions in module 1.2 and exceptions in Track 3.

## Recap

- Every value has a type: `int`, `float`, `str`, `bool` and `None` so far.
- Python will not guess when types are mixed. Convert with `int()`, `float()` and `str()`.
- `int()` truncates and does not round. Conversions can fail with `ValueError`.
- `input()` always returns a string. Convert it right away.
