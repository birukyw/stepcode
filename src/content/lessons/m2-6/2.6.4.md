# 2D Dynamic Programming: Knapsack, Grids & Edit Distance

When a problem has **two** things that change, one number is not enough to describe where you are. How many items have I considered, *and* how much capacity is left? How far along the first word am I, *and* the second? The state becomes a pair, so the table becomes a **grid**. The recipe from the last lesson stays exactly the same. You just fill a 2D table.

## Grid paths: the gentlest 2D DP

How many ways can a robot go from the top-left to the bottom-right of a grid, moving only right or down?

- State: `paths[r][c]` = number of ways to reach cell `(r, c)`.
- Transition: you arrive from above or from the left: `paths[r][c] = paths[r-1][c] + paths[r][c-1]`.
- Base: the first row and first column each have exactly 1 way.

```python
def grid_paths(rows, cols):
    paths = [[1] * cols for _ in range(rows)]
    for r in range(1, rows):
        for c in range(1, cols):
            paths[r][c] = paths[r - 1][c] + paths[r][c - 1]
    return paths[-1][-1]

print(grid_paths(3, 3), grid_paths(3, 7), grid_paths(18, 18))
```

```text
6 28 2333606220
```

The table has `rows × cols` cells, each filled in O(1): **O(rows × cols)**. Brute force would explore a number of routes that grows exponentially.

A variation with **costs**: the cheapest path through a grid of weights.

```python
def min_path_sum(grid):
    rows, cols = len(grid), len(grid[0])
    dp = [[0] * cols for _ in range(rows)]
    dp[0][0] = grid[0][0]
    for c in range(1, cols):
        dp[0][c] = dp[0][c - 1] + grid[0][c]
    for r in range(1, rows):
        dp[r][0] = dp[r - 1][0] + grid[r][0]
    for r in range(1, rows):
        for c in range(1, cols):
            dp[r][c] = grid[r][c] + min(dp[r - 1][c], dp[r][c - 1])
    return dp[-1][-1]

print(min_path_sum([[1, 3, 1], [1, 5, 1], [4, 2, 1]]))
```

```text
7
```

## 0/1 Knapsack

You have a backpack with a weight capacity and some items, each with a weight and a value. You may take each item **at most once**. Maximize total value.

Greedy ("best value per kilo") does not always work. DP does:

- State: `dp[i][w]` = the best value using only the first `i` items with capacity `w`.
- Transition: for item `i`, either **skip it** (`dp[i-1][w]`) or, if it fits, **take it** (`dp[i-1][w - weight] + value`): take the better.
- Base: `dp[0][w] = 0` (no items, no value).

```python
def knapsack(weights, values, capacity):
    n = len(weights)
    dp = [[0] * (capacity + 1) for _ in range(n + 1)]
    for i in range(1, n + 1):
        for w in range(capacity + 1):
            dp[i][w] = dp[i - 1][w]                                   # skip
            if weights[i - 1] <= w:
                take = dp[i - 1][w - weights[i - 1]] + values[i - 1]
                dp[i][w] = max(dp[i][w], take)
    return dp[n][capacity]

print(knapsack([1, 3, 4, 5], [1, 4, 5, 7], 7))
print(knapsack([10, 20, 30], [60, 100, 120], 50))
```

```text
9
220
```

The second case is the famous counterexample for greedy: the best value per weight is the 10 kg item (6 per kg), then 20 kg (5), then 30 kg (4). Greedy takes the first two for 160. DP finds that the 20 kg and 30 kg items together are worth 220.

The cost is **O(n × capacity)**. This is called **pseudo-polynomial**: it is fast when the capacity is a modest number, but grows with the *value* of the capacity, not just the size of the input.

### Shrinking the table

Row `i` only needs row `i - 1`, so keep **one row**. Iterate the capacity **downwards** so each item is used at most once:

```python
def knapsack_1d(weights, values, capacity):
    dp = [0] * (capacity + 1)
    for wt, val in zip(weights, values):
        for w in range(capacity, wt - 1, -1):      # backwards: dp[w - wt] is still the old row
            dp[w] = max(dp[w], dp[w - wt] + val)
    return dp[capacity]

print(knapsack_1d([1, 3, 4, 5], [1, 4, 5, 7], 7))
print(knapsack_1d([10, 20, 30], [60, 100, 120], 50))
```

```text
9
220
```

Going **forwards** would let an item be used repeatedly, which solves the **unbounded** knapsack, like the coin problems of the last lesson. A single loop direction decides which problem you solve.

## Longest common subsequence (LCS)

Given two strings, the longest sequence of characters that appears in both **in order** (not necessarily adjacent). It is how `diff` tools find what stayed the same.

- State: `dp[i][j]` = LCS length of the first `i` characters of `a` and the first `j` of `b`.
- Transition: if `a[i-1] == b[j-1]`, the match extends the LCS of both shorter prefixes: `dp[i-1][j-1] + 1`. Otherwise skip one character from either: `max(dp[i-1][j], dp[i][j-1])`.

```python
def lcs(a, b):
    dp = [[0] * (len(b) + 1) for _ in range(len(a) + 1)]
    for i in range(1, len(a) + 1):
        for j in range(1, len(b) + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
    return dp[-1][-1]

print(lcs("abcde", "ace"))
print(lcs("AGGTAB", "GXTXAYB"))
print(lcs("abc", "def"))
```

```text
3
4
0
```

To get the subsequence itself, walk back from `dp[len(a)][len(b)]`: if the characters match, take it and move diagonally, otherwise move toward the larger neighbour.

```python
def lcs_string(a, b):
    dp = [[0] * (len(b) + 1) for _ in range(len(a) + 1)]
    for i in range(1, len(a) + 1):
        for j in range(1, len(b) + 1):
            dp[i][j] = dp[i - 1][j - 1] + 1 if a[i - 1] == b[j - 1] else max(dp[i - 1][j], dp[i][j - 1])
    out, i, j = [], len(a), len(b)
    while i and j:
        if a[i - 1] == b[j - 1]:
            out.append(a[i - 1])
            i -= 1
            j -= 1
        elif dp[i - 1][j] >= dp[i][j - 1]:
            i -= 1
        else:
            j -= 1
    return "".join(reversed(out))

print(lcs_string("AGGTAB", "GXTXAYB"))
```

```text
GTAB
```

## Edit distance

The fewest single-character edits (insert, delete, replace) to turn one word into another. It powers spell checkers and "did you mean" suggestions.

- State: `dp[i][j]` = edit distance between the first `i` characters of `a` and the first `j` of `b`.
- Base: turning `a[:i]` into an empty string costs `i` deletions, and the reverse costs `j` insertions.
- Transition: if the last characters match, no cost: `dp[i-1][j-1]`. Otherwise take `1 +` the cheapest of **delete** (`dp[i-1][j]`), **insert** (`dp[i][j-1]`) and **replace** (`dp[i-1][j-1]`).

```python
def edit_distance(a, b):
    dp = [[0] * (len(b) + 1) for _ in range(len(a) + 1)]
    for i in range(len(a) + 1):
        dp[i][0] = i
    for j in range(len(b) + 1):
        dp[0][j] = j
    for i in range(1, len(a) + 1):
        for j in range(1, len(b) + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1]
            else:
                dp[i][j] = 1 + min(dp[i - 1][j], dp[i][j - 1], dp[i - 1][j - 1])
    return dp[-1][-1]

print(edit_distance("kitten", "sitting"))
print(edit_distance("horse", "ros"))
print(edit_distance("", "abc"), edit_distance("same", "same"))
```

```text
3
3
3 0
```

`kitten` to `sitting` takes 3 edits: replace k with s, replace e with i, insert g. A search box can use this to suggest the closest known word.

```python
def edit_distance(a, b):
    prev = list(range(len(b) + 1))
    for i in range(1, len(a) + 1):
        cur = [i] + [0] * len(b)
        for j in range(1, len(b) + 1):
            if a[i - 1] == b[j - 1]:
                cur[j] = prev[j - 1]
            else:
                cur[j] = 1 + min(prev[j], cur[j - 1], prev[j - 1])
        prev = cur
    return prev[-1]

words = ["python", "pithon", "typhoon", "java", "pylon"]
typed = "pyton"
print(sorted(words, key=lambda w: edit_distance(typed, w))[:3])
```

```text
['python', 'pylon', 'pithon']
```

Keeping only the previous row reduces memory from `n × m` to `m`.

## Memoized 2D DP

The same state pairs also work top-down. Use `@lru_cache` and let the recursion follow the recurrence directly:

```python
from functools import lru_cache

def lcs_memo(a, b):
    @lru_cache(maxsize=None)
    def go(i, j):
        if i == len(a) or j == len(b):
            return 0
        if a[i] == b[j]:
            return 1 + go(i + 1, j + 1)
        return max(go(i + 1, j), go(i, j + 1))
    return go(0, 0)

print(lcs_memo("AGGTAB", "GXTXAYB"))
```

```text
4
```

Memoization only computes the states that are actually reached, which can be fewer. But very long strings can hit the recursion limit, where the table version never does.

## Choosing the state

The skill in DP is choosing **what the state is**. Ask: "what is the least I must know to continue?" For knapsack that was (items considered, capacity left). For strings, (position in A, position in B). Too little information gives wrong answers, too much makes the table enormous.

| Problem | State | Cost |
|---|---|---|
| Grid paths | (row, col) | O(R × C) |
| 0/1 Knapsack | (items used, capacity) | O(n × W) |
| LCS | (i in a, j in b) | O(n × m) |
| Edit distance | (i in a, j in b) | O(n × m) |

## Common mistakes

- **Mixing up `dp[i]` and `a[i]`** (off by one). When `dp` has an extra row for the empty prefix, character `i` of the string is `a[i - 1]`.
- **Iterating the capacity forwards in 1D knapsack,** reusing items by accident.
- **Forgetting the base row and column** in edit distance.
- **`[[0] * m] * n`** for the table. All rows would be the same list.
- **Large tables.** A 10,000 × 10,000 table is 100 million cells. Keep only the rows you need.

def unique_paths_with_obstacles(grid):
    rows, cols = len(grid), len(grid[0])
    dp = [[0] * cols for _ in range(rows)]
    for r in range(rows):
        for c in range(cols):
            if grid[r][c] == 1:
                continue
            if r == 0 and c == 0:
                dp[r][c] = 1
            else:
                dp[r][c] = (dp[r - 1][c] if r else 0) + (dp[r][c - 1] if c else 0)
    return dp[-1][-1]

def longest_common_substring(a, b):
    best = 0
    dp = [[0] * (len(b) + 1) for _ in range(len(a) + 1)]
    for i in range(1, len(a) + 1):
        for j in range(1, len(b) + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
                best = max(best, dp[i][j])
    return best

def subset_sum(nums, target):
    dp = [True] + [False] * target
    for x in nums:
        for s in range(target, x - 1, -1):
            dp[s] = dp[s] or dp[s - x]
    return dp[target]

print(longest_common_substring("abcdxyz", "xyzabcd"), subset_sum([3, 34, 4, 12, 5, 2], 9), subset_sum([3, 34, 4], 30))   # 4 True False

def max_square(matrix):
    if not matrix:
        return 0
    rows, cols = len(matrix), len(matrix[0])
    dp = [[0] * cols for _ in range(rows)]
    best = 0
    for r in range(rows):
        for c in range(cols):
            if matrix[r][c] == "1":
                if r == 0 or c == 0:
                    dp[r][c] = 1
                else:
                    dp[r][c] = 1 + min(dp[r - 1][c], dp[r][c - 1], dp[r - 1][c - 1])
                best = max(best, dp[r][c])
    return best

print(max_square(["10100", "10111", "11111", "10010"]))   # 2

## Recap

- When two quantities change, the DP state is a **pair** and the table is a **grid**. The recipe is unchanged: define `dp[i][j]`, write the transition, set the base row and column, fill in order.
- **Grid paths** add the cell above and to the left. **0/1 knapsack** chooses *skip* or *take* with state (items, capacity), and runs in O(n × W).
- **LCS** and **edit distance** compare two strings with state (i, j): matching characters extend a diagonal, mismatches take the best neighbour (plus 1 for edit distance).
- Keep only the previous row to cut memory. In 1D knapsack iterate capacity **backwards** so each item is used at most once.
- The hard part is choosing the state: the least information you need to continue.
