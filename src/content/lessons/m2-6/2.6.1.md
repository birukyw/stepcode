# Backtracking & State-Space Pruning

Some problems have no formula: you have to **try things**. Place eight queens on a chessboard so none attack each other. Fill in a sudoku. List every way to split a bill. The honest method is to build a solution one choice at a time, and the moment a choice leads nowhere, **undo it and try the next**. That is **backtracking**: a depth-first search through a tree of choices, with the ability to step back.

## The shape of every backtracking solution

Picture a decision tree. At each node you have some partial answer and a set of options. You pick one, go deeper, and when you return you **undo** the pick so the next option starts from a clean slate.

```python
def subsets(items):
    result = []
    current = []

    def explore(i):
        if i == len(items):
            result.append(current[:])          # a complete choice: save a copy
            return
        explore(i + 1)                         # option 1: skip items[i]
        current.append(items[i])               # option 2: take it...
        explore(i + 1)
        current.pop()                          # ...then undo the choice

    explore(0)
    return result

print(subsets([1, 2, 3]))
print(len(subsets(list(range(10)))))
```

```text
[[], [3], [2], [2, 3], [1], [1, 3], [1, 2], [1, 2, 3]]
1024
```

The three beats: **choose**, **explore**, **un-choose**. The `current.pop()` is what makes it backtracking. Two details matter: save a **copy** (`current[:]`), because `current` keeps changing, and the number of results is 2ⁿ, so this approach only suits small inputs.

## Permutations

Every ordering of the items. At each step, pick any item not yet used:

```python
def permutations(items):
    result = []
    used = [False] * len(items)
    current = []

    def explore():
        if len(current) == len(items):
            result.append(current[:])
            return
        for i, item in enumerate(items):
            if used[i]:
                continue
            used[i] = True
            current.append(item)
            explore()
            current.pop()
            used[i] = False

    explore()
    return result

print(permutations(["a", "b", "c"]))
print(len(permutations(list(range(6)))))
```

```text
[['a', 'b', 'c'], ['a', 'c', 'b'], ['b', 'a', 'c'], ['b', 'c', 'a'], ['c', 'a', 'b'], ['c', 'b', 'a']]
720
```

There are n! permutations (720 for 6 items, 3.6 million for 10), so the work explodes quickly. That growth is why **pruning** matters.

## Pruning: abandon doomed paths early

Waiting until a candidate is complete wastes effort when it was already invalid halfway. **Pruning** checks a constraint at every step and cuts a branch the moment it cannot succeed.

**Combination sum:** find every combination of numbers that adds up to a target, using each number any number of times.

```python
def combination_sum(nums, target):
    nums = sorted(nums)
    result = []
    current = []

    def explore(start, remaining):
        if remaining == 0:
            result.append(current[:])
            return
        for i in range(start, len(nums)):
            if nums[i] > remaining:
                break                          # prune: sorted, so every later number is too big too
            current.append(nums[i])
            explore(i, remaining - nums[i])    # i, not i + 1: reuse allowed
            current.pop()

    explore(0, target)
    return result

print(combination_sum([2, 3, 6, 7], 7))
print(combination_sum([2, 3, 5], 8))
```

```text
[[2, 2, 3], [7]]
[[2, 2, 2, 2], [2, 3, 3], [3, 5]]
```

Sorting first lets one `break` cut off every remaining option at once. Passing `start` forward prevents the same combination from appearing in a different order (`[2, 3]` and `[3, 2]`).

## N-Queens: the classic

Place `n` queens on an `n × n` board so no two share a row, column or diagonal. Place one queen per row, and track which columns and diagonals are taken. A queen at `(row, col)` owns the column `col`, the diagonal `row - col` and the anti-diagonal `row + col`:

```python
def n_queens(n):
    cols, diag1, diag2 = set(), set(), set()
    placement = []
    solutions = []

    def explore(row):
        if row == n:
            solutions.append(placement[:])
            return
        for col in range(n):
            if col in cols or (row - col) in diag1 or (row + col) in diag2:
                continue                       # prune: this square is attacked
            cols.add(col); diag1.add(row - col); diag2.add(row + col)
            placement.append(col)
            explore(row + 1)
            placement.pop()
            cols.remove(col); diag1.remove(row - col); diag2.remove(row + col)

    explore(0)
    return solutions

for n in range(1, 9):
    print(n, len(n_queens(n)))
print(n_queens(6)[0])
```

```text
1 1
2 0
3 0
4 2
5 10
6 4
7 40
8 92
[1, 3, 5, 0, 2, 4]
```

Without pruning, 8 queens means trying 64 choose 8, about 4.4 billion placements. With pruning, the search only ever extends boards that are still valid, and it finishes quickly. The set lookups make each check O(1).

## Sudoku solver

The same recipe, with a 9 x 9 grid. Find an empty cell, try each digit that does not break a rule, recurse, and undo on failure:

```python
def solve_sudoku(grid):
    def ok(r, c, d):
        for i in range(9):
            if grid[r][i] == d or grid[i][c] == d:
                return False
        br, bc = r // 3 * 3, c // 3 * 3
        for i in range(3):
            for j in range(3):
                if grid[br + i][bc + j] == d:
                    return False
        return True

    def solve():
        for r in range(9):
            for c in range(9):
                if grid[r][c] == 0:
                    for d in range(1, 10):
                        if ok(r, c, d):
                            grid[r][c] = d
                            if solve():
                                return True
                            grid[r][c] = 0         # undo
                    return False                   # no digit fits: backtrack
        return True                                # no empty cell left: solved

    return solve()

puzzle = [
    [5, 3, 0, 0, 7, 0, 0, 0, 0],
    [6, 0, 0, 1, 9, 5, 0, 0, 0],
    [0, 9, 8, 0, 0, 0, 0, 6, 0],
    [8, 0, 0, 0, 6, 0, 0, 0, 3],
    [4, 0, 0, 8, 0, 3, 0, 0, 1],
    [7, 0, 0, 0, 2, 0, 0, 0, 6],
    [0, 6, 0, 0, 0, 0, 2, 8, 0],
    [0, 0, 0, 4, 1, 9, 0, 0, 5],
    [0, 0, 0, 0, 8, 0, 0, 7, 9],
]
print(solve_sudoku(puzzle))
print(puzzle[0])
print(all(sorted(row) == list(range(1, 10)) for row in puzzle))
```

```text
True
[5, 3, 4, 6, 7, 8, 9, 1, 2]
True
```

Return values carry the answer upward: `True` means "found it, stop", `False` means "this branch failed, the caller should try something else".

## Word search in a grid

Backtracking also walks paths. Can a word be traced through adjacent letters, using each cell once? Mark a cell as used while exploring, and **unmark** on the way back:

```python
def exists(board, word):
    rows, cols = len(board), len(board[0])

    def explore(r, c, i):
        if i == len(word):
            return True
        if not (0 <= r < rows and 0 <= c < cols) or board[r][c] != word[i]:
            return False
        saved, board[r][c] = board[r][c], "#"          # mark as visited
        found = any(explore(r + dr, c + dc, i + 1) for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)))
        board[r][c] = saved                            # un-mark
        return found

    return any(explore(r, c, 0) for r in range(rows) for c in range(cols))

board = [list("ABCE"), list("SFCS"), list("ADEE")]
print(exists(board, "ABCCED"), exists(board, "SEE"), exists(board, "ABCB"))
```

```text
True True False
```

## Avoiding duplicates

If the input contains repeated items, naive backtracking produces repeated answers. The fix: sort, and at each level **skip an item equal to the previous one that you already tried**:

```python
def unique_subsets(nums):
    nums = sorted(nums)
    result, current = [], []

    def explore(start):
        result.append(current[:])
        for i in range(start, len(nums)):
            if i > start and nums[i] == nums[i - 1]:
                continue                       # same value already tried at this depth
            current.append(nums[i])
            explore(i + 1)
            current.pop()

    explore(0)
    return result

print(unique_subsets([1, 2, 2]))
```

```text
[[], [1], [1, 2], [1, 2, 2], [2], [2, 2]]
```

## When backtracking is the wrong tool

Backtracking explores an exponential tree, even with pruning. If the same sub-situation appears again and again, remember the answers and reuse them: that is **dynamic programming**, which is exactly where this module goes next. And if a **local rule** always picks the best choice, you do not need to search at all: that is **greedy**, the next lesson.

## Common mistakes

- **Forgetting to undo** (`pop`, un-mark). State leaks between branches and answers go wrong silently.
- **Saving the live list** instead of a copy. Every result ends up identical (and empty at the end).
- **No pruning.** The search works but takes forever. Ask "what can I rule out early?"
- **Duplicates from repeated inputs.** Sort and skip equal siblings.
- **Recursing without a base case,** or one that never triggers.

def combinations(n, k):
    result, current = [], []
    def explore(start):
        if len(current) == k:
            result.append(current[:])
            return
        for x in range(start, n + 1):
            current.append(x)
            explore(x + 1)
            current.pop()
    explore(1)
    return result

print(combinations(4, 2))   # [[1, 2], [1, 3], [1, 4], [2, 3], [2, 4], [3, 4]]

```python
def generate_parentheses(n):
    result = []
    def explore(s, opened, closed):
        if len(s) == 2 * n:
            result.append(s)
            return
        if opened < n:
            explore(s + "(", opened + 1, closed)
        if closed < opened:
            explore(s + ")", opened, closed + 1)
    explore("", 0, 0)
    return result

print(generate_parentheses(3))   # ['((()))', '(()())', '(())()', '()(())', '()()()']
```

```python
def partition_palindromes(s):
    result, current = [], []
    def explore(start):
        if start == len(s):
            result.append(current[:])
            return
        for end in range(start + 1, len(s) + 1):
            piece = s[start:end]
            if piece == piece[::-1]:
                current.append(piece)
                explore(end)
                current.pop()
    explore(0)
    return result

print(partition_palindromes("aab"))   # [['a', 'a', 'b'], ['aa', 'b']]
```

Five queens have 10 solutions, as in the table above.

## Recap

- **Backtracking** builds an answer one choice at a time: **choose, explore, un-choose**.
- Save a **copy** of the current path when a solution is complete, and always undo the choice afterwards.
- **Pruning** abandons a branch as soon as a constraint is broken (sorted breaks, attacked squares, closing more than opened). It turns impossible searches into practical ones.
- Classic problems: subsets, permutations, combination sum, N-Queens, sudoku, word search.
- Sort and skip equal siblings to avoid duplicate answers. When sub-situations repeat, switch to dynamic programming.
