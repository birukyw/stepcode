# 1D Dynamic Programming: Memoization vs. Tabulation

Backtracking tries every path. Greedy bets on one. **Dynamic programming** (DP) does something smarter: it notices that the same small question gets asked again and again, **answers each one once**, and remembers the answer. It looks like magic the first time, because an exponential search collapses into a loop of a few lines. This lesson shows the two ways to write it, **memoization** (top-down) and **tabulation** (bottom-up), on problems whose state is a single number.

## The pain: repeated work

The Fibonacci numbers: each is the sum of the previous two. The direct recursion is beautiful and terrible:

```python
calls = 0

def fib(n):
    global calls
    calls += 1
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(25))
print(calls)
```

```text
75025
242785
```

Computing `fib(25)` made about 250,000 calls, and `fib(50)` would take hours. The reason is that `fib(10)` gets recomputed over and over inside `fib(25)`. The call tree is exponential, but there are only **26** different questions (`fib(0)` to `fib(25)`).

## Memoization: remember answers

Add a dictionary. Before computing, check whether you already did:

```python
calls = 0
memo = {}

def fib(n):
    global calls
    calls += 1
    if n < 2:
        return n
    if n in memo:
        return memo[n]
    memo[n] = fib(n - 1) + fib(n - 2)
    return memo[n]

print(fib(25))
print(calls)
print(fib(90))
```

```text
75025
49
2880067194370816120
```

Now each value is computed once: **O(n)** instead of exponential, and `fib(90)` is instant. Python can do the bookkeeping for you:

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)

print(fib(80))
print(fib.cache_info().misses)
```

```text
23416728348467685
81
```

`@lru_cache` (or `@cache`) wraps a pure function with a memo table. It only works when the function's result depends **only on its arguments**, and the arguments are hashable.

## Tabulation: fill a table bottom-up

Memoization recurses from the big question down. **Tabulation** goes the other way: fill a table from the smallest cases upward, so each entry only uses entries already computed. No recursion, no recursion limit:

```python
def fib_table(n):
    if n < 2:
        return n
    dp = [0] * (n + 1)
    dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]

print(fib_table(10))
print(len(str(fib_table(5000))))
```

```text
55
1045
```

And since each entry only needs the last two, you can drop the table and keep two variables: **O(1) memory**.

```python
def fib_fast(n):
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a

print(fib_fast(10), fib_fast(100))
```

```text
55 354224848179261915075
```

## A recipe for any DP problem

1. **Define the state.** What does `dp[i]` *mean*, in one sentence?
2. **Write the transition.** How does `dp[i]` follow from smaller states?
3. **Set the base cases.**
4. **Pick the order** (tabulation) or add the cache (memoization).
5. **Name the answer:** which entry holds it?

Let us use it on real problems.

## Climbing stairs

You can climb 1 or 2 steps at a time. How many ways to reach step `n`?

- State: `ways[i]` = number of ways to reach step `i`.
- Transition: you arrive from step `i - 1` (one step) or `i - 2` (two steps): `ways[i] = ways[i-1] + ways[i-2]`.
- Base: `ways[0] = 1`, `ways[1] = 1`.

```python
def climb(n):
    ways = [1, 1] + [0] * (n - 1)
    for i in range(2, n + 1):
        ways[i] = ways[i - 1] + ways[i - 2]
    return ways[n]

print([climb(n) for n in range(1, 9)])
print(climb(45))
```

```text
[1, 2, 3, 5, 8, 13, 21, 34]
1836311903
```

It is Fibonacci in disguise. That happens a lot: different stories, same recurrence.

## House robber: choose or skip

Houses in a row hold money. You cannot rob two neighbours. Maximize the loot.

- State: `best[i]` = the most you can steal from the first `i` houses.
- Transition: skip house `i` (`best[i-1]`) or rob it (`best[i-2] + nums[i-1]`): take the larger.

```python
def rob(nums):
    prev, curr = 0, 0              # best up to two houses ago, best up to the last house
    for money in nums:
        prev, curr = curr, max(curr, prev + money)
    return curr

print(rob([1, 2, 3, 1]))
print(rob([2, 7, 9, 3, 1]))
print(rob([]))
```

```text
4
12
0
```

Choose-or-skip is the shape of a huge family of problems. A greedy rule ("take the biggest") fails here: `[2, 7, 9, 3, 1]` has 9 in the middle but the best total, 12, takes 2, 9 and 1.

## Coin change: when greedy lost

Fewest coins to make an amount, with arbitrary coin values (the case where greedy failed).

- State: `best[a]` = fewest coins to make amount `a`.
- Transition: try the last coin used: `best[a] = 1 + min(best[a - c] for each coin c <= a)`.
- Base: `best[0] = 0`. Impossible amounts stay at infinity.

```python
def coin_change(coins, amount):
    INF = float("inf")
    best = [0] + [INF] * amount
    for a in range(1, amount + 1):
        for c in coins:
            if c <= a and best[a - c] + 1 < best[a]:
                best[a] = best[a - c] + 1
    return best[amount] if best[amount] != INF else -1

print(coin_change([4, 3, 1], 6))
print(coin_change([1, 2, 5], 11))
print(coin_change([2], 3))
print(coin_change([1, 5, 10, 25], 99))
```

```text
2
3
-1
9
```

The cost is **O(amount × number of coins)**, polynomial, where trying every combination would be exponential.

## Counting ways, not just the best

DP can **count** instead of optimize: add the possibilities instead of taking a min. How many ways to make `amount` from the coins, where order does not matter?

```python
def count_ways(coins, amount):
    ways = [1] + [0] * amount
    for c in coins:                      # coins in the OUTER loop: counts combinations, not orderings
        for a in range(c, amount + 1):
            ways[a] += ways[a - c]
    return ways[amount]

print(count_ways([1, 2, 5], 5))
print(count_ways([2], 3))
```

```text
4
0
```

Swapping the two loops would count **ordered** sequences instead (`1 + 2` and `2 + 1` as different). The loop order encodes the question.

## Longest increasing subsequence

The longest strictly increasing subsequence of a list (items need not be adjacent).

- State: `dp[i]` = length of the longest increasing subsequence **ending at** index `i`.
- Transition: `dp[i] = 1 + max(dp[j] for j < i if nums[j] < nums[i])`.

```python
def lis(nums):
    if not nums:
        return 0
    dp = [1] * len(nums)
    for i in range(len(nums)):
        for j in range(i):
            if nums[j] < nums[i]:
                dp[i] = max(dp[i], dp[j] + 1)
    return max(dp)

print(lis([10, 9, 2, 5, 3, 7, 101, 18]))
```

```text
4
```

This is O(n²). A cleverer version uses binary search (lesson 2.3.1) on a "tails" array to reach **O(n log n)**:

```python
from bisect import bisect_left

def lis_fast(nums):
    tails = []                           # tails[k] = smallest tail of an increasing run of length k + 1
    for x in nums:
        i = bisect_left(tails, x)
        if i == len(tails):
            tails.append(x)
        else:
            tails[i] = x
    return len(tails)

print(lis_fast([10, 9, 2, 5, 3, 7, 101, 18]), lis_fast(list(range(100000))))
```

```text
4 100000
```

## Maximum subarray: Kadane's algorithm

The contiguous stretch of a list with the largest sum. At each position, either extend the best run ending at the previous item or start fresh:

```python
def max_subarray(nums):
    best = current = nums[0]
    for x in nums[1:]:
        current = max(x, current + x)      # extend, or restart at x
        best = max(best, current)
    return best

print(max_subarray([-2, 1, -3, 4, -1, 2, 1, -5, 4]))
print(max_subarray([-3, -1, -2]))
```

```text
6
-1
```

State: `current` = best sum of a run **ending here**. One pass, O(1) memory.

## Memoization or tabulation?

| | Memoization (top-down) | Tabulation (bottom-up) |
|---|---|---|
| Style | recursion plus a cache | loops filling a table |
| Computes | only states actually needed | every state |
| Recursion limit | can hit it on deep states | never |
| Memory tricks | harder | easy to keep only the last few rows |

Start with whichever makes the recurrence clearest. Memoize first to get it right, tabulate if depth or speed becomes a problem.

## Is it a DP problem?

Look for: an **optimization or counting** question, **choices** at each step, and **overlapping subproblems** (the same sub-question appears more than once). If the brute-force recursion repeats work, memoize it.

## Common mistakes

- **No clear definition of `dp[i]`.** Write the one-sentence meaning first.
- **Wrong base cases,** especially for `0` and an empty input.
- **Mutable or unhashable arguments in `@lru_cache`.** Pass tuples, not lists.
- **Loop order mistakes** that count orderings instead of combinations.
- **Using DP when the state is too large.** The table size is the number of states, so make sure it fits.

```python
def tribonacci(n):
    a, b, c = 0, 1, 1
    for _ in range(n):
        a, b, c = b, c, a + b + c
    return a

print([tribonacci(n) for n in range(8)])   # [0, 1, 1, 2, 4, 7, 13, 24]
```

```python
def min_cost_climbing(cost):
    a, b = 0, 0
    for i in range(2, len(cost) + 1):
        a, b = b, min(b + cost[i - 1], a + cost[i - 2])
    return b

print(min_cost_climbing([10, 15, 20]), min_cost_climbing([1, 100, 1, 1, 1, 100, 1, 1, 100, 1]))   # 15 6
```

```python
def can_partition(nums):
    total = sum(nums)
    if total % 2:
        return False
    target = total // 2
    reachable = {0}
    for x in nums:
        reachable |= {r + x for r in reachable if r + x <= target}
    return target in reachable

print(can_partition([1, 5, 11, 5]), can_partition([1, 2, 3, 5]))   # True False
```

```python
def word_break(s, words):
    words = set(words)
    ok = [True] + [False] * len(s)
    for i in range(1, len(s) + 1):
        ok[i] = any(ok[j] and s[j:i] in words for j in range(i))
    return ok[len(s)]

print(word_break("leetcode", ["leet", "code"]), word_break("catsandog", ["cats", "dog", "sand", "and", "cat"]))   # True False
```

## Recap

- DP applies when a problem has **overlapping subproblems**: the same small question is asked repeatedly. Answer each once and store it.
- **Memoization** is recursion plus a cache (`functools.lru_cache`). **Tabulation** fills a table bottom-up and avoids recursion limits.
- The recipe: define the state in one sentence, write the transition, set base cases, choose the order, name the answer.
- Patterns: **choose or skip** (house robber), **try every last move** (coin change), **count instead of minimize** (add instead of min), and **best ending here** (LIS, Kadane).
- When each state only needs the last one or two, keep two variables instead of a table.
